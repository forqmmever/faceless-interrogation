# 第二十七轮：成装改名与互斥 + 一批删减 + 眼镜换血（2026-10-14）

## 用户口径（一次给了 7 件事）

> 「降级成普通下装，连衣裙那一栏改名为，成装并且装备时应和上装和下装互斥，眉钉去掉
> 洛丽塔短裙去掉 手套一栏去掉 单片金链眼睛和黑色墨镜去掉增加两副眼镜，
> 两副眼镜已经现在的圆框眼镜反差值设定均设定为3，头饰一栏去掉」

## 一、三件下装降级成普通下装

`bottom_cut` / `bottom_school_navy` / `bottom_slit` 去掉 `see: "cutout"` 旗 —— 收尾第二十五轮
那个待议项。旗子当年是拿**旧的高腰 `gstring`** 量的（18/22/30 px），换 `lacepanties` 后实测 0 px。
去掉后它们只是普通下装：穿在内裤外面、内裤不算数。
★ 还真的能开门的下装只剩三件：`bottom_mini`(cutout) / `bottom_pleat`(sheer) / `bottom_hotpants`(cutout)。

## 二、`dress` 改名「成装」+ 与上装/下装互斥（本轮结构上最重的一处）

```gdscript
const EXCLUSIVE_GROUPS := [
    [["dress"], ["top", "bottom"]],     # 左边一组 ↔ 右边一组，两两互斥
]
```

### ★★ 为什么是「二分互斥」而不是「组内只能有一个」

第一版把 `dress`/`top`/`bottom` 塞一个组做「只留一个」→ **开局原貌的上装与下装被一起归零**，
反差不再是 0、一键达标求解器整片挂掉。因为「上装+下装」本来就要一起穿。
三者里真正的互斥关系只有「成装 ↔ 上装/下装」这一对。语义上成装的上半截=上装、
下半截=下装，二者取其一才自洽。

### 互斥在四处落地

| 位置 | 行为 |
|---|---|
| `equip()` → `_apply_exclusive()` | 玩家穿成装 → 自动脱下上装/下装（后装备的赢）；穿空件 → 把之前顶掉的**原样还回去**（`_exclusive_stash`），否则脱掉成装后上下装一起空着、暴露凭空 +18 |
| `_equip_defaults()` → `_normalize_exclusive()` | 从现成装备表铺装备时按「左边优先」裁决 |
| `auto_complete_outfit()` → `_walk_options` 剪枝 | DP 不会算出「成装+长裤」（否则与 `_apply_exclusive` 的账对不上） |
| `_counts_with()` → `_covered_by_exclusive()` | **被顶掉的槽位整件不计入** —— 空件本身高数值（`top_none` 暴露 9 / `bottom_none` 差 8），穿成装时白吃下装的 9 点暴露显然不对 |

### ★ 原貌池里 `dress` 只留空件

`TRUE_POOL["dress"] = ["dress_none"]`。理由：原貌是「每槽位一件」的表，而互斥意味着
「成装」与「上装+下装」是两种互斥穿法 —— 若让实体成装入池，就得抽签后归一化，而落败方
压成空件反而白送数值、情报台还会同时报两条自相矛盾的目击。
→ **A 的原貌永远是「上衣+下装」，成装留给玩家主动穿**（那才是「单开一栏」的价值）。
句式跟着改：`CLUE_FRAME["dress"]` = `「他%s。」`，于是 `dress_none` 读作
「他从没见穿过裙子，一贯是上衣配长裤。」★ 记得同步 `story.json`（运行时优先读它）。

## 四、眼镜换血

删 `glasses_monocle`（单片金链眼镜）/ `glasses_shades`（黑色墨镜），从 AU `clothes/face/` 补：

| id | 名称 | 反差 | 需接受度 | 源图 |
|---|---|---|---|---|
| `glasses_round` | 圆框眼镜 | **3**（原 1） | 0 | `round`（金框） |
| `glasses_cateye` | 猫眼眼镜 | **3** | 3 | `cateye`（酒红框） |
| `glasses_square` | 方框眼镜 | **3** | 5 | `square`（深灰框） |

曝光都是 0，戴不戴不影响可解性。候选 `halfmoon`/`deepframe`/`lowframe`/`reading`/`punk` 也量过，
都是 512×256 AU 几何 + 纯灰度（彩度 0），可直接染色、不需 align/scale。
★ `square` 烘出来 27×17（比另两副高）—— 那是**镜腿绕到耳后**，按「落在身体/头发上的像素」核过
**悬空 0 px**，不是错位。

## 五、两处连带影响

### 1. 4 关反差曲线重标：62/72 → **50/52**

删掉一批高反差物件（眉钉 4 / 洛丽塔 5 / 单片金链 4 / 黑墨镜 6）+ 眼镜三副统一成 3
（原 1/4/6，最高那档没了）+ 手套栏下架 + 三件下装降级 → 120 种子 DP 实测最大反差掉到
**45~48 / 54~65 / 54~73 / 54~73**，第 3、4 关当场无解。
★ 第 3、4 关下限**都卡在 54** —— 那不是巧合，**54 就是第 4 关的暴露值上限**
（`10 + 接受度 22 × 2`）。想拉高只能恢复外袍/手套，或补「高反差低暴露」的新物件。

### 2. ★★ 强制装备的「死局槽位」

`hand_tattoo` 的 cover_tags 是 `glove`/`long_sleeve` —— **手套栏一下架，唯一能遮它的只剩
上衣槽那两件长袖**。于是「强制穿 `top_lace`/`top_crop`/`top_offshoulder` 这类短袖款」
= 手背刺青必露 + 上衣被锁死换不掉 → **本关无解**（实测 120 种子 × 4 关出现 6 例，全是这个原因）。

→ 解法不是删 `hand_tattoo`，而是给 `forced_pool` 加一条**算出来的**规则：
**某缺陷的全部可用遮挡物都集中在同一个槽位时，那个槽位不准被强制装备占用**
（`OutfitData.forced_locked_out_slots()`）。
★ 它是算出来的，将来恢复手套栏，top 自动重新变成可强制。
`neck_brand` 不会触发：它除了长袖上装，颈饰的 `neck_collar`/`neck_scarf` 也能遮，
集合是 {top, neckwear} 而非单元素。

## 六、踩到的坑

- **测试里那个「带强制装备的可解性」求解器从贪心改成 DP**（`auto_complete_outfit`）。
  贪心逐槽位试探，一旦某槽位被锁死就绕不回来 —— 实测「只锁 `panties`」的关贪心只到 47、
  同一局面 DP 是 54。贪心**低估上限**，会把能过的关判成无解。
  → TestRunner 的 `_build_viable` 也一样改了（原来是贪心，第 4 关卡在「伪装不成立」）。
  截图脚本的贪心则把成装整栏跳过（没有互斥剪枝，会凑出事后被拆的搭配）。
- **`static func` 每次返回新数组会拖垮热路径**：`_counts_with()` 的互斥闸每次都要问
  `exclusive_peers(slot)`，而它是 DP/贪心/界面刷新的必经之路 → 加缓存。
  另一个大头是 `_delta()` 的互斥分支第一版**无条件**整套重算，被「局部最优」检查
  调用上万次 → 改成「只有对面那组真的占着时才重算」。
  WardrobeTest 5m30s → **1m23s**（比改动前还快，因为剪枝减少了 DP 组合数）。
- **`var x := data.某个static函数()` 推断不出类型** → 报 `Cannot infer the type`。
  `data` 是无类型 Node，必须显式 `var x: Array = ...` / `var x: String = ...`。
- **`story.json` 优先于 GDScript 内置常量**：改了 `ScenarioData.CLUE_FRAME` 后忘了同步
  `story.json` 的 `clue_frame.dress`，运行时不生效。直接改 JSON 那一处（比重导出安全，
  不会丢手改）。
- **删文件靠 `prune_stale()`**：两包各清 16 个旧产物（贴图/图标/`.import`），
  之后两包图标数正好 **102**。新烘的 png 仍要跑 `godot --headless --path . --import`。
- **`_ProbeMaxContrast` 探针**：临时写了 `tests/_ProbeMaxContrast.gd/.tscn` 跑
  「120 种子 × 4 关用 DP 求最大反差」，拿到下限/上限来标定曲线，**用完即删**。

## 八、可选的后续（本轮没动，留给用户决定）

1. **成装偏弱**：`dress_sundress` 反差 3 / `dress_eveninggown` 4，而穿它会顶掉上装+下装
   （那两栏分别可贡献 7 + 7）。按现在的数值，成装永远是「省事但次优」的选择 ——
   玩家可能懒得用。要让它成为一个真选项，得把成装的 exposure/contrast 调高一些，
   但那会再次牵动 4 关的曲线。
2. **曲线的天花板是暴露值上限**：第 3、4 关的可达反差都卡在 `cap=54`。
   想整体抬回去，只有「恢复外袍/手套」或「补高反差低暴露的新物件」两条路。
3. `hand_tattoo` 现在只靠长袖上衣遮 —— 若觉得太紧，可以考虑给它加一条遮挡途径
   （例如让某件成装或配饰带 `long_sleeve` 标签）。
