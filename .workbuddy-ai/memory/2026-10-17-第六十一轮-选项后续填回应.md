# 第 61 轮 · 情景一：把 docx「选项后面那段」填进选项回应

日期：2026-10-17

## 用户口径

> 「刚才给的情景一的文档 没有把选项后面的内容没有填入 填入接在下一题题面前的回应」

上一轮把 docx 每个选项**后面那段结果说明**放进了题目的 `note`（编辑器不显示、运行时也不读），
所以从编辑器里看，选项的「接在下一题题面前的回应」是空的。本轮把它挪进
`options[].echo`。

## 语义调整（重要）

`echo` 现在的两种显示方式：

| `echo` | 下一题题面前显示 |
|---|---|
| 空 | **自动** `你：<选项文本>`（第五十七轮的行为） |
| 填了 | 那段**原样显示**，不再自动加「你：」 |

为什么：docx 里选项后面那段常常是**后果 / 旁白**（「空太郎：我从没听阳乃小姐说过…」），
不是玩家说的话。自动加「你：」会变成「你：空太郎：…」。

实现：

- `Interrogation.last_choice_is_custom`：选完之后记下这个选项是不是自带 `echo`。
- `_letterize()`：自带 → `o["echo_custom"] = true`；回落到选项文本 → `false`。
- `_load_question()`：`last_choice_is_custom` 为真时 `echo_head = echo + "\n"`，
  否则 `"你：" + echo + "\n"`。
- 默认路径（4 套出厂背景一条 `echo` 都没写）行为完全不变。

## 踩坑 / 注意

1. **`echo_custom` 是运行时补的，不写进数据**。数据里只认 `options[].echo`；
   `_letterize()` 根据「自带还是回落」补这个布尔值。别在编辑器/导出里写它。
2. **不能直接用 `echo != 选项文本` 判断自带**：作者完全可能把 echo 写成和选项文本一样。
   必须用「字段有没有填」的信息（`_label` 之前取到的原始 `echo`）。
3. **默认路径的「你：」不能丢**：四套出厂背景没有任何 echo，靠它显示上一题的回答。
   `TestRunner` 里有两条断言钉着（`你：<echo>` / 默认不是自带）。
4. **`note` 和 `echo` 不要混用**：`note` 不显示、只给人和搜索看；`echo` 是下一题前真正显示的文字。
5. 按此前要求，本轮**没有更新 `交接.md` 与 `CHANGELOG.md`**。
