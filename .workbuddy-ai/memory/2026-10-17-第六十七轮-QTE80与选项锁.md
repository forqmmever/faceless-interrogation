# 第 67 轮 · 表情 QTE：通过线 80% / 顶过才能答题 / 只认空格

日期：2026-10-17

## 用户口径

> 「表情控制 qte 改为条顶过 80%，同时只有 qte 通过或是条顶过 80 才能选择选项，只能用空格控制」

三件事：

1. 通过线 60% → **80%**。
2. QTE 期间**选项锁着**：条顶过 80%（或 QTE 结束）才能点选项。
3. QTE 只认**空格**：鼠标左键 / 回车 / 手柄都不再控制。

## 实现

| 位置 | 改动 |
|---|---|
| `Interrogation.gd` | `EXPR_QTE_PASS = 80.0`；新增 `QTE_ACTION = "qte_space"`（运行时 `InputMap` 只映射 Space）；`_process_expression_qte` 改读 `Input.is_action_pressed(QTE_ACTION)`，去掉鼠标左键 |
| 选项锁 | 新增 `_options_locked_by_qte`：`_begin_qte` 置 true + `_set_options_enabled(false)`；`_process_expression_qte` 顶到 80% 置 false + 解锁；`_finish_qte_for_question` / `_cancel_qte` 也解锁（失败 / 超时不能把玩家卡死）。`_select_option` 和 `_refresh_option_buttons` 都认这个标志 |
| 通过锁存 | 新增 `_qte_passed`：条一旦顶过 80% 就记为通过，之后松手回落也不改判（`_finish` 用 `_qte_passed or progress >= pass`） |
| 数值 / 文案 | `story.json` 的 `rules.expr_qte_pass` 60 → 80；`qte_prompt` 改成「按住 [空格] …… 把进度顶过 80% 才能答题」；玩法说明两条同步 |
| 编辑器 | 两处 QTE 下拉标签、玩法说明的「长按空格 / 左键顶过 60%」都改成「长按空格顶过 80%」 |

> 锁定时机：**QTE 面板弹出来之后**才锁；2.5 秒延迟期间仍可答题。
> 这样不会出现「面板还没出来、选项已经灰了」的迷惑状态，也避免答题被延迟卡住。
> 如果以后要连延迟期也锁，改 `_load_question` 末尾的 `_options_locked_by_qte = qte_needed` 即可
> （第 67 轮试过，测试里大量「载入即答」的用例会红，所以先只锁面板出现后的 4 秒）。
