## 二、编辑器合并的落点（`tools/story_editor.html`）

新增的是一组**声明式** section，不是把手机编辑器那套命令式渲染搬过来：

```
PHONE_PAGES   5 个文案页（shell / messages / memo / album / notes）
PHONE_SEGS    每页的字段表（k / label / hint / rows）
PH_EXPECT     每个字段「应该有几个占位符」
PH_MEANING    占位符对照表（memo.cast_body 的 11 个、notes 的三个）
SMS_GROUPS    三组短信（interrogator / companion / friends，field = bg 里的键名）
phoneSections(page) → [{kind:"object", host:()=>phoneSec(page), fields:[…]}]
smsSection(group, bg)  → [{kind:"objlist", arr:()=>bg[grp.field], fieldsFor:…}]
```

★ 关键：`renderSection` / `renderObjList` / `renderField` 本来就能吃 `host()` 和嵌套 `objlist`，
所以「手机那 8 个页面」几乎没有新渲染代码 —— 只是把 phone_editor 的字段定义改写成数据。
`renderField` 的 `t:"objlist"` 分支原来**不传 `blank`**，这轮补上了
（否则「新增一句对话」会是一个没有 `me` / `text` 的空对象）。

★ 视图：`{kind:"phone", page:…}` 与 `{kind:"sms", group:…, index:bg}`。
`navKey()` 必须把这两个也算进去，否则同一组的所有页面共用一个折叠状态。

## 三、`questions_source` 的判断式与分流点

```js
function bgQuestionsSource(b){ return (b && b.questions_source === "manual") ? "manual" : "auto"; }
```

**缺省 = auto**（不写这个键就是原来的行为）→ 出厂四套不用补字段。

manual 模式下**跳过**的校验（都在 `validateNow()` 的 bg 循环里，用 `if (!manual)` 包）：

- `(bg.cards||[]).some(c => c.owner === "A")` —— 「一张 A 卡都没有」
- 题目引用 `q.card` / `q.fact` 是否存在
- 同行者提问必须有「顶回去」的选项
- 挂 A 卡却没有「说漏嘴」/ 挂 B 卡却没有「照实答」
- 选项 `tone === "version"` 但整题没挂事实 / `value` 是否在事实版本表里
- 短信「与朋友」的 `level` 与 `facts` 顺序对齐、`reveals` 指向的事实与版本
- 「每个 fact 是否都有短信揭示」

★ 两处**必须跟着改**的口径，否则 manual 下会刷出一片假错误（各踩过一次）：

1. 短信 `level` 的上界：`facts.length` → manual 时改用「这一局几轮」
   （facts 可能是空的，用 0 当上界会把每条短信都判成越界）。
2. `reveals` 的整段校验：`if (gr.reveals && !manual)` ——
   不只是「对齐那条」要跳，`指向不存在的事实` 也要跳。

## 四、审问官短信的数据迁移

```json
"interrogator_sms": [
  {"id":"intr_<bg>_0","level":0,"contact":"<审讯官名>","avatar":"🕶","messages":[2 句]},
  {"id":"intr_<bg>_1","level":1,"contact":"<审讯官名>","avatar":"🕶","messages":[3 句]}
]
```

原来的 5 句按轮拆成 2 + 3。运行时删掉的东西：

| 删掉 | 在哪 |
|---|---|
| `GameData.interrogator_sms` | 变量 / reset / 每轮快照 / 回滚 / `RunSave` 存取 |
| `PhoneDesk.INTR_THREAD` | 特殊线程 id |
| `PhoneDesk._intr_thread_row()` | 红框那行 |
| `PhoneDesk._build_interrogator_thread()` | 平铺气泡 |
| `ScenarioData.interrogator_sms_at()` + `DEFAULT_PHONE["interrogator_sms"]` | 默认值 |
| `phone.messages.btn_open / interrogator_row / interrogator_tail` | 三条死文案 |

新增 `PhoneDesk._find_thread(id)` → `{t, group}`，`_open_thread` / `_build_thread_view` 共用；
「只有 friends 揭示口径」改成按 `group` 判断，不再用 `is_comp` 布尔。

## 五、测试脚本里的一个**真·既有 bug**（这次才暴露）

`tests/Screenshot.gd` 第 20 步（说漏嘴）只复位了 `_ended` / `_running` / QTE，
**没复位递话干扰**。而 `Interrogation._select_option()` 第一行是：

```gdscript
if _ended or interference_active:
    return
```

上一步（18b 组合干扰）的激活状态没收拾干净时，这一题会被**整题跳过** ——
怀疑度不涨、不出反馈、拍出来是一张「题目还在、什么都没发生」的空图。
证据：诊断打印 `opt0.tone=leak`，但答完 `怀疑度 60.0 / ended=false`。

★ 这个 flake 以前一直存在，只是帧时序刚好没撞上；本轮消息列表多了一行，
时序一变就露出来了。**判据不是「截图变了 = 回归」，而是先查这一屏的状态是否被钉死。**
