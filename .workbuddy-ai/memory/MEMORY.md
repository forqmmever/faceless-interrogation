## 一、工作流

### 一轮的收尾动作

1. `CHANGELOG.md` 追加一节 → **git 提交一次**，提交信息 = 那节第一行。「测试」那行**必须是真跑过的数字**；
   同轮第二块工作写「第 N 轮（续）」。
2. `README.md` 写「为什么这么改 / 机制 / 数值表 / 踩坑」；被作废的旧句**加 ★ 作废说明**。
3. `memory/` 写明细 —— 分文件，进版本库（`.workbuddy-ai/tmp/` **不进**）；`MEMORY.md` **控在 17KB 内**。

★ **memory 权威目录 = `D:\workbuddy\2026-10-11-09-19-59\.workbuddy-ai\memory\`（进版本库）**；
系统注入读的是 `C:\Users\...\WorkBuddy AI\2026-10-11-09-19-59\.workbuddy-ai\memory\MEMORY.md`
—— **改完必须同步这一份到 C:**（明细仍只在 D:）。C: 那份**超过约 17KB 会被截断**。

## 三、测试怎么写（细则见 `REFERENCE.md` 五章）

- ★★ **校验面板只放「问题」** —— 出厂数据必须 **0 错误 0 提醒**。**一片提醒先怀疑规则本身**。
- ★★ **跑完看三样**：`Failures: 0`、**有没有 `SCRIPT ERROR`**、**断言总数有没有莫名减少**
  —— 报错不会让测试失败，只会让那一行静默消失。取数组用 `_arr_of(d, key)`。
- **防「空转通过」**：循环一次都不进 = 什么都没测；`_check(..., true)` 也是空转
  （第 92 轮把删掉的断言改成 `true` 差点留下一条）。**加「样本里确实查到 N 条」的断言**。
- ★ **写断言的四个老坑**：① 只对部分对象生效的规则配**对照断言**；② 写完**故意改回错的**验证能抓到；
  ③「非空」看不见「少做一步」→ 判**数值范围**；④「单调」前**先写下取样点数值**。
  ★ 验「文本不重复」去掉「A. 」前缀再比（前缀把重名盖住，第 77 轮）。
- ★★ **别让断言依赖「上一个测试留下的局」**（随机种子 → 假失败）。★ 断言「涨 N 点」前先**钉死基数**。
- ★ **纯函数测不出「时间线上的 bug」** → 随轮次变的状态要**走完整流程的探针**。
- ★★ **背景不止一种形态时测试要自己挑**：`scene_*` 是 `manual`；依赖某类数据的**钉在 `_canonical_bg()`**。
- **用完清跨局状态**：`ProfileData.reset_all()` + 注入的 `_*_presets` 清回 `{}`。
- ★ **改全局数值 / 删文案键** → `tests/` 与 `editor_smoke.js` 里写死的计数会成片挂，改用常量或 `>=`。
- ★★ **删代码前 grep 它定义的局部变量**（第 83 轮带走 `knownTags` → 冒烟 `ReferenceError`）；
  删局部变量要搜**整个函数体**（续 2 漏了 `declared`，autoload 起不来）。

### ★★ 基线对照：HEAD 数据已经是脏的（第 88 轮起）

第 86 轮提交把用户工作区数据一起带进去了：`border_post` 停用、`bg_new_1` 空、两套 `scene_*` 全 `manual`。
后果：`TestRunner._canonical_bg()` **返回空** → **毫秒种子随机**挑背景 → 同代码两次失败数相差 ±2。
★ 先看「钉在…实际 scene_X」那行挑到了谁。★ 对照：`git worktree`（**先 `--import`**）跑基线，
**失败集 `grep FAIL | sort` + `diff` 比，比数数字可靠**。

### ★★ 截图「变了」怎么判（细则见 `REFERENCE.md`）

1. **先退回 HEAD 重拍**（三方对照）：`③新 vs ②HEAD = 0` 而 `①提交 vs ② ≠ 0` → 仓库那张是旧货。
2. **「时对时错」先查这一屏状态钉没钉死**，再查定时器（`set_process(false)` **停不住 `create_timer()`**）。
3. **判噪声**：同代码连跑两次 —— 若差异量级相当，就是抖动（相册 / shake / QTE 判负本就每次都变）。
4. ★ 报「真变」要给机制上的量 + 差异百分比 + bbox。工具 `tools/cmp_shots.py`。

### ★★ 截图脚本「前置不满足就跳过」= 静默留过期图（第 89 轮）

`else: _plog("!! 跳过")` 的分支，数据一变就整屏不拍，目录里留着旧轮次那张（**可能还带着已删功能**）。
日志里 `!! 跳过` 要当**失败**看；修法优先「给这张图找退路」（借一道普通题拍），不是删图。

④ 稳定随机用确定性哈希，不能用 `RandomNumberGenerator`。⑤ DP 去重的键用归一化字段。
