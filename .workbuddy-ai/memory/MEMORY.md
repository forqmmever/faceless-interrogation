# 项目长期笔记（千面人 · 伪装与高压审讯）

> 只放**可操作的规矩** —— 每条都要能回答「下次怎么做」。
> 诊断过程 / 改动清单 / 临时数据 → 同目录按轮次分文件（`YYYY-MM-DD-第N轮-xxx.md`）。

## 一、工作流

### 一轮的收尾动作

1. `CHANGELOG.md` 追加一节（**一句话级别**）→ **git 提交一次**，提交信息 = 那节的第一行。
   填「测试」那一行时，**必须是真的跑过的数字**。
2. `README.md` 写「为什么这么改 / 机制说明 / 数值表 / 踩坑」—— 主题级，按轮次章节组织。
3. `memory/` 写明细（诊断过程 / 具体改动 / 临时数据）—— 分文件，进版本库
   （`.workbuddy-ai/tmp/` **不进**）。

### 什么时候必须跑四套验证

```bash
godot --headless --path . res://tests/WardrobeTest.tscn   # 换装 + 数据层
godot --headless --path . res://tests/TestRunner.tscn     # 端到端（约 3~4 分钟）
node tools/editor_smoke.js                                 # 文本编辑器
node tools/phone_editor_smoke.js                           # 手机编辑器
godot --path . res://tests/Screenshot.tscn                 # 43 张截图 ★ 非 headless
```

★ **只在动了游戏代码 / 数据时跑**（`scripts/` `data/` `tests/` `tools/*_editor.html`）。
用户 2026-10-15 明确「没动代码不用跑四套验证」—— 纯文档 / 纯清点 / 纯加工具的轮次**跳过**。
判据：这一轮的改动会不会影响游戏运行时的行为或数据。

★ **后台跑长测试时，不要同时改它读得到的资源。**（第 49 轮踩过：E2E 那 3 分钟里
我为了验证断言把贴图临时换成单层，结果那一遍的结论作废、只能重跑。）

### 术语（用户 2026-10-15 定义，之后一律照此）

| 词 | 含义 |
|---|---|
| **一局** | 含一套背景 + 若干轮的那一整局（点开始游戏后的那一盘） |
| **一轮** | 一次换装 + 问答环节（代码里的 `level_index`） |

以前「关 / 轮」混用，**现在统一成「轮」**。用户说「每局游戏能设置不同 X」时，
意思是「挂在这套背景上的、这一局专用的 X」（一局的身份就是「抽到哪套背景」）。

★ 术语统一要**精确模式替换 + SKIP 词表**，不能全局替换 `关`：
改「本关→本轮 / 每关→每轮 / 第 N 关→第 N 轮 / 关卡→轮次」；
**不动**「关口 / 关隘 / 通关文书 / 进关 / 过关 / 关心 / 关键 / 相关 / 关闭」。
改完复查 diff（实测只有 `第四关 · 关隘地牢前厅` 因含地名被跳过，手工改了前半）。
★ 坑：脚本里别用 `line.split('#')[0]` 切注释 —— BBCode 的 `[color=#8a919c]` 会被当注释起点。

## 二、改数据的三条链路

### 改一句界面文案 → 同时找三处，漏一个就出问题

| 位置 | 为什么 |
|---|---|
| `ScenarioData.gd` 的 `DEFAULT_*` | json 缺失 / 解析失败时的兜底 |
| `data/story.json` | 游戏**实际读的**（它优先） |
| `tests/*.gd` 的**期望值** | 断言会挂（实测挂过 4 条） |

★ **改了占位符数量就等于改了接口** —— 文案里多一个 `%d`，所有调用点的参数表都要补
（否则运行时 `not all characters converted`）。顺着这条链找齐：

| 顺序 | 位置 |
|---|---|
| 1 | 用它的代码：`_tf("key", [参数...], "默认")` 的参数个数 |
| 2 | `ScenarioData.DEFAULT_*` |
| 3 | `data/story.json`（★ 它会盖掉默认值） |
| 4 | **「占位符数量守卫」断言**（WardrobeTest 一处、手机编辑器冒烟一处） |
| 5 | 编辑器的字段表（`PHONE_FIELDS` / `PH_EXPECT`） |

第 4 条那两处守卫是**用来防漏的** —— 第 43 轮它抓到了自己的更新，说明这件事本身很值。

### ★ story.json 两段是**整段替换**，另三段才是**逐键覆盖**

```gdscript
_item_desc  = idesc                                    # 整段替换！空字典会被忽略
_backgrounds = bg;  _traits = tr;  _clue_frame = ...   # 整段替换
_rules = _merge_flat(DEFAULT_RULES, ...)               # 逐键覆盖
_ui    = _merge_phone(DEFAULT_UI, ...)                 # 逐键覆盖
_phone = _merge_phone(DEFAULT_PHONE, ...)              # 逐键覆盖
```

**后果**：改 GDScript 里的 `DEFAULT_ITEM_DESC` / `DEFAULT_BACKGROUNDS` /
`DEFAULT_CLUE_FRAME` / `DEFAULT_CLUE_SOURCES` / `DEFAULT_PHOTO_NOTES`，
story.json 的旧值会把它**整段盖掉** —— 光改常量没用。

**同步办法（第 47 / 49 轮用过的「清空→重导→回填」）**：

1. 备份 story.json；把目标段置空（`{}` / `[]`）写回；
2. 跑 `DumpStory` → 拿到全部默认值（**顺序也对**）；
3. 用脚本对比备份：**备份独有的键**应该恰好等于「这一轮删掉的那些」。
   若差集符合预期 → 直接采用默认值；若有别的差异 → 把备份的值叠回去再跑一次 `DumpStory`；
4. 重建两个编辑器快照。

★ **`DumpStory` 不能无条件重跑**：`backgrounds[].questions[]` 里第 29 轮迁移出来的题目
**只存在于 story.json**，常量里没有备份，重跑一次就把题目全冲掉。
所以「顺便更新一下」是禁止的，要么用脚本精确改字段，要么走上面这套。

### ★ 派生数据不会自己跟上来

`OutfitData.gd` 是**唯一权威**，其余全是派生快照。改它的**槽位 / 标签 / 物品**时：

| 派生处 | 怎么跟 | 不跟的后果 |
|---|---|---|
| `data/doll_au.json` 的图层 `z` | **重烘** `python tools/dol_prepare.py` | 第 32 轮挪了丁字裤的槽位没重烘 → 预览里一直画在下装**下面**，谁也没发现 |
| `data/story.json` 的 `catalog` | 重导（见上） | catalog 越漂越远（第 28 轮标签、第 32 轮槽位都漂过） |
| `tools/story_editor.html` 的 `TRUE_POOL` | **手改** | 它在 JS 常量区、**不在内嵌快照标记之间**，`build_story_editor.py` 碰不到它 |

★ 改完权威表顺手问一句「**哪些地方抄了它**」。

### 加新物品的固定顺序

```
改代码 → 烘图 → godot --headless --path . --import → 导出 story.json
        → 重建快照 → 跑测试
```

| 漏了哪步 | 症状 | 修法 |
|---|---|---|
| 没 `--import` | WardrobeTest 报「每件物品都有卡片图标」挂 | 新烘的 png 必须进 `.godot/imported/` |
| 没重建快照 | `editor_smoke.js` 报 catalog 件数是旧值 | `build_story_editor.py` + `build_phone_editor.py` |

★ 删除物品靠烘焙脚本的 `prune_stale()` 自动清产物 —— 4 件物品 = 16 个文件
（贴图 + 图标 + 各自 `.import`）。

## 三、测试怎么写

### 断言要防「空转通过」

读一个已废弃的数据段时循环一次都不进，计数器全 0，断言全绿但什么都没测。
**加一条「样本里确实查到了 N 条」的断言防这个。**

### ★ 给「只对部分对象生效」的规则配**对照断言**

验「眼镜 / 发型 / 鞋子各自最多一次」时，同时断言「**主体（上衣）不受这条限制**」。
否则一个「**所有**槽位都最多一次」的写歪实现也能让测试通过。

同理（第 49 轮）：验「成装必须覆盖上下两截」时，配一条
「**对照：短款上衣确实短（露脐款底边 < 90）**」—— 「短」不是一刀切禁止的。

### ★ 写完断言要验证它真能抓到 bug（防「假护栏」）

标准动作：**把代码故意改回错的 → 确认断言挂 → 恢复 → 重跑**。
第 49 轮实测：把 `dress_nurse` 改回单层 → 输出
`没覆盖上下两截的成装: ["dress_nurse（y48-74，需 y72-104 以上）"]` + `[FAIL]` → 恢复。
**不做这一步就无法排除「新断言其实永远通过」。**

### ★「存在性 / 非空」类断言看不见「少做了一步」

第 49 轮的成装 bug（只烘了 `upper` 一层）活了 12 轮，580 条断言一条都没响 ——
因为旧断言查的是「文件存在」「图层有可见内容」，而少叠一层**两者都满足**。

**唯一能看出来的是几何形状**：像素实际延伸到哪儿。所以断言要判**数值范围**，
并且阈值用**实测**定的（当轮量出「上衣底边 76~112 / 下装 y83..124 /
修好后成装 106~188 / 错的 74~87」→ 取 104 把两类干净分开，空档 19px）。

### 写「单调 / 递增」类断言前，先把取样点的数值写下来

第 33 轮踩的：想验「暴露值越高 → 概率越大」，取了 `min+5 / 中点 / min+15` ——
第三个点（25）其实**比中点（35）还低**，于是 `0.10 < 0.50 < 0.30` 当场挂。
**名字叫 low/mid/high 不代表数值真的递增。**

### 约束的作用域是「整局」时，测试也要走完整流程

照片是「开局 3 张 + 每轮 +2 张」逐轮追加的 ——
「整局各自最多一次」这条**只跑开局那 3 张是验不出来的**，必须逐轮 `advance_level()` 跑完整局。

### 纯函数测试测不出「时间线上的 bug」

第 40 轮两个 bug 都不是单元测试发现的：

- **「假防御」**：`for s in group` 遍历的是**嵌套**数组，`str(s)` 得 `'["dress"]'`，
  `dict.get()` 永远查不到 → 整段是死代码，注释却写着「这是纯防御」。
- **「粘关」**：未配覆写的关沿用了上一关的原貌。★ 单元测试当时**是绿的** ——
  它只测 `_apply_preset()` 这个纯函数，没测 `start_new_run → advance_level → advance_level`。

**规矩**：涉及「状态随时间 / 关卡推进而变」的功能，除了纯函数测试，
**必须再写一个走完整流程的探针**（哪怕临时、用完就删）。
判据：**测试里如果没出现两次以上的状态推进，它就测不到时间线。**

★ **探针要跑真实链路** —— 第 44 轮直接调 `RunData.start_new_run()` 得到
`revealed_slots = 0`（看起来像「原貌不可见」），真相是那个字段由**情报台（UI 层）**写入。
验游戏行为要用 `load("res://scenes/Main.tscn").instantiate()` 起真实场景。

### 测试用完要清「跨局保留」的状态

`ProfileData.add_gain()`（接受度）跨局保留。用例里反复 `advance_level()` 会把它永久推高 →
后面「开局接受度 = START_ACCEPTANCE」当场挂。
**结尾必须显式还原**（`ProfileData.reset_all()` + 把注入的 `_*_presets` 清回 `{}`）。

### 判「两张图是不是同一张」要两个独立方法交叉验证

1. **文件 MD5** 一致 ⇒ 绝对是同一张图（最硬）
2. **`ImageChops.difference(a,b).getbbox()`** 返回 `None` ⇒ 逐像素一致

★ 别只看尺寸 / bbox —— 图包里大量「bbox 一样但内容不同」。
★ 反过来也是：**名字像不代表内容一样，名字不像也不代表内容不同**
（`chastitycage` 与 `chastitycagefetish` 两目录的 `full.png` 完全相同；
`props/npc/` 47 张拼起来是一个完整 NPC 立绘，不是道具）。

### 截图「变了」不一定是回归 —— 先过这三条判据（第 40 轮）

真凶是跑过 `--import` 后**导入缓存刷新**、字体图集烘焙变了，文字边缘抗锯齿随之略有差异。
**三条同时成立 = 抗锯齿差异，别当回归**：

1. 同一份代码**连跑三次完全一致**（渲染本身是确定性的）
2. 差异是**稀疏点状** —— 降采样成字符画看得出是文字边缘，不是整块 UI
3. 该镜头的 `_plog` 状态输出**逐字相同**

★ 二分排查时**先做「代码全还原」这一步**，一次性排除所有代码嫌疑，比逐个文件试快得多。

### 用字符画「看」图片差异

```python
d = ImageChops.difference(a, b).resize((96, 27), Image.BOX)
ramp = ' .:-=+*#%@'      # 每个像素映射成 ramp[min(9, v * 10 // 256)]
```

「整块 UI 不同」→ 大片 `#@`；「文字边缘」→ 稀疏的 `.::`。

## 四、架构约定

### ★ 只使用 AU 图包（第 37 轮起的硬约定）

不是「优先 AU」，而是 **DoL 那条链路已从代码里拆掉**：

- 唯一图包 = `au`：`dol_prepare.PACKS` 只有 `au`；`dol_map` 用 `AU_OVERRIDE`
  （不再有 `PACK_OVERRIDE` / `PACK_HAIR` / `hue_shift()`）；`DolDoll.gd` 只有 `PACK`/`ROOT`/`DATA_PATH`。
- **产物只有一份**：`assets/dol_au/` + `data/doll_au.json`。
  `assets/dol/` 与 `data/doll.json` 已删，**不要再写回代码或文档**。
- 取景框只有 AU 一套（**68×203**，画布 512×256，`crop = (62,0,130,203)` 纯平移无缩放）。
- 引用路径一律走 `DolDoll.root()` / `data_path()`，**不要写死 `assets/dol_au`**
  —— 写死会绕过「换图包」这层抽象，测试也变成假通过。

### ★ 成装（`dress` 槽）= 两层源图叠加

AU 把每件成装拆成**两个文件**，**只取一层就会只有上半身**（第 49 轮修的 bug）：

```python
"dress_nurse": [{"src": ("clothes", "upper", "pinknurse"), "tint": WHITE},
                {"src": ("clothes", "lower", "pinknurse"), "tint": WHITE}],
```

- 两层的 y 范围**精密衔接**（74→74 / 82→82 / 85→85 / 87→85），这是「一整套被拆开存」的铁证。
- 叠放顺序 `upper` 在前、`lower` 在后 → 后画的盖上 → 「裙子压住上衣下摆」。
- 例外：`dress_slip`（babydoll）AU 里没有 `lower/` 对应目录，单层就完整。
- **加新成装时第一件事**：查 `upper/<款>` 和 `lower/<款>` 是否都存在。

### 两条「槽位级名单」语义相反，别搞混（第 39 轮）

```gdscript
OutfitData.DISABLED_SLOTS   # 下架：玩家看不到
OutfitData.MANUAL_SLOTS     # 只能手动装备：看得到、点得到，但系统从不代劳
```

| 表 | 界面可见 | 能手动穿 | 原貌 | 情报 | 相册 | 强制池 | 一键达标 | 数值统计 |
|---|---|---|---|---|---|---|---|---|
| `DISABLED_SLOTS` | 否 | 否 | 不抽 | 不问 | 不拍 | 不进 | 不动 | 不算 |
| `MANUAL_SLOTS` | **是** | **是** | 不抽 | 不问 | 不拍 | 不进 | **不动** | **不算** |

配套三个函数**别混用**：

- `active_slots()` = `SLOT_ORDER - DISABLED_SLOTS` —— **界面口径**
- `auto_slots()` = `active_slots() - MANUAL_SLOTS` —— **自动流程 / 数值口径**
  （原貌 / 情报 / 相册 / 强制池 / 一键达标 / 一致数统计）
- `slot_enabled()` / `is_manual_slot()` —— 单项判断

★ 新加槽位先问：会出现在换装界面吗（→ `active_slots()`）？该被系统自动抽 / 算吗
（→ 不在 `MANUAL_SLOTS`）？
★ 一次不一致就直接出假数字：`peek_hint` 曾印出「13 / 14 处仍一致」。
**凡是「N / M」的显示，分子分母必须同一个集合。**

### 多件槽位：`equipped` 的值有两种形态

- `OutfitData.MULTI_SLOTS := {"tattoo": 2}` —— 只有纹身是多件槽位。
- `WardrobeModel.equipped`：**单件槽位 = `String`，多件槽位 = `Array`**。
- **一律走访问器** `ids_at` / `id_at` / `has_id` / `set_ids` / `solid_ids` / `_ids_of` ——
  别写 `str(equipped.get(slot,""))`（多件槽位上会得到 `["a","b"]` 字符串）。
- 多件槽位的「空件」必须标 `"bare": true`，否则 `_settle_multi()` 把它当真货占名额。
- 门控分级：`outer_slots_of_item(item)` **先看这一件自己的 `gate`**，没有才退回槽位级 `UNDER_GATE`。
- `_delta()` 的连带项只在**可见性真的翻转时**才重算 —— 无条件重算会把测试拖慢 3 倍。

### 运行时覆写：`static var` 是唯一解

要让「一份 JSON 在运行期改掉代码里的常量表」：

- `const` 改不了（编译期只读）；普通 `var` 又不行（`static func` 够不着实例成员）
  → **`static var` 是唯一解**，而且原有的 `OutfitData.ITEMS` 写法一行都不用改。
  ★ 连带的缓存（`_by_slot` / `_by_id` / `_stat_max`）**也要一起改 `static var`**。
- **必须「原地改容器」而不是「换新容器」** —— 全项目几十处**直接读** `X.ITEMS`，
  换表的话那些引用点还拿旧表。
- **autoload 顺序决定谁读得到谁**：`OutfitData` 在 `ScenarioData` 之前 ready，
  数据却在后者手里 → 覆写要由 `ScenarioData._load_story()` 读完文件后**反调** `OutfitData.apply_*()`。
  兜底函数里**绝不能**在「数据源还没就绪」时标记完成，否则空覆写会被当成最终结果、永远丢失。

★ 覆写类数据落盘：**只写「与内置值不同」的条目** —— 改回内置值就删掉那个字段。
好处：文件干净（默认 `{}`）、语义明确（**文件里有 = 改过**）、校验能直接报「这条多余」。

### 改「初始化顺序」前先 grep 谁依赖那个顺序

`start_new_run()` 里 `level_index` 原本在 `_roll_true_appearance()` **之后**才赋值。
第 40 轮让原貌依赖 `level_index` 后，这个顺序就成了 bug
（「从选关面板直接进第 N 关」会取到上一局残留的关卡号）。

### 稳定随机 vs 运行时随机

「同一道题要不要出 QTE」这类**必须用确定性哈希**（`hash("seed|轮号|题号|标签")`），
不能用 `RandomNumberGenerator` —— 同一道题会被**反复装载**（来回切题 / 重来本轮 / 测试），
每次现摇会变成「同一题一会儿出一会儿不出」。

### 结构约束优于概率约束

相册要求「上半身不能出现鞋子、下半身不能出现头发/眼镜」。做法不是「取完候选再筛一遍」，
而是**按组取候选**（上半身只从 `PHOTO_UPPER` 取）—— 越界在**结构上不可能发生**。
**能做成结构约束的，就别做成概率约束。**

## 五、图包知识

### AU `bodywriting` 的位置集合有两套

- **14 个图案**（flower / star / heart / paw print …）全套都有：
  `forehead` / `left·right-cheek` / `left·right-shoulder` / `left·right-thigh` /
  `breasts-0..6` / `pubic`。
- **`text/` 那 32 个短词**只有五个：`forehead` / `left·right-thigh` / `breasts` / `pubic`
  （`default` 例外，全套都有）。
- 两套**都没有 `neck`** → 「颈侧刺青」只能借左肩（第 26 轮起的已知取舍）。
- 两套**都没有「小腿」** → 而且小腿那段两条腿各只有 **8~11 px 宽**、鞋子从 y≈161 起盖住，
  **塞不下可辨认的图案**（第 47 轮的结论）。
- ★ **`paw print` 每个位置都是同一个 5×5 图案**（逐像素比对过）——
  所以「用哪个位置当 `src`」不影响结果，**只有 `align` 决定落点**。
- 源图尺寸差异极大：`paw print` 5×5、`flower` 10×10、`heart` 大腿档是 14×78 竖长条 ——
  挑图案**必须逐个量 bbox**，不能照抄别人的 `scale`。
- ★ 那些 png 都是 **512×256 整画布、左右两列各画一份** —— 探图脚本要自己过滤 `x<130`，
  否则会看到「一张图里好几个词」的假象。

### 纹身 `align` 的反算公式

```
实际落点 = 1.5 × align − (43, 15)      # 即 align = (视口中心 + (43, 15)) / 1.5
```

（`transform()` 里 `tx = (align.x − 58)×1.5 + 106`，取景框裁掉 62 →
视口 = 源图 − (62,0)，两式合并即得。）
★ bodywriting 的 `scale` 要**除以 1.5** —— 它本来就是 AU 几何，再乘一遍 `align_scale` 会凭空放大 1.5 倍。

### 挑款式时「长度档 / 部位」要实测，不能按名字推

同一系列不同款的档位跨度**差几倍**：`pigtails` 的 `short`（109px 高）≈ `neat/short`（39px）的三倍；
`princess wave` **所有档都是 197px**（天生长发，换档只改浓密不改长度）。
**规矩**：选档前先量 `bbox`（尤其**最低点 y**），必要时逐行统计像素分布。
参照系：现有款最低点都在 84 以内、**小人鞋底 y=189**。

★ 目录的语义容易猜错：
- `clothes/lower/` 是**下装**（183 项，绝大多数是裤子裙子）—— 找腰带 / 配饰要按部位去
  `hands/` `legs/` `neck/` 里翻。
- `clothes/legs/` 里既有袜子（归 `stockings` 槽）又有腿环。
- **AU 没有 `accessory` 目录**，「配饰」是从各部位凑出来的。

## 六、杂项踩坑

### GDScript

- **不支持单行 `if … else` 语句** —— `if x == null: a else: b` 直接 Parse Error。
  只支持 `x if cond else y` 这种**表达式**；语句必须拆成多行。
- **`arr or []` 非法** —— `or` 只吃 bool（表现为「打印到一半进程就没了」）。
- **没有 `repr()`** —— 那是 Python 的。
- **删跨行的 `print` 要连后半截一起删**，只匹配第一行会留下孤行 → Parse Error 且行号指偏。
- **只读常量数组要整体 duplicate** —— 光 duplicate 元素不够，`_backgrounds[i] = bg` 照样报
  `Invalid assignment on read-only value`。
- **`sort_custom` 是「不稳定排序」** —— 需要「相同键保持原顺序」时必须**带上原下标当第二键**，
  否则同一批数据每次跑都可能换位置（偶发、极难查）。

### 脚本与工具

- **带反斜杠的 Python 脚本一律写成文件再跑，别用 heredoc** ——
  Bash heredoc 会把 `\\` 吞成 `\`（正则 `[^"\\]` 被改成 `[^"\]` → `unterminated character set`）。
  「看起来能用」的那些其实也在被吞，只是刚好没炸。
- **两个 Python 环境**：烘焙用 `Python39`（PIL 10.1.0），
  量图 / 探针用 `.workbuddy-ai/binaries/python/envs/default`（PIL 12.3.0）。两个都能跑，别搞混。
- ★ **Windows 版 Python 不认 Git Bash 的 `/tmp`** —— 会被解析成 `<当前盘>:\tmp`。
  传路径前先 `cygpath -w /tmp` 换成 Windows 路径（第 49 轮踩过）。
- **编辑大文件后要回读一眼** —— 出现过「替换时把换行一起吃掉、两行合成一行」
  （GDScript 会立刻 Parse Error，但 CSS/HTML 里的合并可能不报错）。
- **DP 去重的键要用「归一化后」字段**（`_defect_mask_of` / `outer_slots_of_item`），
  不能用 `tags` / `gate` 原文 —— 否则等价件互相判定为被支配、双双被删，整个槽位候选清空
  → 该组无解 →「一键达标」静默返回「什么都没改」。
  帕累托剪枝四项全同时**只能让一方赢**（按序号），绝不互删。
