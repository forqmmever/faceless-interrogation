# 第三十六轮：四件刻字纹身 + 纹身改成「多件槽位 + 露出门控」（2026-10-15）

用户口径三条：

> 「要 bitch free-use slave cum-rag」
> 「纹身与内衣内裤处理方法相同，不漏出来时，不计算暴露值反差度。」
> 「同时可装备的纹身上限设为 2 将纹身暴露度设置为 2」

两处歧义先用 AskUserQuestion 问过：

1. 「将纹身暴露度设置为 2」→ **每件纹身都 = 2**（不是总和 2）。
2. 四件刻字的位置 → **分散到四个位置**（左大腿 / 右大腿 / 胸口 / 下腹）。

## 一、四件刻字纹身

| id | 名称 | AU 源 | 原生 | 目标 s | `scale` 字段 | `align` |
|---|---|---|---|---|---|---|
| `tattoo_bitch` | 左大腿「bitch」 | `text/bitch/left-thigh` | 7×39 | 0.72 | 0.4800 | (61.67, 84.33) |
| `tattoo_freeuse` | 右大腿「free-use」 | `text/free-use/right-thigh` | 8×17 | 1.60 | 1.0667 | (52.00, 85.33) |
| `tattoo_slave` | 胸口「slave」 | `text/slave/breasts` | 19×5 | 1.40 | 0.9333 | (57.00, 53.67) |
| `tattoo_cumrag` | 下腹「cum-rag」 | `text/cum-rag/pubic` | 13×11 | 1.40 | 0.9333 | (57.00, 78.00) |

- ★★ **这一批和前面 14 个图案不是一个路子**：AU 的 `text/` 贴图是**按部位画好的整字**
  （不是可以随便缩放搬移的小图案）。所以位置直接沿用图包自己的落点 ——
  `align` 由**该部位字形 bbox 中心**反算，`s` 只在 0.72（bitch 太长，缩一点免得压到膝盖）
  到 1.6（free-use 太小）之间微调，不做大搬移。
- ★★ `text/<词>/<位置>.png` 每张都是 **512×256 整画布**，里面同时画着
  「左列全身像」与「右列复制品」**两份**。`clip_to_body()` 会把 x≥130 那一半清掉，
  所以 `getbbox()` 天然只取到左列那一份 —— 这个坑第二十六轮踩过，
  探图时如果不过滤 x<130，会看到「一张图里好几个词」的假象（我这轮先被它骗了一次）。
- ★ `text/` 只有 `forehead` / `left·right-thigh` / `breasts` / `pubic` 五个位置，
  四件各占一处刚好够用，不会互相压图。
- ★ `dol` 包里这四件同样只能借头部小件顶替（DoL 的 bodywriting 只有 2~5 像素）。

## 二、纹身改成「多件槽位」（上限 2）

- `OutfitData.MULTI_SLOTS := {"tattoo": 2}` + `max_equip(slot)` / `is_multi_slot(slot)`。
- ★★ **模型层的 `equipped` 从此有两种值形态**：单件槽位是 `String`，多件槽位是 `Array`。
  新增访问器 `ids_at` / `id_at` / `has_id` / `set_ids` / `solid_ids` / `_ids_of`，
  全部读写改走它们。**以前那种 `str(equipped.get(slot, ""))` 在多件槽位上会得到
  `["a", "b"]` 这种字符串** —— 这是本轮最容易埋雷的地方（全项目扫了 40 多处）。
- 交互（`WardrobeModel.toggle`，界面点卡片走它）：
  点没装备的 = 加一件；点已装备的 = 脱下来；满 2 件时再点 = **顶掉最早那件**；
  点「（无）」= 全部卸掉。单件槽位语义**没变**（点已装备的仍是空操作）。
- ★★ `tattoo_none` 补上了 `"bare": true`。它是这一槽位的空件（和 `top_none` /
  `dress_none` 同一个语义），但以前**没有**这个标记 —— 不补的话
  「（无）」会被 `_settle_multi` 当成一件真纹身，占掉一个名额（实测：
  装第 1 件后槽里变成 `["tattoo_none", "tattoo_bitch"]`）。
- 每件纹身 `exposure = 2`（原有 6 件从 0 / 1 全改成 2），穿满两件 = 4 点。
- `DolDoll.plan()` 也跟着支持 Array 值（一个槽位可以铺多层）。

## 三、纹身与内衣内裤走同一条「露出门控」

门控本身第二十二轮就有了（透明外衣 / 镂空开档 / 直接外穿三条路），本轮把它
**从「按槽位」扩到「按件」**：

- `OutfitData.outer_slots_of_item(item)`：先看这一件自己的 `gate`，
  没有才退回槽位级的 `UNDER_GATE`。`is_gated_item(item)` 配套。
- 内衣内裤继续走槽位表（`bra` → top/dress/robe，`panties` → bottom/dress）；
  纹身写在自己身上，因为**长在不同部位、能盖住它的衣服不一样**：

  | 部位 | `gate` |
  |---|---|
  | 左 / 右大腿、下腹 | `bottom` / `dress` |
  | 胸口 | `top` / `dress` |
  | 颈侧 | `top` / `dress` / `neckwear` |
  | 面颊 / 额头 | **不给**（没有衣服盖得住，恒计入） |

- `WardrobeModel._counts_with` 拆成 `_counts_with`（槽位级，任一件露着就算）+ 
  `_item_counts`（单件级）。`_sum_now` / `effective_stat` / `covered_defect_ids`
  全部改成**逐件**累加。
- ★ 连带项：`_delta()` 的 watch 列表以前是「`UNDER_GATE` 里开门人含这一槽位的那些」，
  现在改成扫 `OutfitData.gate_dependents(slot)`（**带静态缓存**，因为 `_delta` 是热路径）。
  并且只在**可见性真的翻转**时才重算那一槽位的贡献 —— 无条件重算会把整套测试拖慢好几倍。
- `_matches_true` 改成比 `Array`（`ids_at(slot) == _ids_of(true_appearance[slot])`）。
- 界面（`Wardrobe.gd`）：卡片 `is_equipped` 改成 `cur_ids.has(id)`；
  暴露值点阵**逐件**压暗（多件槽位里可能一件露着、一件被盖住）；
  悬停写清「外衣盖得严实 —— 这一件不计入暴露值」「最多同时装备 2 件（当前 N 件）」。
- 存档（`RunSave`）：`equipped` 的 `duplicate()` 改成 `duplicate(true)`（深拷贝，
  否则 Array 值是共享引用）；`Wardrobe.apply_outfit` 支持 Array 值。

## 四、一键达标（DP）怎么处理多件槽位

- ★★ **纹身故意不并进 `top / bra / dress / bottom / panties` 那一大块**。
  `dp_groups()` 只按 `UNDER_GATE` 连边，纹身不在表里 → 天然自成一个单元素组。
  理由：并进去光选项数就会从 **两万五** 涨到 **上百万**（19×5×3×18×5 × 46 种纹身组合），
  直接跑不动；而纹身**只影响暴露值、不影响反差值**（`CONTRAST_SLOTS` 只有 top / bottom），
  DP 的目标函数与它无关。
- `_multi_group_options(slot)` 枚举「0 ~ 上限件」的所有组合（含空组合），
  `_multi_option_of` 里暴露值按**保守口径**计入（当作露着）——
  真实判定只会更小，所以求出来的解在真实判定下一定不超上限。
- 回填（backtrack）改成 `_ids_of(pick[slot])` + `set_ids`，String / Array 都能落定。

## 六、踩坑

- ★★ **`tattoo_none` 没有 `bare: true`**：只有 `top_none` / `bottom_none` /
  `dress_none` / `robe_none` 四件标了 bare，纹身的空件从来没标。
  多件槽位的「剔空件 / 退回空件」全靠这个标记，所以一装就出 bug
  （实测「装第 1 件后槽里是它」与「装（无）= 全部卸掉」两条断言挂掉）。
- ★★ **探 AU `text` 贴图时被「一张图好几个词」骗了一次**：那些 png 是 512×256 整画布，
  左右两列各画一份，不过滤 x<130 就会以为一个文件里塞了四个词。
  `clip_to_body()` 早就处理了这件事，但**探图脚本得自己过滤**。
- ★ 性能：`_delta()` 的连带项从「比布尔」改成「无条件重算 `_slot_contrib`」之后，
  WardrobeTest 从约 1.5 分钟涨到 4 分钟以上。改回「只在可见性翻转时才重算」。
  另外 `_delta` 的 watch 列表从 1 个槽位涨到 3 个（纹身也挂在 top / bottom 上），
  本身就会变慢一点。
- ★ 用 `AskUserQuestion` 把「每件都 = 2 还是总和 = 2」「四件放哪」先问清楚，
  省掉了后面返工 —— 这两条口径直接决定数值表怎么填。
