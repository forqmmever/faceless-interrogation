# 第 86 轮：选关按钮只写轮次名 · 一局通关后按钮回主界面

用户口径（一次两条）：

1. 「修复选关界面在正常关卡名后多出现了一个不起眼的路人 有点来头的商贩」
2. 「一局通关后点击按钮返回主界面」

## 一、多出来的那半句是怎么来的

面板按钮原来这样拼（`Main._rebuild_level_rows()`）：

```gdscript
btn.text = lv_name if prof == "" else "%s   ·   %s" % [lv_name, prof]
```

`prof` 来自 `_levels_for_panel(bg_id)`，而它自己又是三段回落：

```
全局 levels[i].derived_profile  →  背景自己的 levels[i].derived_profile  →  OutfitData.DEFAULT_LEVELS[0]
```

- 全局 `levels[]`（`data/story.json` 第 154 行那段）写着
  「第一轮 / 一个不起眼的路人」「第二轮 / 有点来头的商贩」—— 这是**出厂兜底**。
- 用户那套背景（`scene_1`）的 `levels[]` 只写了 `name` 与 `intro`，**没写 `derived_profile`**。
- 所以拼上去的必然是全局那句；玩家在编辑器里无论怎么改轮次名都去不掉，
  因为**选关面板这一行没有对应的编辑入口**。

这正是项目里那条判据的另一面：**没有编辑入口、却会被显示出来的数据 = 脏数据**。

## 二、改法

- `_levels_for_panel()` 现在返回 `Array[String]`（纯轮次名），去掉 `prof` 那一整段叠算。
- `_rebuild_level_rows()` 直接 `btn.text = str(lvs[li])`。
- `derived_profile` **没删**：它是玩法内的东西（`RunData.levels()` / `WardrobeModel.derived_profile()`
  照旧会叠全局表）。删掉的只是「选关面板上那半句」。

> 为什么不改成「只在自己写了时才显示」：那样三套背景会长得不一样
> （有的 `第一轮 · 外栅栏哨位 · 一个赶路的行商`，有的只有 `第一轮`），
> 面板要回答的是「挑哪一轮」，不是「这一轮你装成什么」。

## 三、通关按钮回主界面

| | 改前 | 改后 |
|---|---|---|
| `_pending_action` | `new_run` | `home` |
| 文案 | 再来一局（同一套背景 · 新原貌） ↺ | 返回主界面  ➔ |
| 按下 | `_start_new_run(-1, 0, _pending_bg_id)` | `_show_title()` |

改动点：

- `Main._on_interrogation_finished()`：末轮分支 `_pending_action = "home"`。
- `Main._on_overlay_pressed()`：加 `elif _pending_action == "home": _pending_action = ""; _show_title()`。
  `"new_run"` 的 `else` 分支**保留**（测试 / 截图脚本显式设值验证「沿用同一套背景」）。
- 文案三处：`data/story.json` 两套背景的 `endings.overlay_win_btn`、`ScenarioData.DEFAULT_ENDINGS`。
- `tests/Screenshot.gd`：第 25 屏原本靠「按通关按钮开新局」，改成显式 `_start_new_run(SHOT_SEED)`。

★ 通关结算（`note_run_finished` / `RunSave.clear()`）仍在**弹窗前**，
所以回标题后「继续游戏」自动变灰 —— 这条有断言守着。
