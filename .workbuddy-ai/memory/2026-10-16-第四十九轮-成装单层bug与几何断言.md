## 二、★ 核心 bug：AU 把每件成装拆成两个文件

### 现象

换装界面里「粉色护士服」「短款和服」只显示上半截。短款和服尤其离谱 ——
实测烘后只有 **y69-84（16 px 高）**，差不多只剩一条腰带。

### 根因

AU 图包里，一件成装**不是一个 PNG**：

```
clothes/upper/<款>/full.png      ← 上衣部分
clothes/lower/<款>/full.png      ← 裙子部分
```

第二十六轮做的 `dress_sundress` / `dress_eveninggown` 是**两层写法**，
**第三十七轮补的 8 件只写了一层**（只 `upper`）。

### 铁证：两层的 y 范围精密衔接

取景框 68×203、小人鞋底 y=189。源图（AU 画布 x62..130 那一列）实测：

| 款 | `upper` 到 y | `lower` 从 y | `lower` 到 y | 接缝 |
|---|---|---|---|---|
| `kimonomini` | 84 | 82 | 113 | 重叠 2 |
| `pinknurse` | 74 | **74** | 112 | **严丝合缝** |
| `cheongsamshort` | 87 | 85 | 122 | 重叠 2 |
| `leatherdress` | 85 | 82 | 106 | 重叠 3 |
| `swandress` | 81 | 82 | 113 | 相邻 1 |
| `transparentnurse` | 83 | 79 | 121 | 重叠 4 |
| `maid` | 127 | 81 | 178 | 重叠 46 |

74→74 / 82→82 / 85→85 / 87→85 —— 这种接缝只可能来自「一整套被拆开存」。

### 修法与验证

```python
# 修前
"dress_nurse": [{"src": ("clothes", "upper", "pinknurse"), "tint": WHITE}],
# 修后
"dress_nurse": [{"src": ("clothes", "upper", "pinknurse"), "tint": WHITE},
                {"src": ("clothes", "lower", "pinknurse"), "tint": WHITE}],
```

修后实测（视口坐标）：

| 成装 | 修复前 | 修复后 |

- ★ `dress_slip`（babydoll）**不改** —— AU 没有 `lower/babydoll`，它自身到 y=122 就完整。
- ★ 叠放顺序 `upper` 在前、`lower` 在后 —— 两层同属 dress 槽（z 96），

## 三、★ 真正的教训：为什么这个 bug 活了 12 轮

从**第三十七轮**活到**第四十九轮**，期间 580 条断言**一条都没响**。

具体原因 —— 旧断言查的是**存在性与非空性**：

| 旧断言 | 为什么抓不到 |
|---|---|
| `每件物品都有卡片图标` | 图标从贴图裁，有内容就能裁 → 通过 |
| `每件衣物的贴图都有可见内容（不是全透明占位图）` | 有内容 → 通过 |

**「少叠了一层」对「存在 / 非空」这两种检查完全隐形。**
唯一能看出来的是**几何形状** —— 像素实际延伸到哪儿。

### 补的两条断言

```gdscript
_check("成装覆盖上+下（顶边 ≤ 72 且底边 ≥ 104）", _dress_covers_both_halves())
_check("对照：短款上衣确实短（露脐款底边 < 90）", _crop_tops_are_short())
```

阈值是**实测**定的，不是拍的：

| 量的是什么 | 实测范围 |
|---|---|
| 上衣（27 件）底边 | 76 ~ 112（最长是长袖衬衫 112） |
| 下装典型区段 | y83 .. 124 |
| 成装（修好后）底边 | 106 ~ 188（最低是皮质紧身裙 106） |
| 成装（只叠 upper）底边 | 74 ~ 87 |

→ **104 这条线把两类干净分开**（87 与 106 之间空 19 px）。
顶边取 72（修好后 48~69，最高是和服领口 69，留 3 px 余量）。

### 两个实现要点

1. **`_used_rect_of()` 必须合并一件物品的全部图层**再取范围 ——
   成装是两层叠出来的，只看第一层会漏掉下半截（那正好就是 bug 本身）。
2. **对照断言不能省** —— 没有 `_crop_tops_are_short()`，
   一个「所有槽位都必须延伸到 y≥104」的写歪实现也能通过主断言，
   而那种实现在语义上是错的（上衣里本来就有露脐短款）。

### ★ 实测验证了新断言真的能抓（这一步不能省）

把 `dress_nurse` 临时改回单层 → 重烘 → 跑测试：

```
      没覆盖上下两截的成装: ["dress_nurse（y48-74，需 y72-104 以上）"]
  [FAIL] 成装覆盖上+下（顶边 ≤ 72 且底边 ≥ 104）
 Checks: 582   Failures: 1
```

然后 `cp` 回来 + 重烘 + 重跑（582 / 0）。
**不做这一步就无法排除「新断言其实永远通过」的可能。**

## 五、story.json 同步（沿用第四十七轮那套「清空→重导→回填」）

`item_desc` 是**整段替换**（`_item_desc = idesc`），不是 `_merge_flat`。流程：

1. 备份 `data/story.json`（**注意**：Python 是 Windows 版，`/tmp` 会被解析成
   `<当前盘>:\tmp`，必须用 `cygpath -w /tmp` 换成 Windows 路径传进去 ——
   这个坑踩过一次）；
2. 把 `item_desc` 置空 → 跑 `DumpStory` → 拿到全套默认值（顺序也对）；
3. 对比备份：**备份独有的键**应该只剩「这一轮删掉的那些」；

```
默认 51 条 / 备份 53 条 / catalog 168 件
备份独有: ['acc_legband_belted', 'acc_legband_leather']   ← 正好是要删的两条
默认新增: []
```

→ 差集正好等于删除清单，说明不需要回填，`story.json` 已是最新正确状态。

4. 重建两个编辑器快照（`build_story_editor.py` + `build_phone_editor.py`），
   并更新 `tools/editor_smoke.js` 里 `catalog 里有 N 件衣物` 的两处断言（172 → 168）。

## 七、可复用的东西

- **排查「贴图看起来不对」的第一步**：把目标贴图与**源图同位置**量出来对比。
  源图左边那一列（x<130）裁掉取景框 `(62, 0, 130, 203)` 就是视口坐标 ——
  **纯平移、无缩放**，所以两边数值可以直接对。
- **`measure_tattoo.py`**（第四十七轮建的）可以量任意贴图的落点比例，本轮没用到但它同源。
- **断言「防假护栏」的标准动作**：写完断言 → 故意把代码改回错的 → 确认断言挂 →
  恢复。这一轮做了，并因此在 E2E 上多跑了一遍。
