# 第 56 轮：「自行编辑」模式下用不到的字段全部收起

## 一、用户口径

原话：「在用户自己编辑的背景时，用不到的空全部删去，如审讯官的名字，身份档案卡，
选项中的『这句话算哪种』」。

我用 AskUserQuestion 追问了两轮，实际确认的范围：

- **审讯官的称呼（`interrogator`）不删** —— 用户明确回了一句「审讯官的名字不删」。
  理由：准备室顶栏、手机备忘录第二条、短信联系人的名字都还在读它，删了那几处是空的。
- 要收的：`interrogator_gender`（审讯官的性别）、`companion.gender`（同行人的性别）、
  `cover_role`（你伪装的身份）、`true_role`（你的真实身份）、`true_name`（A 的真身名字）。
- 两整节：**③ 身份档案卡**、**④ 事实与版本**。
- 题目里：**用作跨关复问**（`recall`，靠事实表的旧说法挑题）。
- 选项里：**这句话算哪一种**（`tone`）、**代表哪个说法**（`value`）。

留下的：审讯官的称呼、背景名、开场介绍、同行人的称呼、题目文本、
选项的「文本 / 怀疑值 / 触发结局 / 震屏力度」。

## 二、编辑器的做法

不是「删字段」，是**按模式过滤字段表**（数据一条不动，切回自动生成全回来）：

```js
const MANUAL_HIDDEN_META = ["interrogator_gender", "cover_role", "true_role", "true_name"];
const MANUAL_HIDDEN_COMPANION = ["gender"];
```

- `bgSections(bg)` 里 `const manual = bgQuestionsSource(bg) === "manual"`（第 1173 行附近），
  之后各处都能直接用。
- meta / companion 两个 `fields:[...]` 后面挂 `.filter(f => !manual || LIST.indexOf(f.k) < 0)`。
- 整节过滤：`return [...].filter(s => !manual || (s.key !== "cards" && s.key !== "facts"))`。
- `questionFields(manual)` / `optionFields(manual)` 改成**接收参数**，内部按需 `fields.push(...)`。
  ★ `optionFields` 原来是无参的，冒烟里 `P.optionFields()` 不带参 = 自动生成口径，别改坏。
- `optionTitle(o, i)`：自行编辑的选项没有 `tone`，标题不能再显示「选项 1 · ?」，
  改成「有 tone 才带 · tone」。

## 三、校验器跟着改（否则选完一片假红）

- 必填：`cover_role` / `true_role` / `true_name` 三条 `warn` 包进 `if (!manual)`。
- 性别：`interrogator_gender` 与 `companion.gender` 的取值检查包进 `if (!manual)`。
  ★ 顺手补了一条 `warn`：`interrogator` 为空要提醒（两模式都要 —— 三处在用它）。
- 选项：`tone` 合法性、`!text && tone !== "silence"` 两条包进 `if (!manual)`；
  自行编辑时改成「没文本 → `warn`（按钮会是空的）」。
- `suspicion` 非数字的报错文案两种模式分开（「用全局默认」/「用『照实答』的出厂值」）。
- 出厂数据仍是 **0 错误 0 提醒**（冒烟断言守着）。

## 四、运行时三处（这一轮最容易漏的地方）

### ① `_is_unified_question()` 的判据

```gdscript
# 旧：return (raw[0] as Dictionary).has("tone")
# 新：
return first.has("tone") or first.has("text")
```

只看 `tone` 的话，自行编辑的题（没有 tone）会被判成**旧格式的档案题**，
走 `_build_options()` 那条老路 → **完全不读你写的选项**，只摆固定四个。
旧格式（内置常量）的题根本没有 `options` 字段，所以放宽不会误伤。

### ② 「盲区题」判定要关掉

```gdscript
var is_blind := fid == "" and cid == "" and not is_companion \
	and not RunData.questions_are_manual()
```

盲区题的定义就是「既不挂事实也不挂档案卡」，而自行编辑的题**每一道**都不挂 ——
不关的话整局全变盲区题，判定偷偷换成「按他的脾性选对没选对」。

### ③ 未知 / 空 `tone` 分支的代价

原来 `_` 分支只把 `kind` 改成 `"ok"`，`delta` 仍是 `0.0` —— 等于「没写类型 = 不涨不跌」，
和编辑器上写的「留空 = 按照实答算（-6）」对不上。现在：

```gdscript
delta = float(d.get("suspicion", _rf("correct_delta", -6.0)))
if tone != "":
	push_warning("未知的 tone「%s」（题 %s）" % [tone, str(q.get("id", "?"))])
```

★ 出厂 224 个选项**全都有 tone**（脚本核过），所以这条改动对出厂数据零影响。

### 新增的两个门面

- `ScenarioData.questions_source_of(bg) -> String`（缺省 `"auto"`，不认识的值也退回 auto）
- `RunData.questions_are_manual() -> bool`

## 五、修了一条既有 flake

`_test_leak_and_fail_restart` 里写死：

```gdscript
_check("重来本轮 → 回到第 1 轮", RunData.level_number() == 1)
```

这个测试**不开局**，继承的是上一个测试（`_test_multi_level_flow`，用 `main._start_new_run()`
**不传种子** → 随机）留下的局。第 1 轮偶尔抽不到 A 类档案题，测试就会先
`_goto_level_with_card_owner("A")` 跳到后面某一轮，于是「回到第 1 轮」自然不成立。

本轮实测：**第一次跑挂、第二次同样的代码全绿**。加了诊断打印才看清：

```
[诊断] 进来时 level_index=0 / 题数=6 / a_idx=4 / questions_source=<无>
```

改法：`var lvl_before := RunData.level_number()`，判据改成
`RunData.level_number() == lvl_before`（契约本来就是「回到**本轮**开始」；
「从第 2 轮重来仍停在第 2 轮」由 `_test_retry_level_semantics` 钉着）。

## 六、新增的测试 `_test_manual_question_options`（16 条）

覆盖：
- 纯函数：缺省 auto / `"manual"` 认 / 不认识的值退回 auto / 出厂四套都是 auto。
- 没有 tone 的题仍走统一格式（`_is_unified_question`）。
- 自动生成下「不挂卡不挂事实」= 盲区题；切 manual 后不是盲区题。
- 四个选项都读出来、文本原样、显式 suspicion 生效、空 suspicion 取 `correct_delta`、
  kind = ok、选项自己的 `ending` 仍生效。
- 删掉那个键就退回自动生成。

★ **开局用轻量版**：一开始抄了 `_run_a_clean_level()`（先过一轮再重开），实测这段要
**13.8 秒**（占整套 7.8%，排进前 8 名）。但这套断言全是纯函数，只要求「有一局在进行」，
换成 `_start_new_run(20261011)` + `_prepare_and_enter()`（和「盲区题」一样）就够了。

★ 换完之后断言总数 **875 → 874**：少的那条是 `_run_a_clean_level()` 里
`_pass_current_level()` 顺带跑的「第 1 轮判定为通过」，不是覆盖损失
（同一条断言全文件还有 9 处）。**断言数变化一定要能说清是哪一条**。

## 六点五、顺手修了「怀疑值」栏一个既有坑

`suspicion` 那一栏原来没标 `blankDelete` —— 数字框的空值会走 `num("", 0)`，
**清空 = 写回 0**。于是 hint 上写的「留空 = 用全局默认 / 按照实答算（-6）」在界面上根本做不到：
用户看到框里是 0，一改就成了「0 怀疑值」，两种模式都踩这个坑。

改法：`{k:"suspicion", ..., blankDelete:true, placeholder:...}` —— 清空 = 删掉这个键，
空着时灰字写清默认怎么算。冒烟加两条断言（`blankDelete === true` + 有 placeholder）。

★ 同类字段要分清三种语义：`blankDelete`（没有这个键才算没写，0 是有效值）、
`blankZero`（0 就是没写）、默认（空 → 0）。别混。
