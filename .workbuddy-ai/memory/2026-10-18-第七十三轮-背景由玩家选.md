# 第七十三轮：背景由玩家选，删掉「随机」

日期：2026-10-18

## 一、用户口径

> 「游戏开始界面玩家可以自行选择游玩哪个背景，现在却只能用随机，修复这个问题然后删掉随机的选项」

## 二、查到的真相（机制本身是通的，坏的是「默认值」和「用完就丢」）

先说结论：**选背景这条链路一直是好的**（`_on_bg_choice` → `_pending_bg_id` →
`_on_level_selected(li)` → `_start_new_run(-1, li, bg_id)` → `RunData.start_new_run`）。
用探针 `pressed.emit()` 走真实按钮路径验过：点「边境哨卡」→ pending 记下 →
点第 1 轮 → `RunData.background_id == border_post`。

玩家觉得「只能用随机」，是两件事叠出来的：

1. **默认就选中「随机」**（`_pending_bg_id = ""`，第一颗按钮的 id 就是空串）——
   不点背景的人，永远抽；
2. **「再来一局」把选择丢了**：整局通关后 `_on_overlay_pressed()` 的 else 分支是
   `_start_new_run()`（**不传 bg**）→ 每打完一局换一套。玩家挑的背景只用一次，
   按钮上还写着「再来一局（新背景 · 新原貌）」。

★ 教训：**「能点」不等于「玩家会用到」** —— 默认值把功能吃掉了，
光看代码会以为功能是好的。查「只能 X」这类反馈，先看默认值和「之后还会不会沿用」。

## 三、改动

| 位置 | 改动 |
|---|---|
| `Main._build_level_select()` | 删掉「随机」那颗；`bg_choices` 只由 `enabled_backgrounds()` 生成；**默认选中**「`_pending_bg_id` 还在列表里就用它，否则第一套」 |
| `Main._start_new_run()` | 开局后 `_pending_bg_id = RunData.background_id` —— 面板下次打开默认选它 |
| `Main._continue_run()` | 同上（续玩也算「这一局用的那套」） |
| `Main._on_overlay_pressed()` | 「再来一局」→ `_start_new_run(-1, 0, _pending_bg_id)`（沿用同一套背景） |
| `ScenarioData.DEFAULT_UI["title"]` | 删 `select_bg_random`；`select_bg_title` 改成「本局背景（点一套选中）」 |
| `ScenarioData.DEFAULT_ENDINGS` | `overlay_win_btn`：「再来一局（新背景 · 新原貌）」→「再来一局（同一套背景 · 新原貌）」 |
| `data/story.json` | 同三处（`ui.title` 两条 + 4 套背景的 `endings.overlay_win_btn`） |
| `tools/story_editor.html` | 重建内嵌快照（`select_bg_random` 跟着没了） |
| `tools/editor_smoke.js` | `uiLeafCount` 87 → **86**（文案页覆盖仍是 85 —— 这两条文案本来就没进字段表） |
| `tests/Screenshot.gd` | 0a 的 `_plog` 改口（不再说「默认随机」） |

★ **`RunData.start_new_run(..., bg_id == "")` 仍然 = 随机**，没动 ——
测试与截图脚本大量直接调 `_start_new_run(seed)`，它们靠随机覆盖四套背景。
删掉的只是**玩家侧的入口**。这条写进 README 了，免得以后有人「顺手」把回落也删掉。

2. **一颗「随机」都没有**（遍历，每颗 id 非空）

## 五、截图：两张真变，四张是噪声（而且发现一张「提交版本身就是旧的」）

重拍 43 张后 6 张有差异：`00a` / `24` / `25` / `06` / `07` / `18b`。
判断办法（这次多了一步，很有用）：

1. **同代码连拍两次** → 只有 `06` / `07` 变（相册 SubViewport，已知噪声）；
2. 把改动 `git stash` 掉，**用 HEAD 代码再拍一遍**，逐张和「新代码」比：

| 图 | 新代码 vs HEAD 代码 | 结论 |
|---|---|---|
| `00a_level_select` | 0.76%（差异框正好落在背景按钮那一行） | **真变**（「随机」没了） |
| `24_run_cleared` | 0.23%（差异框正好落在按钮文字上） | **真变**（「同一套背景 · 新原貌」） |
| `25_run_failed` | 0.00% | 噪声，还原 |
| `18b_combo_interference` | 0.00% | 噪声，还原 |
| `06` / `07` | 1.27% / 0.42% | 相册噪声，还原 |

★ **额外收获**：`18b` 的**提交版和 HEAD 代码重拍的版本差 1.53%**（题目从档案题变成同行者题）——
说明**仓库里那张 18b 早就是过期的**，跟本轮改动无关。
判据：`新代码 vs HEAD代码 = 0.00%` 但 `HEAD提交 vs HEAD重拍 ≠ 0` → 那张图是旧货。
**所以「截图变了」先别认领，先跑这一对照**：三方（提交版 / HEAD 重拍 / 新代码重拍）一比，
是谁的锅一目了然。

## 六、踩坑

1. **headless 下验不了「真实点击」**：`viewport.push_input` / `Input.parse_input_event`
   在 `--headless` 里 GUI 不处理，`gui_get_hovered_control()` 恒为 `null`。
   能验的是 **`button.pressed.emit()`**（等价于点中之后触发的那一下），验不了「点得中吗」。
   以后遇到「点不动」类反馈，别指望 headless 探针，直接看截图 / 真机。
2. **`_pending_bg_id` 的「还在不在列表里」要按列表判断，不能只判空** ——
   编辑器里把某套背景停用之后，这个值可能是个已经不存在的 id。
3. 面板默认值优先用「上一局那套」而不是「第一套」，否则玩家每开一局都要重新点一遍。
