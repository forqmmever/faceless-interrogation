## 一、画布语义（这轮彻底搞清楚了，推翻上一轮的判断）

上一轮记的是「512×256 = 4 帧 ×128×128，左份全身像 + 右份胸像，整块再复制」。
**这是错的**。叠上 128 网格看 `body/base-classic.png` 才看清：

```
x0..127    全身像列（人物站在 x85..125、y45..190，头 x90..122 / y14..47）
x128..255  胸像列（头 x165..230，**被 y=128 拦腰截断**）
x256..383  第 0 列的逐像素复制
x384..511  第 1 列的逐像素复制
```

→ 不是「帧」，是**按 128 px 一列排的 4 列**。

**分界线 = x130**（不是上一轮估的 134）。全量扫 `body/`+`clothes/`+`hair/` 三层，
统计每列不透明像素的「最远/最近」：

- 全身像列的内容最远到 **x129**（`hair/sides/all down/chest` 的 128:6 129:8）
- 胸像列的内容最近从 **x130** 起（`clothes/upper/blackleather` 的 130:3）

所以 `crop_clip` / `clip_view` 取 `(0,0,130,256)`。取景框 `(62,0,130,203) → 68×203`。

## 二、这轮改了什么

### `tools/dol_prepare.py`

1. **新增 `clip_to_body()`**，在 `layer_image()` 里**任何 bbox 计算之前**把图层裁到全身像列。
   ★ 关键：耳饰/穿环/刺青是「借头部小件 + 位置搬移」，`goldhairpin`/`hairclip` 在 AU 里
   同时画在全身像和胸像两张脸上，整图 bbox 横跨 x109..482（宽 373 px），
   中心落在两张像中间 → 整块被推到画布左边缘。裁掉胸像列后 bbox 才正确。
2. **`align_origin` 从 (104.5, 31.5) 改成 (106.0, 30.5)** —— 实测 `body/base-head`
   在全身像列里是 x90..122、y14..47，头心 (106, 30.5)；头宽 33 px vs DoL 22 px → scale 1.5。
3. **`resolve()` 大改**（挑贴图的顺序，挑到全透明的就跳过）：
   - 先滤掉 `-acc`/`_acc` 变体（那是附加装饰层）
   - `full.png` → `full*` → 带 `idle` 的 → 数字名 → 其余
   - **新增 `has_content()`**：图包里混着**全透明的占位 png**（AU 的 `winterjacket/3.png`），
     不筛掉会选中一张空图 → 那件衣服在预览里整个消失
4. `note_clip()` 简化（im 已经裁过了，不用再裁一遍）。

### `tools/dol_map.py`

- 新增 **`PACK_OVERRIDE`**：按图包覆盖 spec。只有 5 件需要 —— AU 的 `hairclip` 在全身像列里

## 四、踩过的坑（补充）

- **`/tmp` 与 Windows Python 不互通**：Git Bash 的 `/tmp` Windows 版 Python 读不到，
  临时脚本和中间产物一律放 `C:/Users/qiongmuming/AppData/Local/Temp/au_preview/`。
- **新烘出来的 png 必须跑一次 `--import`**：否则 Godot 的 `ResourceLoader.exists()` 返回 false，
  测试会报「图标缺失」而文件其实在磁盘上（只是没有 `.import`）。
- **`make_icon()` 早退的坑**：`acc.getbbox()` 为空时直接 return，但调用处已经写了
  `items[id]['icon'] = ...`，后面的「空件兜底」循环会跳过它 → 图标永远不生成。
  现在被 `_doll_layers_visible()` 这类测试盯住了。
