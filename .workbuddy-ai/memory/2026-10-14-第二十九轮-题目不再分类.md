# 第二十九轮：阶段二题目「不再分类」，改成可逐题编辑的清单（2026-10-14）

## 用户口径

> 「阶段二的问题我想不再给问题分类，直接让我编辑对问题进行编辑，如问题的 qte 出现时间，
> qte 类型，问答，选项，触发游戏结束，问题的个数，是否触发抖动，选择选项之后怀疑值的怎么加多少吗等，
> 但后续可能还会做自动生成整局游戏内容，怎么搞比较好」

三个决策（用户全选推荐方案）：
1. **`facts`（事实/版本表）保留为「可选骨架」** —— 题目可挂可不挂
2. **本轮只做 schema + 逐题编辑器**，生成器留接口、下轮做
3. 生成方式定为**程序骨架 + LLM 填词**

## 一、诊断：「分类」到底分在哪

| | 改造前 |
|---|---|
| 题目从哪来 | **不是清单**，是 `RunData.questions_for_level()` 里 42 行**编排代码**按固定位置拼的（第 3 道固定同行者、第 6 道固定盲区、第 7 道固定跨关复问） |
| 一题有哪些属性 | **四套互不相同的 JSON 结构**：`questions` / `facts` / `companion_questions` / `blind_questions` |
| QTE / 抖动 / 怀疑值 | 绝大多数写在**全局常量与代码里**（只有 `qte_plan` 能按题号覆盖，而它一直是空的） |

→ 「去分类」= 题目变数据 + 字段统一 + 每题自带全部属性。

## 二、统一 schema

`backgrounds[].questions[]`，每题一个对象：

`id` / `level`(0..N 或 -1=通用池) / `speaker`(interrogator|companion) / `text` / `setup` /
`card`(可选) / `fact`(可选) / `recall`(可选) / `plant` / `qte{kind,delay}` / `options[]`

选项：`text` / `tone` / `suspicion`(可空=继承全局) / `value`(仅 version) / `ending`(可选)

**七种 tone**：`correct` / `leak` / `version` / `bluff` / `evade` / `silence` / `made_up`

两条设计原则：
- **一切可缺省**（不写就继承全局）—— `suspicion` 留空 = 仍按「档案卡归属 + 审问官性情」老规则算，
  这样「换个人来问、代价完全不同」的机制原样保留
- **纯数据无耦合** —— 判对错只看选项的 `tone`，不看「题目属于哪一类」

## 三、出题规则（关键设计）

- `level == li` → 本关固定题，按**清单顺序**出
- `level == -1` → 通用池，用来补足到 `questions_per_level`（可每关覆盖）
- 标了 `recall: true` 的通用题 → 按本关抽到的「旧说法」挑对应的一道出来问
- **顺序 = 清单顺序**（想在题库页拖顺序改节奏，就必须让顺序成为数据）

出厂迁移结果（每套 24 道）：通用池 12（8 档案 + 4 复问）+ 每关 3（新说法/同行者/盲区）
→ 每关 3 固定 + 1 复问 + 4 档案 = 8 ✓

## 四、运行时改动（极小）

**判定逻辑一行没改** —— `_select_option` 及其下游原样不动。
新代码只把 `tone` 翻译成原来那套内部字段（`kind`/`owner`/`delta`/`value`/`blind`）。

改动点：
- `RunData.questions_for_level` 新格式优先（`questions_schema == faceless-questions-v1`），旧路径保留兜底
- `Interrogation._build_unified_options` 新增（原四分支保留给旧格式）
- `_q_text` / `_q_is_companion` 兼容新旧字段名（`text`/`q`、`speaker`/`kind`）
- `_apply_qte_plan`：**题目自带 `qte` 优先**于「按题号」的全局计划表
- `_record_answer`：备注只记档案题与盲区题（按挂了什么推）

## 五、编辑器：新增「🗣 题库」页

按背景切换，逐题展开编辑全部字段 + 选项列表（嵌套 objlist）。
`bgSections` 里的 ⑤⑥⑦ 三节合并成一条「已并入题库页」的提示。

## 六、校验器（编辑器与生成器共用）

查：id 唯一 / `level` 范围 / `tone` 合法 / 选项文本非空 / `version.value` 在事实表里 /
`card`·`fact` 引用存在 / **同行者必须有「顶回去」的选项** / **盲区题必须答得出来** / **每关题量够不够**。

★ **当场抓出迁移脚本的两个真 bug**：
1. 同行者提问里「不表态」选项 `value` 为空却标成 `version` → 它其实是 `evade`
   （标错会让它参与一致性检查、算出错误结论）
2. 某道盲区题的「硬答」本来就是空的（合法设计）→ 却被生成成空文本选项（盘问里会出现空按钮）

## 七、为自动生成留的三个接口

| 层 | 做什么 | 现状 |
|---|---|---|
| 骨架层 | `facts` 表 + 卡司 + 关卡表 —— 生成器在这张表上做文章，跨关一致性天然成立 | ✅ 已保留 |
| 生成层 | 程序模板产出结构 + LLM 填措辞 | 下轮 |
| 校验层 | schema 校验器共用 | ✅ 已做 |

## 八、坑

- **测试里到处是「第 N 题是什么」的硬编码**（`_load_question(1)` = 第 2 题是说法题）。
  顺序变数据后全失效 → 改成按类型现找（`_new_fact_index()` / `_q_kind()`）。
  **改动散布在四处**：TestRunner、WardrobeTest、编辑器冒烟、手机编辑器冒烟、截图脚本
- **`Array or []` 在 GDScript 里非法**（`or` 只吃 bool）→ 探针 print 的参数求值直接报错，
  表现为「打印到一半进程就没了」，查了好几轮
- **GDScript 没有 `repr()`**（那是 Python 的）
- **删跨行 print 要连后半截一起删**（只匹配第一行的正则 → 留下孤行 → Parse Error 且行号指偏）
- **`bgSections` 的旧分区要一起删**：迁移删掉了 `companion_questions` 段，
  背景页还留着读它的 section → `arr()` 返回 undefined → 冒烟崩在字段遍历
- **断言会「空转通过」比失败更隐蔽**：同行者问答那段读旧段，循环一次都不进、
  三个计数器全 0 → 断言全绿但什么都没测。改完后**加了一条「样本里确实查到了」的断言**防回归
- **`_companion_option_index` 的 kind 假设**：新 schema 下「不表态」选项的 kind 是 `evade`
  而不是 `companion`（只有「某个版本」才是 companion）
- **QTE 计划表是按题号的**，题序一变测试就错位 → 改成按实际题号生成计划

# 追加：关卡的反差值要求改成「自增 + 可手写覆盖」

## 用户口径

> 「还有关卡的反差值要求自增同时也可以修改」

## 设计

**留空（或 0 / 负数）= 自动**：
- 第 1 关留空 → 用 `rules.contrast_req_base`（出厂 20）
- 后面每一关留空 → 上一关的**最终值** + `rules.contrast_req_step`（出厂 10）
- 任何一关**写了正数** → 用它，**并且成为它后面那些关自增的新起点**

所以「自增」不是固定公式，而是**以手写值为锚点**的阶梯 —— 可以在某一关插一个数、后面整段跟着抬。

**为什么不做成「按关号套公式」**：实际能拿到的最大反差受**暴露值上限**卡着
（第 28 轮实测第 3/4 关都卡在 60），曲线未必是笔直斜线。

## 实现

| 位置 | 改动 |
|---|---|
| `OutfitData.DEFAULT_LEVELS` | 第 1 关留 20，其余三关**删掉 `contrast_req`**（留空 = 自增） |
| `OutfitData._resolve_contrast_req()` | 新增：解析整条曲线，结果**写回** `LEVELS[i].contrast_req` —— 下游（判定/界面/测试）读到的永远是最终值，不需要到处判断「这关是不是自动的」 |
| `OutfitData.contrast_req_is_auto(li)` | 新增：给界面显示用（手写 / 自增） |
| `OutfitData.CONTRAST_REQ_BASE/STEP` | 新增两个常量（出厂 20 / 10） |
| `ScenarioData.DEFAULT_RULES` | 加 `contrast_req_base` / `contrast_req_step`（31 → 33 项） |
| `ScenarioData.LEVELS_EXPORT()` | ★ 改成导出**未解析**的表 |
| 编辑器 num 字段 | 新增 `blankZero`：0 显示成空框 + 灰字「自动」 |
| 编辑器关卡页 | `contrast_req` 用 `blankZero` + 说明「留空 = 上一关 + 每关自增」 |
| 编辑器校验器 | **先解析整条曲线**再校验递增与理论上界（与游戏端同一套规则） |
| 编辑器首页 | 顺手修掉两个 stale 计数（`companion_questions` / `blind_questions` 已并入 `questions`） |

## ★ 关键坑

**`LEVELS_EXPORT()` 不能导出 `OutfitData.levels()`。** 那是**解析过**的运行表 ——
自增出来的数字被烤进 story.json 之后就变成「每关都手写了」，自增机制等于当场失效。
改成导出 `levels_override()`（没有则 `DEFAULT_LEVELS`），**留空的关保持留空**。

**另一个坑**：改 `story.json` 的 levels / rules 时**绝不能重跑 `DumpStory.tscn`** ——
第 29 轮迁移的 `questions[]`（每套 24 道）只存在于 story.json，GDScript 常量里没有，
重跑会把它冲掉。这次是用 Python 精确改的两个字段。
