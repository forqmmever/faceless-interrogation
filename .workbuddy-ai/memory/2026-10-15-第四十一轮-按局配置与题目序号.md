# 第四十一轮：按局（背景）配置流程 + 题目出场序号 + 删轮次联动 + 记住保存位置

日期：2026-10-15

## 用户口径（原话）

> 「题目编辑器，题目出现顺序也应该可以设置，删除关卡后只出现在对应关卡的题目也应自动删去，
> 每局游戏应该能够设置不同强制穿着，qte计划，身体缺陷，关卡轮数，原貌，
> 结果json保存的位置应位于编辑器同一目录」

补充澄清：
- 生效方式 → **按背景分别配置**
- 保存位置 → **对话框默认定位 tools/**
- 题目顺序 → **加「出场序号」字段**
- 「原貌也是按背景的四关每关都可以设置不同的」

## 术语（用户明确定义，之后一律照此）

| 词 | 含义 |
|---|---|
| **一局** | 含一套背景 + 若干轮的那一整局（点开始游戏之后的那一盘） |
| **一轮** | 一次换装 + 问答环节（代码里的 `level_index`） |

以前文档「关」「轮」混用，本轮统一成「轮」。

## 一、五项配置挂到背景上（因为「一局」= 抽到哪套背景）

`backgrounds[i]` 下新增/扩展五个键：

| 键 | 语义 |
|---|---|
| `levels` | ★ **长度 = 本局几轮**；第 i 条是对全局第 i 轮的**逐键覆写** |
| `forced_rules` | 非空即整份取代全局 |
| `qte_plan` | 同上 |
| `defects` | 同上 |
| `true_presets` | 本局原貌（`pool` + `by_level` 逐轮各一套） |

★ **五项都空 = 完全等于以前的行为**（逐字节不变）—— 这是最重要的不变量。

### `levels` 的不对称语义（刻意的）

另外四项是「非空即整份取代」，`levels` 是「非空则长度定轮数 + 逐条按索引覆写」。
原因：背景原先就用它覆写「每一轮叫什么名字」，那时长度必须等于全局轮数。
现在给长度赋予意义 → 「让某套背景只打 3 轮」只要写 3 条，旧数据语义不变。

★ 名字仍由 `RunData.levels()` 叠；`OutfitData.level_at().name` **保留全局名** ——
选轮面板在开局前要显示名字，那时还没抽背景，拿不到也不该拿背景的名字。

## 二、运行时接入：沿用「原地改运行表」

```gdscript
OutfitData.apply_run_overrides(background_id)        # 轮数 / 强制 / 缺陷
ScenarioData.apply_run_qte_plan(background_id)       # QTE
ScenarioData.apply_run_true_presets(background_id)   # 原貌
```

于是 `level_count()` / `forced_rules_at()` / `defects()` / `qte_plan_entry()` /
`true_preset_by_level()` **一行都没改**就自动看到本局那份。

★ **时机**：必须在「设置 level_index / 抽原貌 / 抽强制装备」**之前** ——
关卡覆写决定打几轮，level_index 要按它 clamp、原貌的逐轮预设要按它对齐。

## 三、题目出场序号 `order`

- 同一轮的固定题按 `order` 升序
- **没写 order 的用「它在清单里的下标」当序号**
  → 一道都不写 = 顺序不变；只给某几道写 = 把那儿道插到指定位置
- 想完全控制一轮的出题顺序：把该轮需要的题都标「固定给这一轮」+ 填序号
  （多填也行，多出来的会一起出）

★ **排序必须显式带「原下标」做第二键** —— GDScript `sort_custom` 是**不稳定排序**，
两个相同 order 之间顺序不确定。不处理会导致同一批题每次跑都换位置（偶发、极难查）。

## 四、删轮次联动删题

删掉第 N 轮时：
1. 删掉「固定给这一轮」的题目
2. 把「属于后面几轮」的题目整体往前挪一轮
3. 原貌的「逐轮指定」同样删掉 / 前挪

弹一次确认把牵连列清楚（删几道 / 挪几道 / 动没动原貌），说明只能 Ctrl+Z；
没有牵连时不弹窗、直接删。

实现：给 `renderObjList` 加 `onBeforeDelete` 钩子（返回 `false` = 取消删除）。
**通用列表组件不掺业务规则** —— 联动逻辑挂在 `bgSections` 的那一节上。

## 五、编辑器新增

- 背景页：③「本局几轮」+ 三个「⑥ 本局覆写 · 强制穿着 / QTE / 缺陷」+「原貌（逐轮）」
- 原貌编辑器抽成共用函数 `presetEditor(main, host, levelCount, scopeKey)`，
  全局 / 每套背景共用；切页按 scope 把选中项归零（否则会串味）
- 题库页：每题加「出场序号」

## 六、新增的数字字段语义 `blankDelete`

**空框 = 这一项不覆写（把键删掉）**，与既有的 `blankZero`（0 就是没写）区分。

★ 必须区分的原因：覆写里 **0 是有效值** ——
最后一轮的 `acceptance_gain` 就是 0（「后面没轮次了」），
不能当成「没写」而退回全局的 5。

## 七、保存位置（浏览器限制下的合规做法）

用户要「json 保存到编辑器同一目录」。
★ `showSaveFilePicker` **不能**接收任意路径（安全沙箱）。两条合规办法：

1. `showSaveFilePicker({id: "faceless-story-json"})` —— 同一 id 记住**上次的目录**
2. 把 `fileHandle` 存进 **IndexedDB** → 重开页面按 Ctrl+S 直接写回同一文件

权限 `requestPermission` 只在用户手势里申请得到 → 放在 Ctrl+S 那一步。
UI 标出「已连上文件 / 记忆里有上次的文件」。

## 九、踩到的坑

1. **GDScript 不支持单行 `if ... else` 语句** ——
   `if x == null: a else: b` 直接 Parse Error。必须拆成多行。
   （只支持 `x if cond else y` 这种**表达式**形式。）
2. 编辑时误删换行，把两行合成一行 —— 改完要**回读一眼**。
3. 测试断言一开始写错了对象：轮次名走的是 `RunData.levels()`（叠背景名），
   而不是 `OutfitData.level_at().name`（全局名）。**断言前先想清楚「这个值由谁产出」。**
