# 第四十四轮：照片排除原貌 + 点缀（眼镜/发型/鞋子）整局各自最多一次

日期：2026-10-15

## 用户口径

> 「改成排除原貌，改后会不会导致无法过关」
> 「鞋子、发型、眼镜这三样在**所有照片里各自最多出现一次**，因为这三样东西类型太少」

澄清（AskUserQuestion）：
- 「最多一次」而非「恰好一次」→ **可能一次都不出**
- 名额**整局共享**（不是每轮重置）

★ 术语理解修正：我第一版把「只会出现一种」理解成「**一张照片里**三者最多一个」，
  用户纠正为「**所有照片中**各自最多出现一次」—— 是**跨照片**的约束，不是照片内的。

## 一、★ 回答问题：「会不会导致无法过关」→ 不会

三条独立证据（都实测过）：

1. **原貌不靠照片解锁** —— `IntelDesk._fill_revealed()` 在**开局**把全部槽位标成已还原。
   用真实场景（Main.tscn）实测：`revealed_slots 13 / auto_slots 13`，**一张照片都没擦**。
2. **全程不擦照片 → 40 种子 × 4 轮 = 160 轮「一键达标」0 失败。**
3. 「一键达标」压根不读相册（`auto_complete_outfit` 只看 `true_appearance`）。

★ 探查方法上的收获：**第一版探针直接调 `RunData.start_new_run()` 得到 revealed_slots = 0** ——
  因为 `revealed_slots` 是**情报台**（UI 层）写进去的，探针没实例化场景就看不到。
  改成 `load("res://scenes/Main.tscn").instantiate()` + `main._start_new_run()` 才拿到真实值。
  **探针要跑真实链路，否则会得到假结论。**

## 二、照片排除原貌

`_shown_item_near()` 的候选里跳过 `true_item(slot)`。

★ 兜底：某栏除了原貌再没别的可穿时，只能照实显示（`is_true` 如实标出）。
★ 连带：`is_true` 现在几乎全 false → 「擦亮照片 = 白捡一处还原」基本不再触发。
  这是刻意的，代码保留为兜底。

## 三、点缀整局共享名额

```gdscript
const PHOTO_ONE_OF := ["glasses", "hair", "shoes"]
var _photo_used_one_of: Dictionary = {}    # RunData 里，每局在 _roll_photos() 清空
```

- **主体**（top / bottom）：各自独立，每张照片 50%
- **点缀**：整局掷，每张照片 50% 决定要不要用掉一个名额；用过就从候选里消失

实测（40 局 × 完整 4 轮 = 360 张）：眼镜 31 / 发型 32 / 鞋子 38，**超标 0 次**；
每样在 78% / 80% / 95% 的局里出现过 → 确实「可能不出」。

★ 用户给的理由很关键：**「因为这三样东西类型太少」**。
  款式少时，同一部位在两三张照片里显示不同的款 → 玩家立刻能缩小范围 → 等于给答案。
  所以宁可只出现一次。

## 五、可复用的规矩

1. **探针必须跑真实链路**（实例化 Main.tscn），否则 UI 层写入的状态看不到 → 假结论。
2. **给约束写测试时，配一条「对照断言」** —— 证明规则是**特定于**某些对象的，
   而不是一刀切（否则规则写歪了测试也会绿）。
3. **跨「批次」的约束要跑完整流程** —— 照片逐轮追加，只在第一批验，等于没验。
