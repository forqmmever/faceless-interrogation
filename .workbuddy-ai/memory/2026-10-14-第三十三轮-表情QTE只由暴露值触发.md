# 第三十三轮：表情 QTE 改成「只由暴露值触发」+ 提示文字可编辑（2026-10-14）

用户口径：

> 「暴露值越高现在只会影响按住空格的 qte 即表情管理的 qte，越高触发次数越多，
> 表情管理 qte 现在不会因为别的原因触发，表情管理 qte 还是按之前的设计，
> 一个问题只会出现一次，qte 上方显示的提示文字可以编辑」

## 一、先摸清「暴露值到底影响了什么」

改之前 `exposure` 有**两个**作用面：
1. `needs_expression_for()` —— 暴露值 ≥ `exposure_qte_threshold`(30) → 连寻常题也要压表情；
2. `interference_interval()` —— `max(6.0, 14.0 − 暴露值 × 0.18)`，即**递话干扰也随暴露值变密**。

第二处就是「只会影响」这句话要不要严格执行的分歧点 —— 问过用户，答案是
**彻底解耦：干扰改成固定间隔**。

## 二、表情 QTE 的新触发条件

**只剩两条**：
- 第 1 题恒不出（第十三轮定的，保留 —— 开场先让你把第一句话说完）；
- 其余看暴露值给出的**线性斜坡概率**。

```
p = (暴露值 − exposure_qte_min) / (exposure_qte_full − exposure_qte_min)   夹在 0~1
```

| 参数 | 出厂 | 含义 |
|---|---|---|
| `exposure_qte_min` | 10 | ≤ 它 → 一次都不出 |
| `exposure_qte_full` | 60 | ≥ 它 → 每题必出 |

**删掉的旧触发条件**（用户说的「别的原因」）：
① 题目是盲区题（gap）/ 当场硬答（made_up）；② 选项里有「说漏嘴」（leak）或「当场硬答」（made_up）。

★ 按当前接受度（6/11/16/22 → 暴露上限 22/32/42/54）推算，
四关穿到满暴露时概率约 **24% / 44% / 64% / 88%** —— 越往后越常被盯，
同一关里穿得越露也越频繁。这正好落在「越高触发次数越多」上。

★ 「一个问题只会出现一次」**没动** —— 那是第十三轮定的设计，
`needs_expression_for` 只决定「这一题出不出」，出与不出都由 `qte_done` 把这一题锁死。

★ 题目**显式**写 `qte: expression` 的仍然照出 —— 那是作者的手动安排，不是「自动触发」。

## 三、★ 摇号必须稳定（不是随便用 RNG）

`_expr_qte_roll(index)` 用 `hash("seed|关号|题号|expr") % 10000 / 10000` 得到 0~1 的稳定值，
**不用运行时 `RandomNumberGenerator`**。原因：
同一道题可能被**反复装载**（来回切题、重来本轮、测试里多次 `_load_question`）——
每次现摇会变成「同一题一会儿出一会儿不出」，玩家莫名其妙，测试也没法断言。
新增断言专门查这一点（同一题连问 16 次结果必须一致）。

## 四、干扰：拆掉暴露值耦合

```gdscript
func interference_interval() -> float:
    return _rf("interference_base", INTERFERENCE_BASE)   # 固定 14.0 秒
```
删掉 `interference_min`(6.0) 与 `interference_per_exposure`(0.18) 两条规则与两个常量。
（旧公式写在注释里，想恢复照着加回来即可。）

## 五、QTE 提示文字可编辑

**全局那句**（`ui.interrogation.qte_prompt`）其实早就在编辑器里了 —— 用户提这条，
顺着第 29 轮的按题 `qte` schema 补上**按题覆盖**更有价值：

- 新字段 `questions[].qte.prompt`
- 读取：`_apply_qte_plan()` → `qte_prompt_used`（题目自带优先）
- 使用：`_begin_qte()` → 有覆盖就用它，否则回落 `_ut("interrogation.qte_prompt", ...)`
- 编辑器**两处**都能改：① 题库页的「每题」字段（`sub:"qte"`）；② 全局 QTE 计划页

## 七、踩坑

- **GDScript 类型推断又踩一次**：`var ch_mid := interro.expression_qte_chance()` 报
  `Cannot infer the type`（`interro` 是弱类型引用）→ 改成 `var ch_mid: float = ...`。
  同一段里 `var first := interro.needs_expression_for(...)` 也一样。
- **自己写的断言取样点错了**：想验「越高越大」，却取了 min+5 / 中点 / min+15 ——
  第三个点（25）比中点（35）还低，于是 0.10 < 0.50 < 0.30 挂了。
  改成 min+5 / 中点 / full−5 才是递增的三个点。
  ★ 教训：写「单调」类断言时，**先把取样点的数值写下来核对一遍**。
- **`const qFields` 重名**：`editor_smoke.js` 里同一个作用域已有 `const qFields`，
  我新加的又声明一次 → 改名 `qFieldKeys` / `qteFieldKeys` 规避（比赌作用域块安全）。
- `auto` 的说明文案在编辑器里**有两处**（题库页 + 全局 QTE 页），只改一处会漏。
