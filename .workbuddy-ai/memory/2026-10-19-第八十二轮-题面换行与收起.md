# 第八十二轮（2026-10-19）：点完选项收起题面 · 长题面自动换行

用户口径：
1. 「点击选项后题面要消失」
2. 「第三个背景有题面显示不全的现象」
3. 「回应显示也出现了问题」
4. 「过长就自动换行 保持原来字体样式」

## 一、题面显示不全 = 整块溢出，不是裁字

### 诊断（先量再改）

探针在 `Main.tscn` 的真实布局里打印布局链：

```
VBoxContainer=490 → MarginContainer=518 → PanelContainer=518
→ HBoxContainer=518 → VBoxContainer=688 → MarginContainer=720
```

可用高度只有 **490**（`root` 里还有顶栏 + 底部常驻占位带 96）。
而左栏 `PanelContainer` 被撑到 **518 / 536 / 629** —— 内容越长，最小高度越大，
于是它作为 `root` 子项把后面的东西一路往下推，**底部被切在 720 之外**。

第 3 套背景（`scene_1`）题面最长（110 字 / 7 行）→ 正好越过那条线，
所以只有它「显示不全」。另外两套题面都 ≤ 3 行，没露出来。

★ 关键理解：`autowrap` 只管换行，**换行后 Label 高度按行数长**；
`PanelContainer` 会把这个高度当成自己的最小高度 → 撑高父容器 → 溢出。
所以「加 `autowrap`」「调 `custom_minimum_size`」都不解决。

### 修法

```gdscript
var top_clip := Control.new()        # 普通 Control，不是 Container
top_clip.clip_contents = true
top_clip.size_flags_vertical = EXPAND_FILL

var scroll := ScrollContainer.new()  # 横向 DISABLED → 子项宽 = 容器宽 → 自动换行
scroll.horizontal_scroll_mode = SCROLL_MODE_DISABLED
scroll.vertical_scroll_mode = SCROLL_MODE_AUTO
```

- 普通 `Control` 的 `get_minimum_size()` **只认 `custom_minimum_size`**，不会把子项
  的文本高度传上去 —— 这是「不让内容撑高父容器」的关键。
- `ScrollContainer` 用 anchor 充满 `top_clip`，超出的部分改成可滚动。
- 回应 / 题面 / 反馈三块搬进 `top_box`。
- 选项区 `EXPAND_FILL` → **`SHRINK_END`**（两个都 EXPAND 会各分一半，文字区只剩 200 多像素）。
- 换题时 `top_scroll.scroll_vertical = 0`。

### 实测

| 项 | 结果 |
|---|---|
| 文字区 | 宽 1204 / 可用高 323～378 |
| 正常题面（60 字） | 2 行，字号 15 |
| 10 倍（600 字） | 11 行（scene_1）/ 5 行（scene_2），字号仍 15 |
| 内容 414 > 可用 378 | 出滚动条，不放大不缩小 |

## 二、点完选项收起题面

```gdscript
# _select_option()，在贴完回应之后
_set_dialogue_visible(false)
```

新增两个帮手：
- `_set_dialogue_visible(on)` —— 只切可见性；
- `_set_dialogue(txt)` —— 写文本 + 按「非空」决定可见（收场台词必须走它，
  否则「题面收起了，结局那句话跟着看不见」）。

`_load_question()` 里 `_set_dialogue(...)` 会自动恢复显示。

## 三、「回应显示出问题」的真凶：判定解释只活 1.8 秒

`_load_question()` 原来调 `_show_choice_echo()`，而它会 `feedback_label.text = ""`。
第 81 轮把回应搬去 `echo_label` 之后，反馈区只剩判定解释 —— 于是
「怀疑度 +12」「前后矛盾说明」在下一题加载时（1.8 秒后）被清掉，玩家读不到。

改：**换题不碰反馈区**。回应自己会留着（`echo_label` 不随换题清），
判定解释也留着，两者一起到下一次选择（那时 `_show_choice_echo()` 才清）。

## 四、验证

```
答题前：题面可见=true 60字 | 回应可见=false
答完后：题面可见=false | 回应可见=true [空太郎不理解为什么会有这样的女孩…]
1.8 秒后：题面可见=true 34字 | 回应仍可见=true | 滚动位=0
长题面 10 倍：5 行 / 字号 15 / 内容 414 > 滚动区 378 → 可滚动
```

`TestRunner` **792 / 85 失败**（失败仍是用户数据那批 + scene_1 死局）；
「选项回应」一节 **15 条全 PASS**，新加两条：答完收起 / 新题恢复。
2 条 `SCRIPT ERROR` 是 scene_2 短信数组为空导致（数据问题，非本轮）。

## 五、踩坑

- 探针一开始量到宽 269、行数不对 —— 因为**没在 `Main.tscn` 的真实布局里**，
  单独 `add_child` 出来的 Interrogation 尺寸是假的。必须 `Main.tscn` + `await` 两帧。
- 换背景时必须 `it._questions = []`，否则 `_ensure_questions()` 复用上一套的题，
  量出来的是「上一套背景的题面」。
- 局部变量别和成员同名（`var top_scroll := ...` 遮蔽成员，GDScript 会警告）。
- 截图这一步**没跑**：布局一改，43 张必然要重拍，等 scene_1 死局定下来一起做。
