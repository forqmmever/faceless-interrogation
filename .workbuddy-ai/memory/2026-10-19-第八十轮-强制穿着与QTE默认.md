# 第八十轮（2026-10-19）：强制穿着第 1 轮不生效 · 没写 qte 的题还是冒 QTE

用户口径：「为什么强制穿着不起作用，未设置 qte 的题目为什么还会出现 qte 改掉」。

## 一、强制穿着不起作用（三条原因，全在「读了但没生效」这一类）

### 1. `li <= 0` 把 fixed 也一起跳过了（真凶）

`RunData._roll_forced_items()` 原顺序：

```gdscript
if mode == FORCED_MODE_NONE: return
if li <= 0: return                      # ← 公平性护栏（random 用）
if mode == FORCED_MODE_FIXED: ...       # ← 永远走不到第 1 轮
```

一局只有 **2 轮**，用户 `scene_1` 的本局覆写是
`[{fixed: top_school_navy + bottom_school_navy}, {none}]` —— 正好落在第 1 轮 → 整局一次都不生效。
`README` 第 2140 行「第一轮穿着：强制校服上下装」也早就写着是这么设计的，所以这是实现漏了。

改成 fixed 先返回、`li <= 0` 只管 random。

### 2. `mode: none` + 非空 `rules` → 静默丢弃

用户顶层 `forced_rules` 实际长这样（两轮都是）：

```json
{"mode": "none", "rules": [{"items": ["hair_short"]}]}
```

编辑器「方式」下拉默认第一项就是「没有强制要求」，先加规则、忘了改方式 → `rules` 一个字都不读。
现在 `_ensure_forced_rules()` 里：`mode != fixed` 且 `rules` 非空 → 升级成 `fixed`。

★ 这条**只影响「有规则」的条目**，没规则的 `none` 仍然是「没有强制要求」。

### 3. 验证

一次性探针（`tests/_probe_fix80.*`，跑完即删）：

```
border_post 第1/2轮 fixed ["hair_short"]
scene_1     第1轮   fixed ["top_school_navy","bottom_school_navy"]   ← 改前是空
scene_1     第2轮   none  []
scene_2     第1/2轮 fixed ["hair_short"]
```

## 二、没写 qte 的题还会冒 QTE（两条原因叠加 + 一条真 bug）

| # | 原因 | 位置 |
|---|---|---|
| 1 | `qte_plan` 空 → `qte_plan_entry()` 返回 `auto` → 每道题都按暴露值摇号 | `OutfitData.qte_plan_entry()` |
| 2 | `QTE_NONE` 只关表情 QTE，**随机递话照样来** | `Interrogation._process_interference_timer()` |
| 3 | ★ 编辑器把类型写进 `qte.qte`，游戏只读 `qte.kind` → 选「无」等于没选 | 编辑器 `questionFields()` |

第 3 条是这一轮最有价值的发现：`{k:"qte", sub:"qte"}` 写出来是 `q["qte"]["qte"]`，
而 `_apply_qte_plan()` 读 `od.get("kind")`。用户在编辑器里改了半天，数据变了、运行时没变。

### 改法

1. `qte_plan_entry()` 兜底 `QTE_NONE`；
2. 新增 `OutfitData.question_qte_plan(q, index)`：
   优先级 **题目自带 > 按题号表 > none**；`kind` / `qte` 两个键都认；未知类型退成 none（不再静默变 auto）；
3. `Interrogation._apply_qte_plan()` 改调它（不再自己解析），`QTE_NONE` 时置 `_intf_suppressed = true`；
   `_process_interference_timer()` 开头 `if _intf_suppressed: return`；`_cancel_qte()` 里复位；
4. 编辑器题目字段 `{k:"qte"}` → `{k:"kind"}`；`QUESTION_QTE_OPTS` 把「无」排第一（没写的题显示「无」，与实际行为一致）；
5. `story.json` 9 处 `{"qte": {"qte": ...}}` → `{"qte": {"kind": ...}}`（正则只动这个键名，值不变）。

## 四、测试断言跟着改的地方

- `WardrobeTest`：`qte_plan_entry(0)/(999)` 期望 auto → **none**；新增 4 条 `question_qte_plan`
  （kind / 旧 qte 键 / 完全没写 / 未知类型）；「出厂第 1 轮 none、第 2 轮 random」改成查规则本身
  （用户数据早已不是那样，这两条一直假红）。
- `TestRunner`：「计划清空后回到自动判定」→「默认 = 无 + `_intf_suppressed`」；
  新增 `_clear_question_qte(index)`，因为**题目自带的 qte 现在真的会覆盖按题号表**，
  验表的用例必须先清掉题目自己那份（否则碰上 s1_q6 就假红）。
- 编辑器冒烟没跑（用户口径：不要浪费时间）；只做了 `build_story_editor.py` 重建快照 + `node --check`。

## 五、踩坑记录

- 用 Edit 改 GDScript 函数签名行时把换行吞了两次（`func _prepare_and_enter() -> void:	_reveal_all()`）——
  改完一定 `grep -n "func _" -A 2` 复查。
- 探针里 `var need := it.qte_needed`（无类型标注 + Variant 来源）会 Parse Error；标成 `bool()`。
- `level_questions()` 在 `_load_question()` 之前是空的 —— 探针要先装一道题再取列表，
  否则 `range(1, 0)` 静默跑 0 次（又踩一次「空转通过」）。
