# 第七十二轮：每轮的背景说明，在编辑器里真的能改了

日期：2026-10-18

## 一、用户口径

> 「不同轮游戏的背景说明，现在依然无法在编辑器里编辑，」

「依然」二字说明这是**第六十轮没做完的那件事**的复查。

## 二、真相：字段加对了名字，加错了地方

第六十轮的做法是「往 `levelsFields()` 里加一栏 `intro`」。问题是——
**`levelsFields()` 只被「🪜 关卡与轮数」页用**（那一页写的是 `story.levels`，
四套背景共用的**默认值**）。

而「🎬 背景」页的 **「⑦ 本局覆写 · 几轮」是另写的一份字段表**：

```js
{ key:"levels", title:"⑦ 本局覆写 · 几轮 + 每轮的名字 / 说明 / 数值",
  kind:"objlist", arr:()=>bg.levels,
  fields:[ {k:"name"}, {k:"derived_profile"}, {k:"acceptance_gain"}, {k:"contrast_req"} ] }
```

—— 只有四条，没有 `intro`。标题里却写着「说明」，所以看起来「应该能改」。

### 为什么在全局页改了也没用（游戏读哪一份）

```
bg.levels[i].intro
  → OutfitData._ensure_levels()   逐键并进 LEVELS[i]（只跳过 name / derived_profile）
  → RunData.levels()              从 LEVELS[i] 复制，只覆盖 name / derived_profile → intro 活着
  → RunData.current_level()["intro"]
  → DossierData.intro_text()      非空就用它，空才回落 ScenarioData.intro_of(背景).intro
```

出厂四套背景的 `levels[i]` **各自都写了 `intro`**，所以 `story.levels[i].intro`
永远被盖掉 —— 在「关卡与轮数」页里改，界面上看不出任何变化，等于**白改**。
（`story.levels` 出厂本来也没有 `intro` 键，那一栏一直是空的。）

## 三、改动

| 位置 | 改动 |
|---|---|
| `tools/story_editor.html` `bgSections()` 的 `levels` 节 | **加 `{k:"intro", t:"area", rows:5}`**，放在 name / derived_profile 之后 |
| `tools/story_editor.html` `levelsFields()`（全局页） | 标签改成「（默认，可空）」，hint 明说「四套背景各自都写了，想改某一局请去背景页」 |
| `tools/story_editor.html` 「⑦ 本局覆写 · 怎么读」 | 「③ 本局几轮」→「⑦ 本局覆写 · 几轮」（旧编号是第四十一轮挪节时漏改的），并补一句「每条里的背景说明就是那一轮浮窗的正文」 |
| `tools/editor_smoke.js` | 新增 5 条断言（见下），364 → **369** |

**运行时一行没改** —— 数据本来就在 `bg.levels[i].intro` 里、取值链路也是通的，
坏的只是「编辑器没把这一栏摆出来」。

## 四、新增断言（防「两处字段表只改一处」）

```
-- 7c2. 每轮的背景说明（浮窗正文）在背景页里能改 --
```

1. `levelsFields()` 里仍有 `intro`（全局页那份兜底没被删掉）
2. 背景页有 `levels` 这一节
3. **⑦ 几轮里能改「这一轮的背景说明」**（列出现有字段名，挂的时候一眼看出少了哪个）
4. 名字 / 反差要求仍在（防止这轮改动把它们挤掉）
5. 出厂四套背景 × 2 轮：每轮都有说明、两轮不相同（第六十轮的约定，之前只有 WardrobeTest 在管数据侧）

★ 反向验证：把 `k:"intro"` 临时改成 `k:"introX"` 再跑 →
   `[FAIL] ⑦ 几轮里能改「这一轮的背景说明」（实际：name,derived_profile,introX,acceptance_gain,contrast_req）`
   → 还原后 369/0。**断言确实抓得住**。

## 六、通用教训（已写进 MEMORY.md）

**同一个字段在两处各写一份字段表时，加字段只加一处 = 那一处是死的。**
`levelsFields()`（全局页）与 `bgSections().levels.fields`（背景页）就是这样两份 ——
以后再加「逐轮」类字段（轮次名 / 数值 / 说明……），**两处都要加**，
并让冒烟断言盯住背景页那份（那才是游戏真正读的）。

★ 另一条：**标题写着「说明」不等于有说明字段** —— 用户看到的「无法编辑」往往就是这种
「标题承诺了、字段没给」的错位，查的时候先数 `fields` 的键，别读标题。
