## 一、工作流

### 一轮的收尾动作

1. `CHANGELOG.md` 追加一节 → **git 提交一次**，提交信息 = 那节第一行。「测试」行必须是真跑过的数字；
   同轮第二块工作写「第 N 轮（续）」。
2. `README.md` —— **只写「现在是什么 / 怎么用」，不写「为什么这么改」**（那是 CHANGELOG 的事）。
   ★★ **第 96 轮改的**：原来是「README 写为什么这么改 / 机制 / 数值表 / 踩坑」——
   这条规矩就是 README 涨到 6253 行 / 434KB 的**根因**。现在三条判据：
   - **带「第 N 轮」字样的段落不进 README**（一旦出现就说明是历史，属于 CHANGELOG）；
   - **会过期的数字不进 README**（断言数、物品数、截图数）—— 要么不写，要么写「见 `CHANGELOG` 末尾表」；
   - **单节超 250 行就拆**（说明它没被组织过）。
   改完跑 **`python tools/readme_check.py`**（五类检查，`--strict` 有错退出码 1）。
   ★ **删章节时先 `grep` 那个标题名**，看谁在引用它 —— 第 96 轮删完发现 5 处「见下文某节」
   失效，其中 3 处（「轮次与曲线」「盘问中掏手机」「怀疑度的来源」）**早就烂了**。
   ★ 全文基线 2576 行（第 96 轮瘦身后），涨过 10% 检查器会报。
3. `memory/` 写明细 —— 分文件，进版本库（`.workbuddy-ai/tmp/` **不进**）。

★★ **memory 只维护 D: 这一份**：`D:\workbuddy\2026-10-11-09-19-59\.workbuddy-ai\memory\`
—— 用户 2026-10-19 明确要求：**不再压缩 `MEMORY.md`**、**不再同步到 C 盘**。

## 三、测试怎么写（细则见 `REFERENCE.md` 五章）

- ★★ **校验面板只放「问题」** —— 出厂数据必须 **0 错误 0 提醒**。**一片提醒先怀疑规则**。
- ★★ **跑完看三样**：`Failures: 0`、**有没有 `SCRIPT ERROR`**、**断言总数有没有莫名减少**
  —— 报错不会让测试失败，只会让那一行静默消失。取数组用 `_arr_of(d, key)`。
- **防「空转通过」**：循环一次都不进 = 什么都没测；`_check(..., true)` 也是空转
  （第 92 轮差点留下一条）。**加「样本里确实查到 N 条」的断言**。
- ★ **写断言的四个老坑**：① 只对部分对象生效的规则配**对照断言**；② 写完**故意改回错的**验证能抓到；
  ③「非空」看不见「少做一步」→ 判**数值范围**；④「单调」前**先写下取值点**。
  ★ 验「文本不重复」去掉「A. 」前缀再比（第 77 轮，前缀把重名盖住）。
- ★★ **别让断言依赖「上一个测试留下的局」**（随机种子 → 假失败）；断言「涨 N 点」前**钉死基数**。
- ★ **纯函数测不出「时间线上的 bug」** → 状态随轮次变要走**全流程探针**。
- ★★ **背景不止一种形态时测试要自己挑**：`scene_*` 是 `manual`；依赖某类数据的**钉 `_canonical_bg()`**。
- **用完清跨局状态**：`ProfileData.reset_all()` + 注入的 `_*_presets` 清回 `{}`。
- ★ **改全局数值 / 删文案键** → `tests/` 与 `editor_smoke.js` 写死的计数成片挂，改用常量或 `>=`。
- ★★ **删代码前 grep 它定义的局部变量**（第 83 轮带走 `knownTags` → 冒烟 `ReferenceError`）；
  删局部变量要搜**整个函数体**（续 2 漏了 `declared`，autoload 起不来）。

### ★★ 基线对照：HEAD 数据已经是脏的（第 88 轮起）

第 86 轮提交把用户工作区数据一起带进去了：`border_post` 停用、`bg_new_1` 空、两套 `scene_*` 全 `manual`。
后果：`TestRunner._canonical_bg()` **返回空** → **毫秒种子随机**挑背景 → 同代码两次失败数相差 ±2。
★ 先看「钉在…实际 scene_X」那行挑到了谁。★ 对照：`git worktree`（**先 `--import`**）跑基线，
**失败集 `grep FAIL | sort` + `diff` 比，比数数字可靠**。

### ★★ 截图「变了」怎么判（细则见 `REFERENCE.md`）

1. **先退回 HEAD 重拍**（三方对照）：`③新 vs ②HEAD = 0` 而 `①提交 vs ② ≠ 0` → 仓库那张是旧货。
2. **「时对时错」先查这一屏状态钉没钉死**，再查定时器（`set_process(false)` **停不住 `create_timer()`**）。
3. **判噪声**：同代码连跑两次 —— 差异量级相当就是抖动。★ 对照取 `git show HEAD:screenshots/*.png`，
   **别「跑之前 cp」**（异步任务，cp 常落在跑完之后 → 对照组是新的，看成「没变」）。
4. ★ 报「真变」要给机制上的量 + 差异百分比 + bbox。工具 `tools/cmp_shots.py`。

### ★★ 截图脚本「前置不满足就跳过」= 静默留过期图（第 89 轮）

`else: _plog("!! 跳过")` 的分支，数据一变就整屏不拍，目录里留着旧轮次那张（**可能还带着已删功能**）。
日志里 `!! 跳过` 要当**失败**看；修法优先「给这张图找退路」（借一道普通题拍），不是删图。
