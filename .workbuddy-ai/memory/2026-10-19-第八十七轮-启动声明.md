# 第 87 轮：启动声明（进游戏前 3 秒）

用户口径：「进入游戏界面前显示这段文字 3 秒 本作品无色情内容，无不良引导，完全免费。」

## 一、做法：盖一层，不延后建标题

```
_ready()
  ├─ _build_title / _build_level_select / _build_overlay / _build_intro
  ├─ help_overlay
  ├─ _build_splash()      ← 最后建 = 最上层
  ├─ _show_title()        ← 标题第一帧就绪
  └─ _show_splash()       ← create_timer(3.0) → _hide_splash()
```

为什么不能「先不显示标题、3 秒后再显示」：

- `TestRunner` 启动后**一帧**就读 `title_screen.visible`（「开局先出开始界面」）；
- 截图脚本也是启动后立刻开拍，会拍到空白；
- 声明层只做遮挡：`mouse_filter = MOUSE_FILTER_STOP`，3 秒内点不到按钮，但状态已就绪。

`_skip_splash()` 给测试 / 截图用（不等 3 秒）。

## 二、文案

| 位置 | 键 |
|---|---|
| `data/story.json` → `ui.common` | `splash_text` |
| `ScenarioData.DEFAULT_UI.common` | `splash_text`（兜底，story.json 缺键也能跑） |
| 编辑器 | 「💬 界面文案 → ① 通用」第 2 条（多行框，2 行） |

连带改了两个写死计数（加键必然要动）：

- `editor_smoke`：`uiLeafCount()` 73 → 74
- `editor_smoke`：文案页字段覆盖 76 → 77

★ 第一次只改了 74 忘了 77，冒烟立刻报「文案页覆盖 76 条」——
这类计数是**两处**，改一个键要两个都数一遍。

## 三、测试

`_test_boot` 里 7 条静态断言：

1. 层建出来了
2. 启动那一刻亮着（标题在它下面已就绪）
3. 吃掉鼠标（MOUSE_FILTER_STOP）
4. 文案含「无色情内容 / 无不良引导 / 完全免费」
5. 文案来自 `ui.common.splash_text`
6. `SPLASH_SECONDS == 3.0`
7. `_skip_splash()` 后层收起、标题仍在

`_test_splash_autohide()`（`await` 调用，紧跟 `_test_boot`）—— 真实计时：

```
_show_splash() → 断言亮着 → 等 3.2 秒 → 断言自己收起 + 标题可见性没被连带改动
```

★ **踩到的坑**：第一版写的是「收起后标题可见」，跑出来 FAIL —— 因为 `_test_boot`
末尾已经真的开了一局（`_on_level_selected(0)`），那时 `title_screen` 本来就是收着的。
正确的断言是「前后可见性一致」，不是「可见」。
★ 这一段固定花 3 秒多，是整套测试里唯一真的等真实时间的地方。
