# 第八十四轮（2026-10-19）：短信气泡调宽 · 换背景轮次名 · 查清反差口径

用户三句：
1. 「短信中每条消息的显示调宽一点」
2. 「修复主界面切换背景，每轮的名字不会随之变化」
3. 「与相册里图片中的衣服相同暴露值的衣服还计算反差度吗」

## 一、短信气泡

`PhoneDesk._build_thread_view` 里那行是「垫片 : 气泡 : 垫片」，三个都 `EXPAND_FILL`
→ 每个各拿 1/3；手机内容区 `PHONE_W(336) - 9×2 - 8×2 = 302`，气泡只有 **~100px**。

改成按 `size_flags_stretch_ratio` 分配：

```gdscript
sp_l.size_flags_stretch_ratio = 1.0
sp_l.custom_minimum_size = Vector2(10, 0)     # 短消息不贴边
sp_r.size_flags_stretch_ratio = 1.0
sp_r.custom_minimum_size = Vector2(10, 0)
bubble.size_flags_stretch_ratio = 5.0
```

气泡拿 5/7 ≈ 71%，实测 **205px**（原来 ~100）。

## 二、切背景时轮次名不变

根因：`_build_level_select()` 只在 `_ready` 跑一次，行文字取 `OutfitData.level_at(li)`
（那是**上一局生效的 LEVELS**），`_on_bg_choice()` 只改按钮选中色、**没人重算名字**。

改法：
1. 轮次行搬进 `level_rows_box`（VBoxContainer，`_build_level_select` 里创建后调 `_rebuild_level_rows()`）；
2. 新增 `_levels_for_panel(bg_id)` —— **只读**，按「`OutfitData.global_levels()` +
   `ScenarioData.bg_levels(bg_id)` 逐键覆写」重算名字/推导形象。
   ★ 不能用 `OutfitData.level_at()`（取当前局 `_bg_levels`），也不能用 `RunData.levels()`
   （取 `background()` = 当前局）—— 面板里还没开局。
3. 新增 `_rebuild_level_rows()`：清空容器 → 按 lvs 逐行重建（样式/禁用/回调与原来一致）。

实测：

```
border_post → 第一轮 / 第二轮
scene_1     → 第一轮 · 桌游店偶遇 / 第二轮 · 生日宴
scene_2     → 第一轮 · 服装店试衣间 / 第二轮 · 又一次偶遇
```

## 三、反差口径：只看暴露值差（本轮只查清楚，没改）

`WardrobeModel._contrast_of`：

```
单槽位反差 = |你穿的 exposure − 原貌(true_appearance)那件 exposure| × contrast_per_exposure(5)
```

**不看「是不是同一件」**。所以换一件完全不同但暴露值相同的衣服 → 差 0 → **不涨反差**。

实测（原貌 短发，暴露 0）：

```
hair      利落短发 → 侧编辫     反差 0
glasses   不戴     → 圆框眼镜   反差 0
makeup    素颜     → 烈焰红唇   反差 0
earrings  不戴     → 戴耳钉     反差 0
```

按物品表统计的分布：

- 发型 7 件**全是暴露 0**；眼镜 3 件全 0；妆 5 件全 0；鞋 3 件全 0
- 颈饰：露 1 的三件、露 2 的三件
- 上装：露 6 的五件、露 7 的三件、露 9 的三件

→ **发型 / 眼镜 / 妆容 / 鞋 这四个槽位，怎么换都不涨反差。**

★ 为什么不改：`contrast_req` 的 125 / 150 是按这个公式标定的（第 49 轮全槽位改造时重标过），
改公式必须同时拉开原貌池 + 重标整条曲线，否则四关全部变白送或全部变无解。
所以本轮只写进 README，等用户定方案。

候选改法（供用户选，本轮**未实现**）：
- A. 每件物品加一个「不同件」保底分（如 +1/件），并把 `contrast_req` 整体按比例上调；
- B. 只给「同暴露值但不同件」加一个小分（如 +1），其余不动；
- C. 给发型/眼镜/妆/鞋这些槽位改用物品自己的 `contrast` 字段（现在被忽略）。

## 四、顺手修掉一段依赖用户数据的老测试

`TestRunner._test_new_mechanics` 的「强制装备」一节原来跑**随机背景**：
- 「每局第一轮没有强制服装要求」→ 撞上 `scene_1` / `scene_2` 第 1 轮的 `fixed`，必然假红；
- 后面几条拿到的是 `_roll_forced_items(1)` 临时抽的、与 RunData 实际那一轮错位。

改成：**注入一份两轮规则**（`[none, random]`）+ **钉住 `border_post`**（它自己的 `forced_rules` 是 `[]`，
会回落全局），并以「第 2 轮开局」真跑一遍。跑完还原 `ScenarioData._forced_ov`。
→ 4 条断言由红转绿。
