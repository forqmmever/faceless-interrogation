# 第九十七轮：README 重写成「只讲现状」+ 英文版（2026-10-20）

## 一、用户口径

「现在生成一个新的readme只保留现在是什么样的，再加上一个英文版本」。

## 二、为什么是重写而不是删改

旧版 2576 行里的历史成分：

| 成分 | 行数 | 占比 |
|---|---|---|
| `> ★ 第 N 轮…` 引用块 | 597 | 23% |
| 含「第 N 轮」 | 250 | 10% |
| 含「原来 / 以前 / 已删 / 作废」 | 82 | — |

逐块剥离会留下断句（比如「原来三栏…现在整块删掉」这种句子删掉一半就没法读）。
所以按「现在的事实」重新组织，不参考旧文的行文。

## 三、结果

- `README.md` **2576 → 642 行（-75%）**，30 KB
- `README.en.md` 新增 **685 行**，32 KB

主题覆盖（12 个二级标题）：快速开始 / 前提 / 一局流程 / 准备室 / 盘问 / 手机 / 数据 /
编辑器 / 美术 / 测试 / 截图 / 已知限制。

删掉的三节：

| 旧节 | 为什么不留 |
|---|---|
| 变更记录与版本控制 | 内容就是「去看 CHANGELOG」，目录结构里已列 |
| 位置 | 环境信息（项目在 D 盘），不是项目内容 |
| 后续可扩展方向 | 是未来，不是现状 |

## 五、英文版

不是逐字直译，按英文技术文档习惯重写。术语固定：

| 中文 | 英文 |
|---|---|
| 一局 | run |
| 一轮 | round |
| 准备室 | wardrobe |
| 盘问 | interrogation |
| 反差值 | contrast |
| 暴露值 | exposure |
| 接受度 | acceptance |
| 怀疑度 | suspicion |
| 性情 | temperament |

结构与数值与中文版一一对应，用脚本核对过关键数字（125 / 150 / 156 / 128 / +48 / +16 /
+36 / +45 / +32 / 0.5 / 2.6）在两版里出现次数一致。

## 六、检查器改造

`tools/readme_check.py` 从「只查 README.md」改成**多文件**：

```python
TARGETS = [
    ("README.md", 642),
    ("README.en.md", 685),
]
```

中文版跑全部五项；英文版只跑适用的三项（总量 / 单节超 250 行 / 假标题）——
「第 N 轮」与「N 项断言」两项对英文版没有意义。

## 七、教训

★★ **文档里的数值必须在改代码那一轮就跟着改，否则它会变成「看起来权威的错误答案」。**
这批数字过期了 22 轮，期间没有任何检查发现它 —— 因为数字长得像正常的数字。

★★ **重写比重构更能暴露问题。** 上一轮做「删重复」时只看结构，这轮按「现在是什么」重写，
才被迫逐项核对每一个数值，于是发现了整张表都错。**重构是整理，重写是校对。**

★ 顺手确认：`README.md` 里「两轮穿到满暴露时触发率约 40% / 76%」是算出来的
（上限 30 → (30−10)/50、上限 48 → (48−10)/50），不是抄的。
