# 第七十五轮：过关线 100 + 接受度逐轮手写

> 用户口径：「过关线修改为 100，请调整每题增加的怀疑值；我准备暂时不使用接受度全局累计，
> 改为每轮可用的暴露值不同；请帮我看看第一轮多少接受度能保证可以组合的服装足够多」。

## 一、怀疑度：线 60 → 100，一整组增量 ×2

起点 20 不动 → 预算 40 → 80，正好翻倍。所以整组按 ×2 重标，**换算后难度与旧版一致**。

| 项 | 旧 | 新 |
|---|---|---|
| `pass_suspicion` | 60 | **100** |
| `correct_delta` | −6 | **0**（负数本来就会被钳到 0） |
| `silence_delta` | 6 | 12 |
| `improvise_penalty` | 12 | 24 |
| `blind_made_up_delta` | 24 | 48 |
| `contradiction_penalty` | 35 | 70 |
| `expr_qte_fail` | 24 | 48 |
| `interference_fail_penalty` | 18 | 36 |
| `phone_pull_penalty` | 8 | 16 |
| `leak_delta` | 100 | **100（不翻倍）** |

性情（`DEFAULT_TRAITS` 的 bluff / evade）：多疑 45/12 → **90/24**、迟钝 6/10 → **12/20**、
精明 30/8 → 60/16、急躁 10/32 → 20/64、心软 18/6 → 36/12。

★ 三处同步：`ScenarioData.DEFAULT_RULES` / `DEFAULT_TRAITS`（兜底）、`data/story.json`（真正读的）、
`Interrogation.gd` 那批 `const`（`_rf()` 的第二参数）。

**等价性核对**（改完实测）：
- 多疑撒谎 90 → 20 + 90 = 110 → 死（旧 45：20 + 45 = 65 > 60 → 死）✔
- 全沉默 6 题：20 + 72 = 92 < 100 险过（旧 20 + 36 = 56 < 60 险过）✔
- 迟钝撒谎 12：六次 20 + 72 = 92 < 100 死不了（旧 6：20 + 36 = 56 < 60 死不了）✔

## 二、接受度：不再跨局累计，改成每轮手写

```gdscript
var acceptance: int:
    get: return acceptance_at(level_index)

func acceptance_at(li: int) -> int:
    # ① levels[li].acceptance 有值 → 直接用它
    # ② 没写 → START_ACCEPTANCE + 本局已通过那几轮的 acceptance_gain
```

- `levels[i].acceptance` 是新字段。它同时决定**能穿哪些**（`acceptance_req ≤ 接受度`）与
  **暴露上限 = `EXPOSURE_BASE(10) + 接受度 × 2`**。
- `ProfileData.total_gain` 还在记账（战绩面板），**不再影响任何数值**。
- 准备室「跨局保留 +N（失败也不会丢）」那句删了。
- `START_ACCEPTANCE` 14 → **10**（现在只是「某轮没写 acceptance」时的兜底）。
- 编辑器**两份字段表都要加**：`levelsFields()` 与 `bgSections()` 的 `levels.fields`。

## 三、第一轮给多少：实测 **10**

6 套背景 × 24 种子 = 144 个局面，用 `WardrobeModel.auto_complete_outfit()`（真实求解器）。

| 接受度 | 上限 | 可穿件数 | 可达反差 最差/中位 | 对 125 的余量 |
|---|---|---|---|---|
| 8 | 26 | 113 | 125 / 145 | **0（不能用）** |
| 9 | 28 | 125 | 135 / 155 | +10 |
| **10** | **30** | **132（封顶）** | **145 / 165** | **+20** |
| 11 | 32 | 132 | 155 / 175 | +30 |
| 12 | 34 | 132 | 160 / 185 | +35 |
| 14（旧） | 38 | 132 | 170 / 205 | +45 |

**10 = 可穿件数封顶那一档**（132/137，只剩 5 件 `req=15` 的极端款锁着）。
**8 = 下限**（零余量，塞一件强制装备就死局）。

第 2 轮保留 **19**（上限 48）：带强制装备（平均 0.75 件）时最差 155~170 → 余量 +5~+20；
压到 12（上限 34）最差只剩 160，而仓库标定最差是 155 → 再压会有人无解。

## 四、真 bug：多件槽位被写成字符串

`WardrobeTest._first_improving_move()` / `_packing_optimal()` 里原来写
`var cur := str(keep.get(slot, ""))` + `m.equipped[slot] = cur`。

纹身是**两件的 `Array`** → 第一次试探就被压成 `String` → 纹身整栏从所有计算里消失
（暴露少 4、反差少 20、门控也歪）。

- 为什么第 49 轮没发现：只有「上限卡得很紧」时才现形（旧上限下 DP 解早饱和）。
  第 1 轮上限 38 → 30 之后才冒出来。
- 修法：`_slot_ids(m, slot)` / `_restore_slot(m, slot, keep)` 两个助手，按 Array 还原。

## 六、踩坑清单

1. **假失败：继承到 100 上限**。`硬答恒定扣分` 断言「涨 48」，但前一段把怀疑度顶到 100 →
   48 被钳掉 → 差值 0。**凡断言「涨了 N 点」，先钉死基数**。
   同理「没带尼古喵尾」基数 40 → 10（40 + 70 撞上限）。
2. **逐背景探针会把「当前这一局」重开**（`start_new_run` 是全局单例）→ 后面
   `_test_editable_sections` 读本局背景的强制穿着规则，不还原就三条断言凭空变红。
   修法：进来时存 `seed_value` / `background_id` / `level_index`，出去时 `start_new_run` 还原。
3. **越界会静默吞断言**：`a_cards()[0]` 在空数组上越界 → 后面几条凭空消失，摘要照旧。
4. **CRLF**：本仓库 GDScript / JSON 是 LF，`tools/story_editor.html` 在 HEAD 里是 CRLF。
   用 Python 批量改文件时必须二进制模式统一换行，否则 `git diff` 变成上万行假差异。
