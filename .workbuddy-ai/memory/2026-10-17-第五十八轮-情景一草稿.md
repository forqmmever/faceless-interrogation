## 踩坑 / 注意

1. **草稿必然让校验面板多一条提醒**。`editor_smoke.js` 原来断言「出厂 0 提醒」，
   新增草稿后必须把这条提醒单独认下来（`draftWarns.length === 1`），
   不能直接把断言删掉 —— 那等于把「出厂 0 提醒」的守门人拆了。
2. **所有 `story.backgrounds.forEach` 的内容校验都要改成 `enabledBgs()`**（7b / 7f / 结局段），
   否则草稿的空 `facts` / 空 `endings` / 没有盲区题会刷一片假红。
3. **`bgQuestionsSource` 的「出厂四套都是 auto」也要只看已启用** —— 情景一是 `manual`。
4. **别把 `endings` 填成 `void`**：结局文案里有 `%s` / `%d` 占位符，
   填 `void` 在启用后会直接 `not all characters converted`。留空走 `DEFAULT_ENDINGS` 才是安全的。
5. **强制校服的 item id 必须是目录里真实存在的**：`top_school_navy` / `bottom_school_navy`
   是第二十四轮加的两件校服；改 id 前先查 `OutfitData`。
6. **`questions_source = "manual"` 是这套场景的关键**：docx 没有卡片与事实，
   不设 manual 的话这 15 道题会被当成「盲区题」（不挂卡不挂事实），判定会偷偷换成「按脾性选」。
7. **题目的 `note` 不是编辑器字段**（不显示、不能改），但它是保留原文结果说明的地方；
   搜索索引这轮才把它收进去。别把运行时该显示的文字写进 `note`。
8. 一次性插入脚本放在 `.workbuddy-ai/tmp/add_scene.py`（不进版本库）；story.json 的缩进与
   换行（tab + LF）是照着原文件拼的，**不要用 `json.dump` 整个重写**，否则全文件 diff。
