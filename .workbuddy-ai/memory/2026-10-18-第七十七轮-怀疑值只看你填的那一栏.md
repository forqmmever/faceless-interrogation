# 第 77 轮：怀疑值只看「你填的那一栏」（两套自行编辑的背景）

日期：2026-10-18
用户口径：「玩玩的关系和杜鹃之女的两套的怀疑值不要按回答类型设置，按我给怀疑值设置大小关系进行修改，
现在第二轮的接受值能满足所有衣服都能装备吗」

## 一、先确认「按类型算」还剩在哪儿

`_build_unified_options` 从第 56 轮起就是「选项自己写了 `suspicion` 就硬覆盖」，
所以绝大部分选项没问题。真正漏的有两类：

### 1）4 个选项压根没写数（留空 → 退回按类型算）

| 位置 | 台词 | 原来的算法 | 补成 |
|---|---|---|---|
| `scene_1 / s1_q1` 第 3 项 | 我是阳乃，我被他抓住了把柄 | `tone: leak` + `ending: leak` → `leak_delta` | 100 |
| `scene_1 / s1_q2` 第 2 项 | 听说你正好来采购桌游 | 同上 | 100 |
| `scene_1 / s1b_q7` 第 2 项 | 她说再见 | 连 `tone` 都没有 → `_` 分支 → `correct_delta` = 0 | 4 |
| `scene_1 / s1b_q7` 第 3 项 | 她说小心陈虎 | 同上 = 0 | 8 |

★ `s1b_q7` 那两句是**玩笑话**（`echo`：空太郎懒得理会这样的玩笑，扭头便走），
所以给的数比同题第 1 项（16，一条具体的假通知）小：4 / 8。
★ 没给它们补 `tone` —— `manual` 模式下编辑器**不显示** `tone` 栏（第 56 轮口径），
补了就是一条用户改不到、也看不见的字段。代价已经由 `suspicion` 决定，`tone` 只剩「反馈文案」的作用。

### 2）说漏嘴的结算把选项写的数整个盖掉（更隐蔽）

`_select_option` 里两条分支原来都是无条件加 `leak_delta`：

```gdscript
if ending == "leak":
    _add_suspicion(_rf("leak_delta", 100.0))   # 完全不看选项写了多少
```

于是 `scene_2 / s2_q1`（写了 20）与 `s2_q5`（写了 16）实际都按 100 结算 ——
**数据里写的大小关系在运行时被扔了**。

改法：

```gdscript
if ending == "leak":
    _add_suspicion(float(opt["delta"]))
```

`opt["delta"]` 在 `_build_unified_options` 的 `TONE_LEAK` 分支里就是
`float(d.get("suspicion", _rf("leak_delta", 100.0)))` —— 没写数的选项仍然等于 `leak_delta`，
所以**出厂四套那 16 个说漏嘴选项一个数都没变**（已用 `git show HEAD:data/story.json` 核对过）。

## 二、顺手抓到：12 道题的按钮显示同一句话

### 现象

`_build_unified_options` 里有一段收集：

```gdscript
for o in raw:
    match str(d.get("tone", "")):
        TONE_BLUFF: bluff_text = str(d.get("text", ""))   # ← 循环覆盖，留下的是**最后一个**
        TONE_EVADE: evade_text = str(d.get("text", ""))
var td := _trait_options(bluff_text, evade_text)
```

然后每个 bluff 选项都 `text = td["bluff_text"]` —— **整句被换成「这道题最后一个 bluff」的文本**。

出厂四套**每道题最多一个 bluff**（已统计：`{1: 10, 0: 6}` × 4 套），所以这个 bug 藏了 20 多轮；
自行编辑的背景里「三选一全是撒谎」很常见，一进盘问就露。

### 中招清单（用 HEAD 版本跑新断言得到，共 12 道）

- `scene_1`：`s1_q3` / `s1_q5` / `s1b_q1` / `s1b_q2` / `s1b_q4`
- `scene_2`：`s2_q2` / `s2b_q1` / `s2b_q2` / `s2b_q3` / `s2b_q4` / `s2b_q5` / `s2b_q6`

（每道题里显示的，都是该题**最后**一个 bluff 选项的那句话。）

### 修法

```gdscript
TONE_BLUFF:
    ...
    # 只补 ⚠ 前缀，文本用它自己那一句
    if td["bluff_danger"]:
        text = "⚠ " + text
```

`_trait_options("", "")` 的文案参数从此只有盲区题那条老路在用（`_build_blind_options` 每道题只有一个 bluff，安全）。

### 踩到的两个坑（都已写进注释）

**坑 1：`(d.get("options", []) or [])` 在 GDScript 里返回 bool。**
`or` 永远返回 bool，缺字段时给的是 `true` → `for x in true` 当场 `SCRIPT ERROR`，
而 **SCRIPT ERROR 不会让测试失败**：那一节断言整片静默消失，摘要照打「ALL TESTS PASSED」、
`Checks: 952`（和上一轮一模一样，正是「断言总数没变」这个信号暴露的）。
改用 `_arr_of(d, key)`。

**坑 2：验「按钮文本不重复」时比的是带「A. 」前缀的整串。**
按钮文本 = `letter + label`，`A. xxx` / `B. xxx` 天然不相等 → 把代码改回错的，断言照样 PASS。
改成先 `strip` 掉前缀（按 `ui.common.option_letters` 逐个下标取）再比，才抓到那 12 道。
