# 第六十九轮（续）：选项按钮的布局 bug —— 「第二局第一轮第四问」

## 一、用户报的现象

> 「现在还有选项显示不正常的情况 如第二局第一轮第四问」

「第二局」= 第二局游戏（背景随机抽的，出厂四套之一）；「第一轮第四问」= 第 4 道题。
四套正式背景的题库顺序都一样：**3 道 3 选项 + 3 道 4 选项** ——
所以「第一轮第四问」正好是**这一局第一次出现 4 个选项**的那道题。

## 二、根因

`_refresh_option_buttons()` 是**按钮池**：按需补齐、多余的隐藏。
第 4 个按钮是在「第一次遇到 4 选项题」这一刻才 `add_child` 的，**此时宽度还是 0**。
按钮开着 `autowrap_mode = AUTOWRAP_WORD_SMART`，而 `Button` 的**最小高度是按当前宽度算的**：

> 宽度 0 → 文本被当成「一个字一行」→ 最小高度 = 510
> （「（你什么也没说 —— 沉默着，没有接这个话头。）」约 25 字 × 20px）

这个错误的最小尺寸**之后没有任何东西触发重算**（只有 text 再变一次才会），于是：

| 现象 | 实测 |
|---|---|
| `opts_box` 高度 | **672**（应 208） |
| 第 4 个按钮高度 | **510**（应 46） |
| 「掏出手机」按钮底边 | **922** / 屏高 720（被挤出屏幕） |
| 等 227 帧会不会恢复 | **不会** |

★ 为什么前面 3 题没事：只有 3 个按钮时池子够用，不新建第 4 个，永远碰不到这条路径。
★ 为什么第 5、6 题（同样 4 选项）正常：按钮池已经有 4 个了，只改 text → 触发重算 → 46。

## 三、修法（三处）

```gdscript
# ① _make_option_button：高度只由文本决定，容器别拉伸它
b.custom_minimum_size = Vector2(0, OPTION_BTN_H)
b.size_flags_vertical = Control.SIZE_SHRINK_BEGIN

# ② _refresh_option_buttons：新建按钮时**先按容器宽度定尺寸，再写文本**
nb.size = Vector2(maxf(opts_box.size.x, OPTION_BTN_WIDTH_FALLBACK), OPTION_BTN_H)

# ③ 刷新末尾：让按钮按当前宽度重算一次最小高度
opts_box.update_minimum_size()
```

新增常量 `OPTION_BTN_H := 46.0` / `OPTION_BTN_WIDTH_FALLBACK := 320.0`。

## 四、测试与反向验证

`TestRunner._test_option_button_layout()`（协程，`await` 调用）：
从**一个按钮都没有**开始（`b.free()` + 清空池），先加载 3 选项题、再加载 4 选项题。

判据全用**相对量**，不写死像素 —— 第一次写死 154 / 208 直接假失败：

- headless 下按钮实测 **47** 高（字体行高，不是 46）；
- headless 的视口尺寸不可信（手机按钮底边报过 **10126**，屏高 720）。

最终 4 条：

1. 3 选项：选项区 ≤ `3×80 + 2×8`；
2. 4 选项：选项区 ≤ `4×80 + 3×8`；
3. 4 选项：每个按钮 ≤ 80 高；
4. **最高与最矮的按钮差 ≤ 2** ← 这条是 bug 的指纹（坏的时候只有第 4 个是 510，前三个 46）。

★ 反向验证：撤掉修复重跑，4 条全红（按钮最高 **1061**、选项区 **1226**），恢复后全绿。

## 五点五、顺带修好截图脚本两个坑（22 号「前后矛盾」）

重拍时发现 22 号拍的是一张「题目还在、什么都没发生」的图。两个独立原因叠在一起：

1. **三道闸只复位了一半**：`_select_option()` 开头是
   `if _ended or interference_active or _options_locked_by_qte: return`。
   这一屏只复位了 `_ended` / `_running` / QTE，**没复位** `interference_active`
   与第 67 轮新加的 `_options_locked_by_qte`。
2. **异步定时器（更隐蔽）**：上一屏答完题会走 `_after_answer()` → `_next_question_delay()`，
   而后者是 `await create_timer(1.8)` 再 `_load_question(idx + 1)`。
   这个定时器**不受 `set_process(false)` 影响**，会在本屏加载完第 0 题之后才到点，
   把题推成第 1 题（同行者题）→ 说法题的选项找不着（下标 -1）→ `_select_option` 直接 return。

诊断路径：打印 `rf / 题目 id / current_question_index / current_options 的 kind`，
看到 `current_question_index=1`（刚加载完是 0）才锁定是异步定时器。

修法：复位三道闸 + 加载前 `await _wait(120)`（2 秒）让旧定时器过期。

## 六、顺带确认的事

`scene_1` / `scene_2`（用户自己做的两套）在 `story.json` 里是 `enabled: false`（草稿），
所以 `background_ids()` 只有 4 套正式背景 —— **游戏里抽不到那两套**，不是 bug。
（用户报的「第二局」抽到的必然是四套之一。）

## 七、教训

★ **新增「按需创建」的控件时，先问一句「它的最小尺寸依赖什么」**：
依赖宽度的（autowrap / 自适应文本）控件，在**宽度为 0 的那一刻**算出来的最小尺寸是废的，
而且不会自己修正。做法：`add_child` 后**先给尺寸、再写内容**。

★ **布局类断言一律用相对量**：绝对像素会被字体行高 / headless 视口坑成假失败。
「最高与最矮差多少」这类**形状判据**比「等于多少」稳，而且恰好是 bug 的指纹。
