# 第三十九轮：新增「妙妙工具」一栏（尼古喵尾）+ 引入平坦贞操笼

日期：2026-10-15

## 用户口径（原话）

> 「引入 back，在服装最下面新增一栏名称为妙妙工具，此栏专门为减少换装环节难度的设置的，
> 只能手动装备，调试计算反差值时请不要使用，引入的物品名称设定为尼古喵尾，
> 介绍为喵什么错都没有，效果装备时，无论选择什么选项都不会提高怀疑值，
> 但是触发游戏结束的选项依然会使游戏结束，引入平坦贞操笼放在下内衣，暴露度取最高」

## 一、「引入 back」是什么意思

AU 图包 `clothes/back/` 里**只有一样东西**：`fox tail butt plug`（挂在身后的尾巴）。
项目以前从没接过这一层。这就是尼古喵尾的贴图来源。

源图 `back.png`：512×256，左列（全身像）bbox `36,40-116,107`，
**灰度蒙版**（实测平均饱和度 0.00）→ 必须 tint 上色。用新色 `FUR_FOX = (0.66,0.38,0.19)`。

## 二、`MANUAL_SLOTS` —— 一张与 `DISABLED_SLOTS` 语义**相反**的表

这是本轮最核心的设计。用户要的「只能手动装备 + 调试计算反差值时不要使用」，
本质是「玩家看得见、点得到，但系统从不代劳」—— 这和「下架」是两件不同的事：

| 表 | 玩家看得见 | 能手动穿 | 原貌 | 情报 | 相册 | 强制池 | 一键达标 | 数值统计 |
|---|---|---|---|---|---|---|---|---|
| `DISABLED_SLOTS` | 否 | 否 | 不抽 | 不问 | 不拍 | 不进 | 不动 | 不算 |
| `MANUAL_SLOTS` | **是** | **是** | 不抽 | 不问 | 不拍 | 不进 | **不动** | **不算** |

落地方式：新增 `OutfitData.auto_slots()` = `active_slots()` 去掉 `MANUAL_SLOTS`，
然后把**所有**「原貌 / 情报 / 相册 / 强制池 / 一键达标 / 一致数统计」的口径切过去：

```
RunData._roll_true_appearance / _build_clues / _roll_photos
IntelDesk._fill_revealed / sync
WardrobeModel.matching_slots / changed_slots / resemblance / auto_complete_outfit
OutfitData.forced_pool / gate_dependents
```

★ **`active_slots()` 的语义保持不变（界面可见槽位）** —— 换装界面要用它，
必须能看见妙妙工具那一栏。这是两套口径并存的原因，别把它们合并。

## 三、怀疑值免疫：致命判据用规则值，不用写死的 100

```gdscript
if GameData.carried_tool(TOOL_TAIL_ID) \
        and amount < _rf("leak_delta", 100.0):
    return
```

- 用 `leak_delta`（规则值，默认 100）而不是硬编码 100 → 编辑器改这个数时自动跟上
- 也不用「选项的 kind」判 —— 因为 `_add_suspicion()` 拿不到选项上下文，
  而**数值本身**就足够说明问题：leak 那条路的增量天生就是 `leak_delta`（一次顶满）
- 携带状态：`GameData.carried_tools`（新增），由 `Wardrobe.sync_outfit_verdict()` 写入，
  存**实体件 id**（空件不算）；`reset_level_state()` 会清空（换关要重新确认）

## 四、平坦贞操笼「暴露度取最高」怎么落地

先实测 `panties` 现有 12 件的暴露值分布 → 最高档是 **9**（5 件并列），空件是 8。
所以 `panties_flatcage` 取 9。

★ 测试里写成「== 该栏最高值」（`_max_exposure_of("panties")`）而不是写死 9 ——
将来这一栏加了 10 档，断言会自己报警。

★ 贴图：`genitals/flatchastitycage/full.png`。第三十八轮清点时已实测
**四态（full/torn/tattered/frayed）内容完全相同**（MD5 一致），只取 full 即可。
位置天然对齐（左列 bbox `91,89-118,101` vs `gstring` 的 `88,84-121,106`），
**不需要 align 搬移**。

## 五、踩到的坑

1. **`var none_id := data.bare_id_of(s)` 编译不过** —— `data` 是 `Node` 类型，
   返回值类型推不出来。改成 `var none_id: String = str(...)`。
2. **口径不一致（假数字）**：`peek_hint` 的分子走 `matching_slots()`（已切 auto_slots）、
   分母还是 `active_slots()` → 会印出「13 / 14 处仍一致」。
   **凡是「N / M」的显示，分子分母必须来自同一个集合**。
3. **测试里一批断言把 `active_slots()` 当「参与原貌的槽位数」**（共 20+ 处）——
   新增 manual 槽位后全挂。修法是按语义分成两类改：
   - 原貌 / 情报 / 一致数 / 候选池覆盖 → `auto_slots()`
   - 界面卡片数 / 默认装备 / equipped 数量 → 保持 `active_slots()`
4. **`_every_slot_has_default` / `_defaults_resolve`** 遍历 `SLOT_ORDER`（含下架的）——
   manual 槽位不在 `TRUE_APPEARANCE` 里，要单独跳过（它的默认值由
   `_equip_defaults()` 走 `bare_id_of()` 铺）。
5. **编辑器校验器要求所有 SLOTS 都写 `clue_frame` / `clue_sources`** ——
   妙妙工具不进情报，要求它写是错的。改成用 `catalog.manual_slots` 过滤。
6. **heredoc 又吞转义**（`\n` / `\t` 被吃掉，脚本 5 处全部「未命中」）——
   项目笔记里早写过这条规矩，又忘了。带反斜杠的脚本一律用 Write 写成文件再跑。

## 六、z 值怎么定

两套表要给同一个位次：

- `OutfitData.SLOT_ZORDER["tool"] = 196` —— WTS 参考值域里，`bottom` 191 与 `top` 211 之间
- `dol_map.SLOT_Z["tool"] = 92.0` —— 烘焙值域里，`bottom` 90 与 `top` 95 之间

理由：挂在身后的尾巴从腰后翘出来，压在下装之上、上装之下最自然。
