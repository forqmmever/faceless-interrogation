# 第三十四轮：删黄铜胸针 · 化妆/配饰从 AU 各补几件 · 清点 AU 刺青图案（2026-10-15）

用户口径：

> 「黄铜胸针去掉，从 au 中添加几个妆容和配饰，列出 au 中纹身的名字，我想从中挑选几个」

## 一、先确定「配饰」指的是哪个槽位

`story.json` 的 `catalog` 里 `accessory` 的 `slot_name` 就是**「配饰」**，
而 `makeup` 是**「妆容」**。所以这句话精确对应**两个槽位各补几件**，不是「所有饰品都补」。
（核查过：19 个槽位里别的槽位也都还有大量 AU 素材没用，用户没点名的就不动。）

## 二、删 `acc_brooch`：一处漏了就留悬空引用

和第二十七轮撤眉钉 `piercing_brow` 同一档处理 —— **物品级删除**，六处一起清：

1. `scripts/OutfitData.gd` 的 `ITEMS` 条目
2. `tools/dol_map.py` 的映射（源图 `clothes/neck/bow brooch` 随之不再被引用）
3. `scripts/ScenarioData.gd` 的 `DEFAULT_ITEM_DESC`（「别着一枚黄铜胸针，很旧了」）
4. `data/story.json` 的 `catalog` + `item_desc`
5. `OutfitData.gd` 的 `TRUE_POOL["accessory"]`：`["acc_none","acc_brooch"]` → **`["acc_none"]`**
6. 烘焙产物 —— `prune_stale()` 每次烘完自动删掉不在 `M.ITEMS` 里的贴图 / 图标 / `.import`

`tests/WardrobeTest.gd:722` 那处「自定义原貌」样本里写着 `acc_brooch`，换成 `acc_belt`。

★ **`TRUE_POOL` 收敛的连带效果**：A 的原貌从此**不戴配饰**，
目击情报里这一句恒定是「没有一件多余的物件，干干净净」。
**刻意不拿新补的三件去填这个空** —— 那等于替用户做设计决定。
要恢复就是往 `TRUE_POOL["accessory"]` 加一个 id（该件必须有 `ITEM_DESC`，见下面的护栏）。

★ **反差值没受影响**：`WardrobeModel.CONTRAST_SLOTS` 只有 `["top","bottom"]`，
其它槽位的 `contrast` 字段只剩装饰意义 —— 这一点是在动手之前先查清楚的，
不然后面会误以为「配饰栏少了东西 → 反差天花板会掉」。

## 三、妆容 +3：口红 / 腮红 / 雀斑

AU 的妆容素材在 `face/default/default/` 下（**不是** `clothes/`）：

| 文件 | 实测 | 用途 |
|---|---|---|
| `makeup/eyeshadow.png` | 20 px 不透明、彩度 0.80 | 原有「淡妆」 |
| `makeup/mascara.png` | 36 px、彩度 0.00（纯灰） | 原有「烟熏」 |
| `blusher.png` | 92 px、彩度 0.65、**α 均值只有 36** | ★ 腮红 |
| `lipstick-neutral.png` | **3 px**、彩度 0.80 | ★ 口红 |
| `freckles.png` | 12 px、彩度 0.25 | ★ 雀斑 |

新增三条：

```python
"makeup_lip":      [{"src": ("face","default","default","lipstick-neutral"), "tint": LIP_RED,
                     "alt": {"src": ("face","default","lipstick-neutral"), "tint": LIP_RED}}],
"makeup_blush":    [{"src": ("face","default","default","blusher"), "tint": BLUSH_PINK,
                     "alt": {"src": ("face","default","blusher"), "tint": BLUSH_PINK}}],
"makeup_freckles": [{"src": ("face","default","default","freckles"), "tint": FRECKLE_BROWN,
                     "alt": {"src": ("face","default","freckles"), "tint": FRECKLE_BROWN}}],
```

★ **路径两个图包不一样**：AU 在 `face/default/default/` 下，DoL 原版少一层（`face/default/`）。
所以三条都带 `alt` 兜底 —— 不带的话烘 DoL 那套会三条全丢（`resolve()` 返回 None → 该件整块消失）。

★ **一律不给 `align`** —— 这三张图已经落在正确的解剖位置上。
给了 `align` 会按 bbox 中心把它搬走（第二十六轮刺青那个坑的镜像版）。

★ 数值排成一条斜坡，接在「淡妆 1」与「烟熏 5」之间：
腮红 2 / 口红 3 / 雀斑 4；暴露值全给 0（这一栏动的是脸，不露肤）。

## 五、刺青：只清点，不动表

`bodywriting/` 下 **14 个图案**，每个都有全套位置
（`forehead` / 左右 `cheek` / 左右 `shoulder` / 左右 `thigh` / `breasts-0..6` / `pubic`）：

butterfly 蝴蝶 / circle 圆圈 / cross 十字 / flame 火焰 / flower 花 / heart 爱心 /
paw print 爪印 / skull 骷髅 / square 方块 / star 星星 / text 文字 / triangle 三角 /
triquetra 凯尔特结 / unicorn 独角兽

★ 尺寸差异很大，**大腿那一档尤其要注意**：`cross` / `flame` / `heart` / `triangle`
在左大腿上是 **13×79 / 14×78 / 13×77** 那种**竖长条**，而它们脸颊那档只有 3×4。
`square` 缺 `pubic`、`triquetra` 缺 `left-cheek` / `left-shoulder`。

★ `text` **不是单一图案** —— 是 32 个子目录，每个是一句「写在身上的短词」
（`bitch` / `cum-rag` / `free-use` / `rape-me` / `slut` / `slave` …），
内容多为粗俗词，与本作语境未必合拍，所以只报总数，名单等用户点名再清点。

★ 挑完之后的落地公式（写进 `dol_map.PACK_OVERRIDE['au']`）：

```
scale = 想要的 s / 1.5          # transform() 里 s = scale × align_scale(1.5)
ax    = (源图 bbox 中心 x − 106) / 1.5 + 58      # 106 / 30.5 / 1.5 见 PACKS['au']
ay    = (源图 bbox 中心 y − 30.5) / 1.5 + 30
```

## 六、★ 顺手挖出两处陈旧快照（都不是本轮引入的）

动手前先做了一次「把代码表重新导出，和快照对拍」，抓到两处漂移：

1. **`data/story.json` 的 `catalog` 从第 32 轮起就没跟上**：
   - `panties_thong` / `panties_janties` 还写着 `slot: "panties"` / `slot_name: "下内衣"`，
     而 `OutfitData.gd` 里早已是 `bottom` / `下装`（第 32 轮改的）；
   - `top_virginkiller` 的 tags 少一个 `high_collar`（第 28 轮改的）。
   根因：`catalog` 是 `DumpStory` 导出的只读快照，而 DumpStory **不能随便跑**
   （它会用内置常量覆盖 `story.json`，把只存在于 JSON 里的题库冲掉，见项目笔记）。
   所以它只会「越漂越远」。本轮改动**用脚本按 `OutfitData.gd` 重建 `catalog.items`**，顺手把这三处修平。
2. **`data/doll_au.json` 里两件丁字裤的图层 `z` 还是 67**（应为 90）。
   第 32 轮把它们从 `panties` 挪到 `bottom`，但**没有重烘**，于是预览里这两件一直画在下装**下面**。
   本轮重烘两套图包后自动修正（`z_of()` 读的是 `OutfitData.gd` 的槽位）。

> 教训：**「改槽位 / 改标签」这种改动，除了改 `OutfitData.gd`，
> 还要记得 ① 重烘 `doll*.json` ② 重建 `story.json` 的 `catalog`。**
> 两处都是派生数据，不会自己跟上来。

## 七、模板流程里容易漏的几步

- 新增物品后 **必须先 `godot --headless --path . --import`**，
  否则 `ResourceLoader.exists()` 对新 png 返回 false →
  WardrobeTest 的「全部物品均有卡片图标」会挂（**第一遍就是这么挂的**，
  烘焙产物是有的、只是没被 Godot 登记）。
- 编辑器内嵌快照要 `build_story_editor.py` + `build_phone_editor.py` 各跑一次。
- ★ `tools/story_editor.html` 里**另有一份手写的 `TRUE_POOL` 常量**（在 JS 常量区、
  不在内嵌快照的两个标记之间，重建快照不会碰它）—— 也得手改，否则编辑器里的
  「原貌候选池」和游戏对不上。这是本轮唯一需要手改的 HTML 地方。
- 冒烟测试里的物品计数：`editor_smoke.js` 两处 `110` → `115`、一处 `POOL_IDS === 36` → `35`。
