# 第七十四轮：编辑器不再为「空文案」报警，界面也不留空行

日期：2026-10-18

## 一、用户口径

> 「将现在编辑器中提醒会退回出厂文案和界面上会留下空白的地方全部去掉，不再需要填入文字，
> 提示会退回出厂模板那一句的地方不用管」

问过两句之后确认的范围：

| 问题 | 选择 |
|---|---|
| 那 4 条「是空的 —— 界面上会留一块空白」怎么处理 | **只去掉提醒，字段留着**（空着不报警、也不用填；游戏里空标签自己收起） |
| 「会退回出厂文案」这一类提醒要不要一起删 | **一起删掉**（这些键都有出厂兜底，空着也能跑） |

## 二、改之前的状态

编辑器一打开就是 **0 错误 / 6 条提醒**，其中 4 条是同一类：

```
界面文案 · 开始界面 / 选关面板 · 标题下的一句副标 是空的 —— 界面上会留一块空白
界面文案 · 阶段二 · 盘问界面 · 掏太多次被发现的提示 是空的 —— 界面上会留一块空白
界面文案 · 玩法说明的正文 · 准备室 · 副标题 是空的 —— 界面上会留一块空白
界面文案 · 玩法说明的正文 · 盘问 · 副标题 是空的 —— 界面上会留一块空白
```

（另 2 条是两套草稿的「还是草稿」，按设计保留。）

★ 这 4 句是**用户自己清空的**（第六十七轮为此在冒烟里开了个 `userEmptyWarns` 豁免）。
第六十七轮的处理是「容忍提醒」，这轮用户明确要求「把提醒本身去掉」——
**同一个现象，先容忍、后根治**，说明这类「提醒只是噪音」的判断该早点做。

## 三、删了哪几条规则（`tools/story_editor.html` 的校验器）

| 原规则 | 处理 |
|---|---|
| 界面文案**缺键** → 「会用出厂文案」 | **删**（缺键 = 用出厂那句，不是问题） |
| 界面文案**空串** → 「界面上会留一块空白」 | **删** |
| 手机某栏**空着** → 「会退回出厂文案」 | **删**（改成「只有带占位符的空着才算错」） |
| 占位符个数对不上 → 「…游戏会退回出厂文案」 | **保留这条错**，只把尾句改成「这句话会拼不出来」（不再提「退回出厂文案」） |
| 缺整块 `phone` 段 → 「手机会全部退回出厂文案」 | **保留**（结构问题），尾句改成「手机页整块缺失」 |
| 结局文案空着 → 「会退回出厂模板那一句」 | **不动** —— 用户说「那一句的地方不用管」 |

### ★ 为什么「带占位符的空着」还必须报错

`_ut(...)` 拿到空串之后，调用点还会 `% int(...)`。Godot 里 `"" % [8]` 会直接
**报 "not all arguments converted"** —— 那是运行时崩，不是「少一句话」。
所以这条留着，措辞改成「这句带占位符，空着游戏拼参数时会崩」，比原来那句更说清后果。

## 四、界面侧：空标签自己收起

`title.subtitle`（开始界面副标）原来是个 `Label`，清空后**仍占一行**——
截图里标题下面那条空白就是它。现在：

```gdscript
sub.visible = sub.text.strip_edges() != ""
```

`VBoxContainer` 会跳过隐藏子节点，所以那一行连同 `separation` 一起消失。
（另外两句 `help.*_sub` 是 `draw_string` 画的，空串本来就不画；`phone_caught` 空着就是
不写反馈区，第七十一轮的「怀疑度 +N」会补上。）

### ★★ `20_leak_exposed` 一度「时对时错」：`SceneTreeTimer` 抢跑

同一份代码两次渲染，一张「潜伏失败 · 身份暴露」、一张「题目还在、什么都没发生」
（怀疑度停在 60、`_ended = false`）。日志里明明写着
「说漏嘴用的题：q_a_brand（第 4 题，选项 0 = leak）」。

排查顺序（值得照抄）：

1. **先怀疑自己的改动** → `git stash push -- scripts/Main.gd` 退回 HEAD 重跑
   → **结果一样（60 / false）**，立刻排除本轮改动，省下大量时间。
2. 加一行临时探针打印 `_ended / interference_active / _options_locked_by_qte /
   current_options.size() / current_question_index` →
   `ended=false intf=false qte_lock=false opts=4 idx=5/6`。
   **四个守卫全过、选项 4 个、但题号是 5 而不是 4** —— 一眼定案。

根因：上一屏答完题会走 `_after_answer()` → `_next_question_delay()`，
而后者是 `await get_tree().create_timer(1.8).timeout` 再 `_load_question(idx + 1)`。
**`SceneTreeTimer` 不受 `set_process(false)` 影响**，所以本屏 `_load_question(4)`
之后它才到点，把题推成第 5 题 → 选项 0 根本不是「说漏嘴」。
（第 69 轮第 22 步踩过同一个坑，注释就写在那儿，这次是另一屏。）

修法（`tests/Screenshot.gd` 第 20 步）：

```gdscript
interro._options_locked_by_qte = false   # 别指望上一屏收干净
interro.set_process(false)
await _wait(120)                         # 先让 1.8 秒的定时器过期
interro._load_question(a_idx)
_plog("     实际加载到第 %d 题（选项 %d 个）" % [        # 落地核对，下次抢跑会当场说出来
    interro.current_question_index, interro.current_options.size()])
```

修完：`怀疑度 100.0 ｜ 已收场 = true ｜ 收场原因 = gameover`，
`20_leak_exposed.png` 与提交版**逐像素一致（0.00%）**。

## 七、经验

1. **「提醒」也要有归属**：一条提醒如果出厂数据必然触发，它就不是提醒而是噪音 ——
   要么改数据、要么删规则，别长期用「豁免」压着（第六十七轮的教训）。
2. **空文案分两种**：**不带占位符**的空 = 不显示（合法）；**带占位符**的空 = 运行时崩（必须拦）。
   校验器要按这个分，不要一刀切。
3. ★★ **截图「时对时错」先查异步，再查渲染**：`set_process(false)` 只停 `_process`，
   **停不住 `await create_timer()`**。凡是「上一屏答过题、下一屏直接 `_load_question()`」的地方，
   中间都要垫一个 `await _wait(120)`。（第 69 轮第 22 步、本轮第 20 步，同一个坑两次。）
4. ★ **先 `git stash` 退回 HEAD 重跑一遍**，能一秒判定「是不是这轮改出来的」。
   本轮就是靠这一步把「20 号图变了」从「本轮回归」摘出去，最后发现是脚本老坑。
