# 第八十一轮（2026-10-19）：结局文案「不写不用」· 回应搬到题面之上

用户口径两条：
1. 「结局文案中所有的部分不写默认不使用」
2. 「接在下一题题面前的回应的大小字体与题面一致、颜色使用淡蓝色，下一题的题面应该出现在回应后面，调整回应的出现的位置」

## 一、结局文案：拆掉两层兜底

改之前有三层「帮你补上」，所以「没写」和「写了」在界面上一样：

| 层 | 旧行为 | 现在 |
|---|---|---|
| `_fill_endings()` | 每套背景都 `_merge_flat(DEFAULT_ENDINGS, bg.endings)` 逐键补齐 | 从文件读的一律 `_fill_endings(false)`：只补一个空 `{}`，不填模板 |
| `ScenarioData.endings_of()` | 同上再补一次 | 原样返回字典 |
| `end_t(key, dflt)` | 调用点还带一句出厂文案 | **去掉 dflt 参数**，没有就是 `""` |

`_fill_endings(true)`（填默认）现在只剩「根本没有 story.json」那条演示兜底路径。

★ 关键细节：`_fill_endings(false)` 要给「从文件读、但这套没写 endings」的背景补一个
**空字典 `{}`**。否则 `endings_of()` 会把「没有这个键」判成「内置常量」，
又退回 `DEFAULT_ENDINGS` —— 那就等于没改。

界面上的「空」：
- 标题 / 正文 / 提示 → `visible = false`，整块收起（`_show_overlay` 与 `_show_result`）；
- 按钮标签 → 只显示箭头（`➔` / `↺`）。**用户确认过这个方案**：按钮是唯一前进手段，
  不能变成空白块；
- `exposure_reason_*` → `_add_reason()` 跳过空串，不留空行。

调用点写法：`_et(key)` / `_etf(key, args)`（空串直接返回空串，不拿参数去格式化）。
`_etf` 是这一轮新加的，两侧（`Interrogation` / `Main`）各一份。

## 二、回应搬到题面之上

`echo_label` 插在 `dialogue_label` **之前**：

```
echo_label      淡蓝 Color(0.62,0.80,0.98) = #9ECCFA，字号 15
dialogue_label  题面，字号 15，白
feedback_label  反馈区，字号 12，灰（从此只放判定解释）
bottom          掏出手机 + 选项
```

- 间距沿用 `vb.separation = 10`（用户选「常规 10px」）；
- 没写回应 / 第一题 → `visible = false`；
- `_show_choice_echo()` 同时清空 `feedback_label`；
- `start_interrogation()` 两处都清。

★ 探针实测：echo 索引 0 < 题面索引 1；字号 15 = 15；颜色 (0.62,0.8,0.98) vs (1,1,1)。

## 五、⚠ 第 80 轮造成的真实死局（不是本轮引入，但本轮才被跑出来）

`scene_1` 第 1 轮强制「藏青校服衬衫 + 藏青超短校服裙」之后：

- 手套槽位在 `DISABLED_SLOTS` 里（下架），手背刺青只能靠**长袖**遮；
- 校服衬衫是短袖 → 刺青露着；
- 上下装被锁死 → 反差只到 95，低于第 1 轮要求的 125。

120 个种子里 **6 个第 1 轮无解**。这是数据配置问题（引擎按作者写的规则执行），
三种调法写在 README 里，没有擅自改用户数据。

## 六、踩坑

- `%r` 不是 GDScript 的格式符（只认 `%s` / `%d` / `%f` / `%x` 等），
  探针里用了会 `unsupported format character` 并中断后面的输出。
- `--check-only --script` **不加载 autoload**，每个脚本都会报
  `Identifier not found: ScenarioData` —— 那不是语法错误，别被它骗。
- `load("res://scenes/Main.tscn").instantiate()` 的类型是 `Node`，不是 `Control`。
