# 第 54 轮：清掉编辑器打开时的 57 条提醒

用户口径一句：「打开编辑器后出现了57个提醒修复这些问题」。

---

## 一、★ 最重要的发现：27 条根本不是数据的问题，是校验器算错了

把 57 条全导出来（写了个临时探针复用 `editor_smoke.js` 的加载逻辑，打完就删），
按**性质**分类：

| 类别 | 条数 | 性质 |
|---|---|---|
| 「反差要求超过理论上界 —— 一定无解」 | 2 | ★ **公式用的是旧口径**（125/150 明明有解） |
| 「题目属于第 N 轮，而这一局只打 0 轮」 | 24 | ★ **轮数算成 0**（空 = 回落全局，但没回落） |
| 「最后一关还在给接受度 —— 给了也用不上」 | 1 | ★ **判据错**（它会进跨局账号） |
| 「没有自己的关卡表」+「levels 是空数组」 | 8 | 同一条规则报两遍，且出厂就是空的 |
| 「衣物描述里多了一条 XXX」 | 21 | 判据对，但逐条刷屏（出厂就有 21 条） |
| 「按轮覆写会让 A 逐轮变化 —— 这是设计意图」 | 1 | **设计说明**混进了**问题面板** |

★ **教训：看到「一大片提醒」时，先假设其中一部分是规则本身的 bug，逐条验证判据，
而不是急着去改数据。** 这次如果照 57 条去改数据，会把出厂的正确曲线（125/150）
改成「校验器觉得对」的错曲线。

### 三个算错的判据（都值得记）

**① 「理论上界」用的是第 49 轮之前的公式。**

```js
// ❌ 旧：按「每件衣服的 contrast 字段」逐槽位取 max 求和
cat.forEach(x => { if (x.contrast > best[x.slot]) best[x.slot] = x.contrast; });
```
第 49 轮把反差改成 `Σ|你穿的这件 − 原貌这件| × 倍率` 之后，**单件反差不再是一个固定值**
（取决于原貌那件穿的是什么），所以那个 `contrast` 字段与真实口径无关。
它算出的「上界 59 / 77」低于要求 125 / 150 → 把**有解**的曲线报成「一定无解」。

```js
// ✅ 新：只用两条事实推
//   ① |a − b| ≤ a + b  →  Σ|你 − 原貌| ≤ Σ你 + Σ原貌
//   ② 「你穿的暴露值合计」≤ 这一轮的暴露值上限 cap = 10 + 接受度 × 2
//   于是 反差 ≤ 倍率 × (cap + Σ原貌)，Σ原貌取「候选池每槽位最大暴露之和」
const upper = perExp * (cap + trueUpper);
```
★ 这个上界**安全但偏松** —— 它只拦「明显写飞了」的值，没超上界**不保证**有解。
文案也相应从「理论上界」改成「**宽松上界**」，别让用户以为它是一种保证。

**② 「这一局只打 N 轮」的 N 没做「空 = 回落全局」。**

```js
const n = bg.levels.length;                                    // ❌ 空数组 → n = 0
const n = bg.levels.length || (story.levels || []).length;      // ✅
```
出厂那四套背景的 `levels` 都是空的（第 52 轮起，轮次名改用全局的），
于是 `n = 0`，把每套 6 道题全报成「永远不会出现」= **24 条假警告**。

★ 这类 bug 的根源是**「空 = 回落」这个语义在代码里只实现了一半**：
运行时有回落（`OutfitData.bg_levels()` 空 → 用全局），但校验器直接读了原始字段。
**凡是「空表示继承」的字段，校验器里每一处读取都要走回落。**

**③ 「最后一关给接受度是白给」—— 判据错。**

通关那一步走的也是 `RunData.advance_level()`（`Main._on_overlay_pressed()` 的
`last_level` 分支），而它里面有 `ProfileData.add_gain(gain)` ——
接受度是**跨局保留**的，所以最后一轮给的照样进账号，下一局开局更宽松。

★ 写这条判据时只想了「同一条线里后面还有没有轮次」，忘了**接受度是账号级的**。

## 二、区分「问题」与「说明」—— 校验面板只放问题

那 21 条 `item_desc` 提醒的**判据是对的**（`item_desc` 只服务原貌的目击描述
`clue_text`，而原貌只从候选池 + 按轮钉死那几件里出，池外的确实用不到），
但它是**数据现状说明**（出厂就有 21 条），不是「你改坏了」。

处理方式：**给它做了一节内的提示，不进顶部面板**。

```js
// strmap 本来就有 missing 机制（列出「还缺哪些」）—— 加一个对称的 extra（「多出来哪些」）
const extra = spec.extra ? spec.extra() : [];
if (extra.length){ addRow.append(h("div", {class:"help"}, ...)); }
```

于是顶部面板 0 条，打开「📝 外貌情报 / 全局文本」页还能看到这 21 条。

★ **判断标准**：
- **问题**（用户能改坏的）→ 进顶部面板
- **说明**（出厂就这样 / 设计意图）→ 写在对应编辑节的 hint 里

同理删掉了「按轮覆写会让 A 逐轮变化 —— 这是设计意图，不是 bug」那条 ——
一句「这不是 bug」出现在问题面板里，本身就是误导。

## 三、★★ 加了一条守门断言：出厂数据下「0 错误 **且** 0 提醒」

以前的冒烟只断言 `errs.length === 0` —— 所以 **57 条假提醒能一直躺着没人管**。

```js
ok(warns.length === 0, "出厂数据下 0 条提醒（实际 " + warns.length + " 条）" + ...);
```

这是这次的**守门人**：以后谁再往校验器里加「出厂必然触发」的规则，冒烟立刻挂，
而不是等用户又看到一片红字。

★ 并且按项目规矩**验证了它真能抓到问题**：临时把第 1 轮反差要求改成 9999 →
冒烟报「出厂数据下 0 条提醒（实际 2 条）」+ 另两条 → 恢复后全绿。

### 「0 提醒」这条断言为什么值得加

它是**用户视角**的指标：用户打开编辑器，第一眼看到的就是那个面板。
面板一脏，真问题就被淹了 —— 这次 57 条里只有 21 条是「有信息量的」，
其余 36 条纯粹是噪声。**让面板常态为 0，是让它重新有信号的前提。**

## 四、★ 改 CRLF 文件：多行 old/new 必须先归一化行尾（第 52 轮 + 第 54 轮各踩一次）

`tools/story_editor.html` 是 **CRLF**。用 `open(P,'rb').read().decode('utf-8')` 读进来时
换行是 `\r\n`，而我写的多行 old 字符串里是 `\n` → **匹配不上**（`substring not found`）。

更阴的是：**如果匹配上了、但 new 里写的是 `\n`，就会写出「混合行尾」**。

所以固定下来这个 helper（本轮之后每次都照抄）：

```python
s = open(P, 'rb').read().decode('utf-8')
NL = '\r\n' if '\r\n' in s else '\n'      # 先探测

def N(t):
    """把任意行尾归一化成文件自己的行尾 —— 不做这步就会匹配不上或写出混合行尾"""
    return t.replace('\r\n', '\n').replace('\n', NL)

def cut(a, b, new, label):
    """把 [a 起点, b 终点] 这一段整体换成 new（比长串精确匹配稳得多）"""
    A, B = N(a), N(b)
    i = s.index(A); j = s.index(B, i) + len(B)
    global s
    s = s[:i] + N(new) + s[j:]
```

★ **写回后立刻验一遍**：
```python
b = s.encode('utf-8'); open(P,'wb').write(b)
crlf = b.count(b'\r\n'); lone = b.count(b'\n') - crlf
print('CRLF=%d 单独LF=%d %s' % (crlf, lone, '✓' if lone == 0 else '★ 混合行尾！'))
```

★ 另一个更稳的定位技巧：**先验证短锚点唯一**（`s.count(anchor) == 1`），
再用 `cut(起始锚点, 结束锚点, ...)` 做区间替换 —— 比一整段长字符串的精确匹配
对空白/换行差异的容忍度高得多。

## 五、临时探针的写法（把编辑器跑起来看内部状态）

要查「编辑器为什么报这些」时，最快的办法是**复用 `editor_smoke.js` 的加载逻辑**
写个一次性探针：DOM 桩 + 抽 seed + 抽主脚本 + `eval`，然后 `globalThis.__probe`
暴露 `issues` / `story` / 内部函数，跑完打出来。

```js
mainJs += `
;globalThis.__probe = {
  get issues(){ return issues; },
  loadStory, validateNow,
  get story(){ return story; },
  get index(){ return index; },
  bgSections, globalSections, POOL_IDS, TRUE_POOL,
};
`;
(0, eval)(mainJs);
```

★ 探针放 `tools/_probe_*.js`，**打完就删**（`_` 前缀 + 不进版本库的约定）。
