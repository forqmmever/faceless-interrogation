## 一、用户口径

两条一起下的：

> 「去掉表情 qte 同时出现的那个图片」

### ★ 为什么要拆 `with_thumb`

`_make_bar_overlay(fill, from_bottom, with_thumb)` 的第三个参数**只服务那张缩略图**：
它把 `margin_right` 从 170 改成 24（给图腾位置），还额外 new 一个 `TextureRect` 并
`host.set_meta("thumb", thumb)`。

功能一删，这个参数就是**没有编辑入口的死开关** —— 按项目规矩（第 83 轮定的：
「没有编辑入口的数据不许留」）必须一起拆。拆完签名回到
`_make_bar_overlay(fill: Color, from_bottom: int)`，`margin_right` 恒为 170。

`TestRunner` 里原来有 3 条「小图可见性」断言，换成 1 条反向守卫：

```gdscript
_check("★ QTE 条上不再挂下腹部缩略图",
    interro.qte_container.get_meta("thumb", null) == null)
```

## 三、删 9 件物品

### ★ 只有 `bra` 的上限被顶掉

删之前 `bra_tape` 是 `bra` 栏**唯一**的 9 档，删完最高只剩 8（`bra_latex`）——
`_max_exposure_of("bra")` 从 9 变 8，这会影响「暴露上限够不够用」的曲线。

`panties` 虽然删掉了 9 档的 `panties_flatcage`，但 `panties_gstring` / `panties_tieside`
两件也是 9 档，**上限没动** —— 所以曲线不用重标。

### ★★ `DumpStory` 不会删 `item_desc`

我从 `ScenarioData.ITEM_DESC` 删了 4 条刻字描述，导出后 `item_desc` 仍有 4 条残留 ——
因为 `story.json` 是权威源，`ScenarioData` 是从它**加载**的，不是反过来。

修法：`sed -i '4851,4854d' data/story.json`，然后断言
「`item_desc` 55 → 51、背景数 4、题目 39、`rules` 36 全部不变」。

## 六、踩坑

### ★★ dol_prepare 重烘 → 全部 png 显示为 M（纯压缩字节噪声）

跑完 `python tools/dol_prepare.py`，`git status` 里 **316 个 png** 全是 `M`。
逐张像素比对（Pillow `ImageChops.difference(...).getbbox()`）**全部是 None** ——
尺寸一样、像素一样，只有 PNG 压缩后的字节不同（Pillow 版本 / zlib 参数差异）。

处理：`git archive HEAD assets/dol_au | tar -x` 到临时目录，全量比对，把像素一致的
`git checkout --` 还原。提交里就只剩 36 个**真删除**。

★ 下次看到成片的 png 改动，先怀疑这个，别一张张看。

★ 顺带踩了个小坑：Python 写出来的文件在 Windows 上是 `\r\n`，
`tr '\n' '\0' | xargs -0 git checkout --` 会把 `\r` 带进路径 → `pathspec 'xxx.png?' did not match`。
先 `tr -d '\r'` 再处理。

### ★★ 截图拍不到「表情 QTE」那一屏

`Screenshot.gd` 第 19 步原来这么找题：

```gdscript
var a_idx := _find_question_index("A", 1)      # 找「挂 A 卡的题」
if a_idx < 0:
    a_idx = _goto_level_with_card_owner("A")    # 换一关再找
```

两套 `scene_*` 都是「自行编辑」模式，**一道挂卡的题都没有**；唯一有 A/B 卡的
`border_post` 是草稿（`enabled = false`）。两条路都返回 -1 → **整屏跳过**，
目录里留着的是第 78 轮那张**带下腹部小图**的旧图 —— 正好是本轮删掉的东西。

修法：加一条退路 —— 借**第 2 道普通题**（第 1 题固定不出 QTE），只为了拍 QTE 面板本身；
同时把「已出结果 / 怀疑度」复位（`_result_shown` / `_end_reason` / `suspicion_level` /
`_update_suspicion_ui()` / `result_hint.visible` / `result_btn.hide()`），
否则拍出来是「失败收场文字」叠着一条 QTE 条。

第 20 步「说漏嘴」**没有退路**（必须真有 A 卡才能把 A 的情报塞进 B 的档案）→ 仍然跳过。

★ 教训：**测试脚本里「找不到前置条件就跳过」的分支会静默产出过期截图**。
以后动数据导致某屏拍不到，日志里那句 `!! 跳过` 要当失败看待。

### sed 批量替换误伤新写的断言

把样本 id 从 `tattoo_slave` 换成 `tattoo_thigh` 时，`sed` 顺手把刚写的
「四件刻字纹身已按口径删除」断言里的 id 也换掉了 —— 变成断言「`tattoo_thigh` 不存在」，
必然 FAIL。手工改回。

★ 老规矩：**批量替换后 grep 一遍新写的断言**。
