# 第七十一轮：涨怀疑度的说明写在题面下面

## 一、用户口径

> 「所有增加怀疑度的说明 放在题面下面 如掏出手机后」

关键在「如掏出手机后」这半句 —— 掏手机越界原来是**唯一一处**「数值动了、题面下面却什么都不说」的地方。

## 二、原来的账：为什么掏手机没有说明

怀疑度上升有 6 条路：选项代价 / 掏手机越界 / 表情 QTE 失败 / 干扰没拦 / 前后矛盾 / 盲区硬答。

- 前 5 条各自有反馈文案（`_ut(...)` 拼一句写进 `feedback_label`），但**文案里不带数值**；
- 掏手机越界走 `_phone_pull_event()`，它写的文案是 `ui.interrogation.phone_caught`，
  而这条在 `data/story.json` 里是**空串**（`ScenarioData.DEFAULT_UI` 里其实有整句
  「（他把视线移开了两秒，又转回来。你听见自己的心跳。）」—— 被 story.json 的空串盖掉了）。
  于是题面下面的反馈区**一片空白**，玩家只看到手机面板通知条上飘了个 `+8`。

★ 教训：**「数据里是空串」和「代码里没有这句」是两回事**。查「为什么没显示」时
先 `grep` 数据文件，别只读脚本 —— 第 69 轮「自行编辑不加说话人名牌」也是同一个坑的亲戚。

## 三、做法：一处排队，本帧末统一追加

改 `Interrogation._add_suspicion()` 一个地方，**不动那 11 个调用点**：

```gdscript
func _add_suspicion(amount: float) -> void:
	var delta := maxf(0.0, amount)
	GameData.suspicion_level = clampf(GameData.suspicion_level + delta, 0.0, 100.0)
	_update_suspicion_ui()
	if delta > 0.0:
		_queue_delta_note(delta)
	if GameData.suspicion_level >= 100.0:
		_game_over()

var _pending_delta := 0.0
var _delta_flush_queued := false

func _queue_delta_note(d: float) -> void:
	_pending_delta += d
	if _delta_flush_queued:
		return
	_delta_flush_queued = true
	call_deferred("_flush_delta_note")

func _flush_delta_note() -> void:
	_delta_flush_queued = false
	var d := _pending_delta
	_pending_delta = 0.0
	if d <= 0.0 or _ended:
		return
	var note := _ut("interrogation.delta_note", "（怀疑度 +%d）") % int(round(d))
	var body := feedback_label.text.strip_edges()
	feedback_label.text = note if body == "" else feedback_label.text + "\n" + note
```

### 为什么必须 `call_deferred`（这轮最要紧的一条）

**各调用点的顺序不一样**：

- `_select_option()`：**先** `_add_suspicion(代价)`、**再** `feedback_label.text = ...` 写选项反馈
  → 当场拼会被后写的那句**整句盖掉**；
- `_phone_pull_event()`：也是先加后写；
- 干扰 / 矛盾那几处：有先有后。

排到**本帧末**统一追加，不管调用点在前在后都对。**这类「多个调用点顺序不一致」的场景，
不要在调用点里改顺序（11 处都得看），要改的是「什么时候写」。**

- 同一帧加好几笔（说漏嘴 + 收场）先**累加成一个数**再写，不刷屏；
- 已经收场（`_ended`）不写 —— 结果覆盖层会盖住反馈区，写了也看不见；
- 换题时 `_pending_delta = 0.0`（`_load_question()` 里紧跟 `feedback_label.text = ""`）——
  上一题的 `+N` 不能贴到新题上。

## 四、改一句界面文案的三处 + 编辑器

| 位置 | 内容 |
|---|---|
| `ScenarioData.DEFAULT_UI["interrogation"]` | `"delta_note": "（怀疑度 +%d）"` |
| `data/story.json` → `ui.interrogation` | 同上（**它优先**） |
| `Interrogation._flush_delta_note()` | `_ut(...)` 的默认值与 `%d` 个数 |
| `tools/story_editor.html` → `ui_interrogation` 段 | `A("delta_note", "涨怀疑度时接在反馈后面那句", 1, "带 1 个 %d：本次涨了多少", true)` |
| `tools/editor_smoke.js` | 文案条数 86 → 87、文案页覆盖 84 → 85 |

改完重建内嵌快照：`python tools/build_story_editor.py`（JSON 105291 → 页面 288991 字节）。

## 五、测试

新增 `_test_delta_note()`（7 条，协程），注册在 `_test_option_button_layout` 之后：

1. 涨 8 → 反馈区末尾有「（怀疑度 +8）」
2. 原来那句反馈还在（`begins_with`，不是被替换）
3. 怀疑度真的 +8（数值断言，不只看文案）
4. 反馈区为空时 → 只有「（怀疑度 +5）」
5. 照实答 `-6` 截成 0 → **不写**（`text == "照实答"`）
6. `_phone_pull_event()`（`phone_pulls = 2`，免罚 1 次）→ 有「（怀疑度 +8）」
7. 换题后不带上一题的 `+N`

★ 第 2 条是**防「覆盖」**的：只断言 `contains` 抓不到「原句被盖掉」。
★ 第 3 条是**防「只改文案不改数值」**的：文案绿了不等于逻辑对。
★ 协程里两次 `await get_tree().process_frame` —— `call_deferred` 在**本帧末**跑，
  一次 await 有时赶不上（帧末与帧首的边界），两次稳。

## 八、这轮暴露的通用经验

1. **「为什么没显示」先查数据文件**（空串会静默吃掉 DEFAULT）。
2. **多个调用点顺序不一致 → 改「写」的时机，不改调用点**。
3. **`contains` 断言抓不到覆盖**，要配 `begins_with` / `==`。
4. **文案断言要配数值断言**，否则「只改文案不改数值」也能全绿。
