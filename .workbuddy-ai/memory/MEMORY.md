## 二、改数据的几条链路

### ★★ 「逐轮」类字段有两份字段表，加字段必须加两处（第 72 轮）

`levelsFields()` 只给「🪜 关卡与轮数」页用（写 `story.levels`，**默认值**）；
「🎬 背景」页的「⑦ 本局覆写 · 几轮」是**另写的一份 `fields`**（写 `bg.levels[i]`，**游戏真正读的**）。
第 60 轮只加了前者 → 用户「依然无法在编辑器里编辑」一直到第 72 轮才修好。
以后加「逐轮」类字段（名字 / 数值 / 说明…）**两处都要加**，冒烟断言要盯**背景页**那份。
★ **标题写着「说明」不等于有说明字段** —— 排查「改不了」先数 `fields` 的键，别读标题。

### 改一句界面文案 → 同时找三处

① `ScenarioData.gd` 的 `DEFAULT_*`（json 缺失时的兜底）；② `data/story.json`（游戏**实际读的**，它优先）；③ `tests/*.gd` 的**期望值**。
★ **改了占位符数量 = 改了接口**（否则运行时 `not all characters converted`）。六处依次同步：`_tf(...)` 参数 → `DEFAULT_*` → `story.json` → **占位符守卫断言**（两处）→ 编辑器字段表 → `ui` 段的 `ph:true` 标记（第 50 轮漏了最后一处，冒烟连带挂两条）。
★ **`phone.*` 的文案字段分两处登记**：`PHONE_SEGS`（编辑器字段表）与 `PH_EXPECT`（该有几个占位符）。

### ★ 「为什么没显示」先查数据文件，别只读脚本

`story.json` 里的**空串**会静默盖掉 `DEFAULT_*` 的整句。第 71 轮「掏手机越界、题面下面一片空白」就是
`ui.interrogation.phone_caught` 被写成 `""`（`DEFAULT_UI` 里其实有整句）。
判据：文案不出现时**先 `grep` 数据文件**确认那个键是不是空串，再去读 `_ut(...)`。

### ★ story.json 两段整段替换，另三段逐键覆盖

`_item_desc` / `_backgrounds` / `_traits` / `_clue_frame` / `_clue_sources` / `_photo_notes` = **整段替换**（空字典被忽略）；`_rules` / `_ui` / `_phone` = **逐键覆盖**。
**后果**：改 GDScript 里那几段 `DEFAULT_*`，story.json 旧值会**整段盖掉** —— 光改常量没用。
**同步办法**：备份 → 目标段置空写回 → 跑 `DumpStory` → 对比备份（**备份独有的键**应恰好是这轮删掉的那些）→ 重建两个快照。
★ **`DumpStory` 不能无条件重跑**：`backgrounds[].questions[]` 里第 29 轮迁移的题目**只存在于 story.json**，重跑就全冲掉。只改 `rules` / `levels` / `true_presets` 这类段**不用重导**。

### ★ 派生数据不会自己跟上来

`OutfitData.gd` 是**唯一权威**，其余全是派生快照。改它的**槽位 / 标签 / 物品**时：

- `data/doll_au.json` 的图层 `z` → **重烘** `python tools/dol_prepare.py`（第 32 轮没重烘 → 预览里一直画错层）
- `data/story.json` 的 `catalog` → 重导；`tools/story_editor.html` 的 `TRUE_POOL` → **手改**（在 JS 常量区、**不在内嵌快照标记之间**）
- `screenshots/_flow_overview.png` → **重跑** `python tools/flow_overview.py`（不在四套验证里，**最容易漏**；图注表**写死了题数与手机次数**）。用带 PIL 的解释器 `.../envs/default/Scripts/python.exe`。

★ 改完权威表顺手问一句「**哪些地方抄了它**」——出厂数据一改，**编辑器冒烟的「出厂状态」断言要跟着改**。

### 加新物品的固定顺序

`改代码 → 烘图 → godot --headless --path . --import → 导出 story.json → 重建快照 → 跑测试`
漏 `--import` → WardrobeTest 报「每件物品都有卡片图标」挂；漏重建快照 → `editor_smoke.js` 报 catalog 件数旧值。
删物品靠烘焙脚本 `prune_stale()` 自动清产物。

### ★★ 加「会被随机抽到 / 会被测试遍历」的内容型数据 → 先想草稿标志（第 53 轮）

加之前先问两句：**① 半成品会不会被抽到？② 测试会不会遍历它？** 两个「会」→ 需要 `enabled`（草稿）标志，
否则「空壳」会崩游戏（随机抽到）或让一片断言红。**判断式 `b.get("enabled", true) != false`（缺省 = 启用）**。
★ 过滤只放在**产生新选择**的地方（抽局 / 列按钮 / 校验）；**按 id 取对象的地方不过滤**（存档里可能有后来被停用的背景）。详见 `REFERENCE.md`。

### ★★ 「自行编辑」模式（`questions_source = manual`）：编辑器收字段，运行时**三处**必须同步

背景不建档案卡与事实时，编辑器把用不到的字段**整节/整栏收起来**（数据一条不动）：
`MANUAL_HIDDEN_META`（`interrogator_gender` / `cover_role` / `true_role` / `true_name`）、
`MANUAL_HIDDEN_COMPANION`（`gender`）、③ 档案卡与 ④ 事实两整节、题目 `recall`、选项 `tone` / `value`。
★ **`interrogator`（称呼）不在此列** —— 用户明确「审讯官的名字不删」，顶栏 / 备忘录 / 短信联系人都在用。

运行时**三处必须一起改**，少一处就出怪事：
① `_is_unified_question()` 判据从「有 `tone`」放宽成「有 `tone` 或 `text`」（否则掉进旧「档案题」那条路，**完全不读你写的选项**）；
② `is_blind` 加 `and not RunData.questions_are_manual()`（否则整局变盲区题）；
③ 未知 / 空 `tone` 分支的 `delta` 取 `correct_delta`（原来只改 `kind`，`delta` 还是 0 = 不涨不跌）。
★ 判据放宽不会误伤旧格式：内置常量的题**根本没有 `options` 字段**。

## 三、测试怎么写（细则见 `REFERENCE.md` 五章）

- ★★ **编辑器校验面板只放「问题」，不放「说明」** —— 出厂数据必须 **0 错误且 0 提醒**（冒烟已断言守住）。「设计意图」「数据现状」写进对应编辑节的 hint 里。第 54 轮清掉 57 条，其中 **27 条是校验器自己算错**。**看到一大片提醒时先怀疑规则本身**。
- ★★ **跑完测试看三样**：`Failures: 0`、**有没有 `SCRIPT ERROR`**、**断言总数有没有莫名减少**。**越界 / 运行时报错不会让测试失败，只会让那一行静默消失**。改「轮数 / 槽位数」这类常量后要 grep 所有带下标的断言。
- **防「空转通过」**：读废弃数据段时循环一次都不进 → 断言全绿但什么都没测。**加「样本里确实查到 N 条」的断言**。
- ★ **写断言的四个老坑**（展开见 `REFERENCE.md` 五章）：① 只对部分对象生效的规则要配**对照断言**；
  ② 写完要**故意改回错的**验证它真能抓到 bug；③「存在性 / 非空」断言看不见「少做了一步」→ 要判**数值范围**，阈值用**实测**定；
  ④ 写「单调 / 递增」断言前**先把取样点数值写下来**（名字叫 low/mid/high 不代表递增）。
- ★★ **别让断言依赖「上一个测试留下的局」**（第 56 轮）：继承来的局是**随机种子** → 假失败，**同代码两次跑一挂一过**。要么自己开局，要么判据改成「相对量」。★ 出现「时好时坏」先怀疑**继承状态**。
- ★ **纯函数测试测不出「时间线上的 bug」** → 涉及「状态随轮次推进而变」的功能**必须再写一个走完整流程的探针**；判据：**测试里没出现两次以上状态推进，就测不到时间线**。探针要跑**真实链路**（`Main.tscn` 起场景）。
- **约束作用域是「整局」时测试也要走完整流程**（照片「开局 3 张 + 每轮 +2 张」）。
- **测试用完清跨局保留状态**：`ProfileData.add_gain()` 跨局保留 → 结尾必须 `reset_all()` + 注入的 `_*_presets` 清回 `{}`。### ★★ 截图「变了」怎么判（最容易误判的一节）

1. **先 `git stash` 退回 HEAD 重跑一遍**（三方对照：①提交版 ②HEAD 重拍 ③新代码重拍）。
   `③ vs ② = 0` 而 `① vs ② ≠ 0` → **仓库里那张是旧货**；`③ vs ② ≠ 0` 才是真变。
2. **「时对时错」先查这一屏状态有没有钉死，再查异步定时器**。状态清单：`_ended` / `_running` /
   `is_qte_active` / `interference_active` / `_options_locked_by_qte` / `interference_timer`。
3. ★★ **`set_process(false)` 停不住 `await create_timer()`**：上一屏答完题会走
   `_after_answer()` → `_next_question_delay()`（`await create_timer(1.8)` → `_load_question(idx+1)`），
   它会在本屏 `_load_question()` **之后**才到点，把题推成下一题 → 选的那项根本不是想拍的。
   **修法：先 `await _wait(120)` 让它过期，再 `_load_question()`**，并加一行「实际加载到第 N 题」
   的落地核对。（第 69 轮第 22 步、第 74 轮第 20 步，同一个坑两次。）
4. **判噪声**：① 同代码连跑三次完全一致 ② 差异稀疏点状 ③ `_plog` 逐字相同 → 三条同时成立 = 抗锯齿差异。
   ★ 相册 SubViewport / 带 shake / QTE 判负这些镜头**每次跑都不同** → 判据 = 「与旧版差异量级 ≈ 同代码两次跑量级」→ `git checkout --` **还原别提交**。
5. ★ **报「真变」要给机制上的量**（第 74 轮面板 487→455 = 一行 18px + separation 14），不能只说「看着不一样」。## 四、数值曲线的规矩（第 52 轮：一局 **2 轮**；展开见 `REFERENCE.md` 七章）

### 五条硬规矩（展开见 `REFERENCE.md`）

**① 凡「N / M」的显示，分子分母必须同一个集合**。**② 改「初始化顺序」前先 grep 谁依赖它**。
**③ 结构约束优于概率约束**。**④ 稳定随机用确定性哈希**，不能用 `RandomNumberGenerator`。**⑤ DP 去重的键用归一化字段**，不能用 `tags` / `gate` 原文。
