# 第四十三轮：相册改成「一段半身」+ 照片数量随轮次增长

日期：2026-10-15

## 用户口径（原话）

> 「相册里图片的照片只会出现眼镜，发型，上衣，下装，鞋子这五类，并且可能会同时出现，
> 如出现下半身时可以同时有下装和鞋子，但不能有头发眼镜，
> 上半身可以同时有眼镜发型上衣，但不能有鞋子，擦亮后应同时显示多个服装，
> 照片中的服装选取与原貌的暴露值相近的服装，发型与原貌保持一致，
> 照片数量每局开始时有三个，每轮增加两个」

澄清（AskUserQuestion）：
- 「相近」→ **差值最小（含原貌本身）**
- 擦亮揭示 → **照片里那件**（不是原貌那件）
- 每轮 +2 → **累加保留**

## 一、结构性改动：照片从「一处特写」变成「一段身体」

| | 以前 | 现在 |
|---|---|---|
| 一类照片 = | 一个槽位 | 一段半身 |
| 一张照片几件 | 1 件 | 1~N 件（随机子集，至少 1 件） |
| 可能出现的槽位 | 13 类 | **5 类** |
| 取景框 | 按槽位裁特写 | `PHOTO_FOCUS_HALF` |
| 数量 | 固定 5 张 | 开局 3 + 每轮 2（累加） |

## 二、两组不混是**结构保证**，不是概率

```gdscript
const PHOTO_UPPER := ["glasses", "hair", "top"]
const PHOTO_LOWER := ["bottom", "shoes"]
```

抽到上半身就只从上面那组取、抽到下半身就只从下面那组取。
所以「下半身不会出现头发/眼镜」「上半身不会出现鞋子」在**结构上**成立。

★ 测试对 12 个种子的每一张**逐项**核对（不属于对面那组、不越界、槽位合法……）。

## 三、每件怎么选

取「暴露值与原貌**最接近**」的（并列随机，**含原貌**）。
**发型例外**：直接是原貌那件。

★ **实测观察**：原貌池里同暴露值的件少（hair 全 e0、shoes 只一件），
  「差值最小」**经常直接命中原貌**（差 0 最小）→ 照片实际更像「直接证据」而非「模糊暗示」。
  这是选项本身的结果（用户选的就是「差值最小且含原貌」），不是实现偏差。

## 四、★ 已还原的语义没被照片带偏

照片里那件**不一定**是原貌 → 「擦亮照片 = 白捡一处还原」这条老规则不能照搬。

`_wipe()` 现在只在**真拍到原貌**（`is_true`）时才 `slot_revealed.emit()`：
- 拍到原貌 → 该槽位算已还原（准备室「?」消失）
- 只拍到同档位的别的件 → **不算还原**（仍是个「?」）

这样「已还原」始终意味着「你确实见到了 A 在那个部位的样子」。
`is_true` 与「显示的是不是原貌那件」的一致性也进了测试。

## 五、★ 文案拆三段 —— 连带改了两处「占位符守卫」

一张照片多件后，`album.cleared` 从 2 个占位符变 1 个，拆成：

| 键 | 作用 |
|---|---|
| `album.cleared` | 前缀（%s = 拼好的清单） |
| `album.piece` | 每件格式（`%s→「%s」`） |
| `album.list_sep` | 分隔符 |

★ 连带要改的地方（**这类改动最容易漏**）：
1. `PhoneDesk._wipe` 附近的调用
2. `ScenarioData.DEFAULT_PHONE` 默认值
3. `data/story.json` —— ★ **注意**：`_merge_phone` 是**逐键覆盖**，
   story.json 里的旧 `cleared` 会**盖掉**新默认值 → 必须**直接改 story.json**
   （实测：改了 DEFAULT_PHONE 后导出，cleared 仍是旧值）
4. **两处「占位符数量守卫」断言**：WardrobeTest 一处、手机编辑器冒烟一处
5. 手机编辑器的 `PHONE_FIELDS.album` 与 `PH_MEETING`/`PH_EXPECT`

★ 这两处守卫这次**抓到了自己的更新** —— 它们正是用来防「文案改了代码没跟上」的。

## 六、照片不存盘

照片完全由「种子 + 轮次」决定 → 不存盘、重算即可复现。
`resume_run()` 要补一句「按当前轮次补齐应有张数」，否则续玩时照片会少。

半身框 68×99（0.687），照片视口 108×158（0.684）—— 几乎完全吻合，画面不留黑边。
视口宽度同时受手机屏宽约束（`2×(VW+16) + 7 ≤ 302`）。

## 九、可复用的教训

1. **改文案占位符数量 = 改接口** —— 要顺着找齐：实现 → 默认值 → story.json
   → **守卫断言** → 编辑器字段。
2. **`_merge_phone` / `_merge_flat` 是逐键覆盖** ——
   改了 GDScript 里的默认值，story.json 里的旧值仍会盖掉它。
   **要么直接改 json，要么把那个键从 json 里删掉。**
3. **结构约束优于概率约束** —— 「两组不混」做成「按组取候选」而不是「取完再筛」，
   这样越界在结构上不可能发生。
