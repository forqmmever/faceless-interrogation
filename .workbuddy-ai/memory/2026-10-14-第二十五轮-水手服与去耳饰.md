## 二、★ 核心 bug：「内裤显示在下装上面」——有两层原因

### 表层（换源图）

`panties_lace` 原映射到 AU 的 `gstring`（**高腰系带**画法），腰带高于所有下装腰线，
实测在 8 条下装下都露出 11%~21% 像素。

→ 换源图为 `lacepanties`，露出 **0%**；名字从「蕾丝丁字裤」改成「**黑色蕾丝内裤**」。

### ★ 深层（真正的根因：z 序全部退化）

**`tools/dol_prepare.py` 用「物品 id」去查「按槽位编号」的 `SLOT_Z` 表**：

```python
# 错：our_id 是物品 id（如 "panties_lace"），SLOT_Z 的键是槽位（"panties"）→ 永远查不到
z = M.SLOT_Z.get(our_id, 100.0)
```

`dol_map.SLOT_Z` 是**按槽位**编号的（top 95 / bra 70 / bottom 90 / panties 67 …）。
拿 id 去查 → 全部落到兜底 `100.0` → **76 个衣物图层 z 全是 100.0**。

于是 `DolDoll.plan()` 里的 `sort_custom` 面对**全部相同的 z** 时退化成
「`equipped` 的插入顺序」= `SLOT_ORDER`，而 `SLOT_ORDER` 里 **`bottom` 排在 `panties` 之前**
→ 内裤画在下装**上面**。

同一原因还让 `bra` 压住 `top`、`stockings` 压住 `shoes` —— 只是这两处不那么显眼，没人报。

**修复**（`tools/dol_prepare.py`）：

```python
def item_slots():
    """从 scripts/OutfitData.gd 抓「物品 id → 槽位」。**这是唯一的权威来源**。"""
    import re
    path = os.path.join(HERE, 'scripts', 'OutfitData.gd')
    pat = re.compile(r'"id"\s*:\s*"([^"]+)"[^\n]*?"slot"\s*:\s*"([^"]+)"')
    out = {}
    with open(path, encoding='utf-8') as f:
        for line in f:
            m = pat.search(line)
            if m:
                out[m.group(1)] = m.group(2)
    return out

# main() 里：
slots = item_slots()
def z_of(our_id):
    return M.SLOT_Z.get(slots.get(our_id, ''), 100.0)
```

三处调用点（477 / 481 / 494 行）统一改成 `z_of(our_id)`，末尾加兜底自检：

```python
noz = [k for k in M.ITEMS if not M.SLOT_Z.get(slots.get(k, ''))]
if noz:
    print('★ 这些物品查不到槽位、图层 z 退化成 100.0（层序会乱）: %s' % noz)
```

**实测结果**：两包 `doll*.json` 的图层 z 分布从「76 层全是 100.0」变成完整的槽位 z 谱
（10 / 36 / 45 / 60 / 66.6 / 67 / 70 / 76 / 85 / 90 / 95 / 103 / 105 / 110 / 132 / 139 / 145 / 146 / 149 / 150）。
用临时 Godot 场景实测 `DolDoll.plan()`，顺序变为
**panties 67 → bra 70 → shoes 85 → bottom 90 → top 95** ✅

> 这个 bug 从第一轮烘图包起就存在，直到「内裤压住下装」被肉眼看见才暴露。

## 五、晚礼服的 18px 裁边（已知且接受）

`bottom_eveninggown` 是**整包里唯一被取景框切到的图层**（烘 AU 时打印「切 18 px」）。

- 原因：共用取景框只有 68 px 宽（x62..130），而 AU 这条舞会裙在全身像那一列横跨 x44..139（95 px），
  左边 18 px 裙摆外扩被裁掉，右边另有 9 px 被 130 的接缝挡掉。
- 试过换成 `lower/ballgown`（正好 62..130，0 裁剪），但那是条**短蓬裙**，和「晚礼服」语义不符。
- **结论：宁可留这点裁边也要保住这条长裙。** 已在 `dol_map.py` 与 README 留说明。

`gstring` 是唯一两者兼具的，但它正是 bug 源头。

→ `see: "cutout"` 的**逻辑判定**仍照常工作（判定不看像素），只是像素上不再成立。
