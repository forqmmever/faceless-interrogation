# 第八十三轮（续 2）：把全局缺陷层删干净

用户一句：「全局的缺陷设置不是都删掉了吗」。

## 一、我上一轮的错

上一轮我为了「别让全局那 2 项消失」，把它从 `[]` 恢复成了 2 项。
但**编辑器里那一页（流程四页之一）已经删了** —— 于是这份数据变成：

> **没有任何入口能改，却会在「背景没写 defects」时偷偷生效。**

这正是用户说的「脏数据」。恢复数据本身没错（那是我误删的），
但恢复之后**没有跟着把这一层拆掉**，是我的判断失误。

## 二、这次彻底拆掉

| 层 | 处理 |
|---|---|
| `story.json` 顶层 `defects` 段 | **删除**（三套背景各自的 `"defects": []` 保留） |
| `ScenarioData._defects_ov` / `_defects_declared` | 删除 |
| `ScenarioData.defects_override()` / `defects_declared()` | 删除 |
| `_load_story()` 里的读取 | 删除 |
| `OutfitData._ensure_defects()` | 三级回落 → **两级** |

```gdscript
// 现在只有这两行
var src: Array = _bg_defects if _bg_defects_declared else DEFAULT_DEFECTS
```

| 顺序 | 条件 | 结果 |
|---|---|---|
| ① | 本套背景写过 `defects`（哪怕 `[]`） | 用它 —— **空就是没有** |
| ② | 没写 / 没有当前背景 | 代码里的 `DEFAULT_DEFECTS`（仅「没有 story.json」时） |

★ `DEFAULT_DEFECTS` 是**代码常量**，不是数据，所以不算「留了一份改不了的数据」。

## 三、实测

```
border_post 0 项 / scene_1 0 项 / scene_2 0 项     ← 三套都显式写了 []
clear_run_overrides() 后 = 2 项                    ← 代码兜底
抹掉 border_post 的 defects 键 → 2 项               ← 没写才兜底
三套背景的 defects 键都还在，内容都是 []
```

## 四、踩的坑（新）

`_ensure_defects()` 末尾还有一句 `if DEFECTS.is_empty() and not declared:` ——
`declared` 变量已经被我删了，**整个 OutfitData 解析失败**（autoload 起不来，
所有依赖它的脚本跟着挂）。探针第一次跑就报了 `Identifier "declared" not declared`。

★ 教训：删局部变量前，把**整个函数体**搜一遍这个名字，别只改第一处。
已改成 `not _bg_defects_declared`。
