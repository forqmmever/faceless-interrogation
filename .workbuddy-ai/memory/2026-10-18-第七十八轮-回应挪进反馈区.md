# 第 78 轮：选项的「回应」挪进反馈区，模板反馈句删掉

日期：2026-10-18
用户口径：「接在下一题题面前的回应放在反馈句的现在的位置，原来的反馈句删除」

## 一、改前的结构

盘问界面左栏（`_build_left`）从上到下三块：

```
dialogue_label   (min h 96, 15px)   ← 题面；上一题的 echo 拼在它前面
feedback_label   (min h 64, 12px)   ← 系统模板反馈句（「他没有接这个话头」…）
bottom HBox                         ← 「掏出手机」+ 选项按钮
```

`_load_question()` 里第一件事就是 `feedback_label.text = ""` —— 换题即清空；
而 echo 要等**下一题**才出现，所以它一直挂到 `dialogue_label` 里，随题面一起被替换。

## 二、改了什么

### 1. 位置

| | 改之前 | 改之后 |
|---|---|---|
| `options[].echo` | 下一题题面**前面**（同一个 Label） | 题面**下方**反馈区，留到下次选择 |
| 反馈区内容 | 模板反馈句 | 只剩判定解释 + 结尾「（怀疑度 +N）」 |

关键改动（`_load_question`）：

```gdscript
# 原来：feedback_label.text = ""
_show_choice_echo()      # 重新贴一遍 last_choice_text
```

**为什么必须这样**：反馈区原来是「换题就清空」，而 echo 正是换题那一刻才该显示的东西。
不改清空逻辑，回应会一闪就没。

`_dialogue_text()` 从 5 个参数降到 3 个：

```gdscript
func _dialogue_text(manual: bool, speaker: String, qtext: String) -> String:
	var speaker_head := "" if manual else speaker + "："
	return speaker_head + qtext
```

### 2. 取法（新增 `_choice_echo`）

```gdscript
func _choice_echo(opt: Dictionary) -> String:
	var echo := str(opt.get("echo", ""))
	if echo.strip_edges() == "":
		return ""
	if bool(opt.get("echo_custom", false)):     # 作者自己写的
		return echo
	if RunData.questions_are_manual():          # 回落的那份 = 选项原文，manual 不再念一遍
		return ""
	return _ut("interrogation.speaker_you", "你") + "：" + echo
```

| 选项写了 `echo`？ | manual 背景 | auto 背景（出厂四套） |
|---|---|---|
| 写了 | 原样 | 原样 |
| 没写 | **留空** | 「你：<选项原文>」 |

### 3. 判定解释用 `_append_feedback` 接在后面

```gdscript
func _append_feedback(txt: String, gap: String = "\n\n") -> void:
	var clean := txt.strip_edges()
	if clean == "":
		return
	var body := feedback_label.text.strip_edges()
	feedback_label.text = clean if body == "" else body + gap + clean
```

调用点：`_answer_fact`（口径不符 / 前后矛盾）、`_answer_companion`（顺着说 + plant）、
`_answer_blind`（选对选错 + 备忘录）、`_flush_delta_note`（「（怀疑度 +N）」，gap 用单换行）。

### 4. 删掉的 13 条反馈句

`ui.feedback` 从 **24 → 11 条**。删的：

三处同步删：`ScenarioData.DEFAULT_UI`、`data/story.json`、`tools/story_editor.html` 的 `uiSections()`。

### 5. 保留的 11 条（都是「解释数值 / 教玩法」）

## 三、踩到的坑：把 story.json 写坏成 3 套背景

用 `json.loads → 改 → json.dumps` 整体重写 `data/story.json`，结果写成了一份
**只有 border_post / scene_1 / scene_2 的旧版**（139646 字节，`git diff` 2258 行删除），
连 `silence_text`、`qte_prompt`、`intf_default_line` 都被退回旧内容。

发现路径：`tools/build_story_editor.py` 打印「已内嵌快照：**3 套背景**」，而正常应是 6 套。

处理：
1. `git checkout -- data/story.json` 恢复（213014 字节 / 6 套）；
2. 改成**逐行文本删除**（正则 `^\t\t\t"key":` 精确匹配那 13 行），diff 变成 **2 增 15 删**；
3. 写后立刻断言「6 套 + 字节数 211464」，再重建快照。

**教训**（已写进 MEMORY.md）：改 `story.json` 一律文本级操作 + 写后立即校验背景数与字节数。
整体重写还会打乱 `DEFAULT_*` 与数据的一致性 —— 那次连第 74 轮的文案改动都被回退了。

## 六、留下的口子

- 出厂四套（auto）的选项**没有 `echo`**，反馈区显示「你：<选项原文>」，等于把你选的那句再念一遍。
  如果想让四套也「有回应感」，给它们的选项补 `echo` 即可 —— 不需要改代码。
- `interrogation.speaker_you`（「你」）现在只在 auto 背景的回落路径里用，仍保留。
