# 第三十八轮：清点 AU 未接入的四类（masks / genitals / props / belly）

日期：2026-10-15

「清点」（承接第三十七轮留下的「下一轮列出这四个的具体内容」）。

**本轮一行游戏代码都没改** —— 只做清点，产出工具 + 文档 + 对照图。

## 一、怎么量的（口径必须和烘焙一致）

一律按烘焙时的同一把尺子：

- 只取**全身像列**（`x < 130`），因为右边那列是胸像、游戏里根本不画
- 再裁到内容 bbox，所以图里看到的形状就是游戏里会长出来的形状
- 几何、空图、内容重复全部**实测**（MD5 / ImageChops.difference / getbbox），不靠名字猜

新增三个工具：

| 工具 | 作用 |

| `tools/scan_unused_cats.py` | 量尺寸 / bbox / 几何分类 / 空图，出明细 |

## 二、四类的真实性质（与预期不一样）

| 分类 | 量 | 真实性质 | 能不能直接变成衣服 |

## 三、三处「名字看不出、必须实测」的发现

1. **`genitals` 只有 7 个独立图案，不是 8 个** ——
   `chastitycage` 与 `chastitycagefetish` 的 `full.png` **内容完全相同**
   （MD5 都是 `fc0a9b98…`）。
2. **四种磨损态基本是摆设** —— `full` / `torn` / `tattered` / `frayed` 里，
   只有 `chastitybeltfetish` 的四张真的是四张不同的图，
   其余 7 个目录的**四张文件 MD5 一致**。
   （第一次用「逐像素数差异」判，得到满屏 0 / 小数字，容易看错；
   改用 **MD5 + `ImageChops.difference().getbbox()`** 两个独立方法交叉验证才敢下结论。）
3. **`props/npc/` 根本不是道具** —— 47 张拼起来是一个**完整的 NPC 立绘**
   （`base` / `brand_*` / `hair_*` / `robe` / `sack`）。按名字完全看不出来。

## 四、`belly` 的结构（图包作者定的分界，扫文件名扫出来的）

- `body/pregnant-belly/1..24.png` —— 24 阶孕肚本体（与 `clothes/belly` 配套）
- `clothes/belly/`：
  - `mask-N` / `mask-min-N` / `mask-clip-N` 各 10 张，**只到 15~24 阶**
  - `shadow-N` 17 张，**8~24 阶**
  - `mask-shirt-*` 10 张（含 `-clip` / `-clip-big` / `-breasts`）
  - `belly-mask*` 6 张（基准 + 上/下缘阴影，各带 `-2` / `-3`）
  - 7 张全透明占位

★ **`mask-*` 只从 15 阶起、`shadow-*` 只从 8 阶起** —— 说明前 14 阶肚子还没大到
需要把衣服挖开。这个分界不是猜的，是扫出来的。

## 五、`props` 的命名约定（写代码时用得上）

| 后缀 | 含义 | 张数 |
|---|---|---|
| （无） | 基准图 | 596 |
| `-basket` | 装了东西的篮子（`apple` → `apple-basket`） | 41 |
| `-acc` | 附属小件（单独拆出来的一层，`resolve()` 会滤掉） | 23 |
| `-underarm` | 夹在腋下的姿态 | 17 |
| `-cover` | 盖住的形态 | 8 |
| `-open` | 打开状态 | 5 |
| `-big` | 放大版 | 1 |

按 MD5 比对：**26 组、56 个文件内容重复**，独立图案 661 / 691。
（`box-creature` / `box-creature-underarm` / `box-porn` / `box-porn-underarm` 是同一张图。）

## 六、结论

四类里真正「补进去就多一批衣服」的只有 **`genitals`（7 件）**。
`masks` / `belly` 是渲染机制，`props` 是另一个系统的东西。

`genitals` 若要接入：位置（`x91..118 / y81..104`，与 `panties` 同层同高）和贴图都现成，
**成本只是「加一栏 + 7 件数据 + 目击描述」**。
