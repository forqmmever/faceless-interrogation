# 第九十四轮 · 「玩玩的关系」开局相册多一张上半身

日期：2026-10-19

## 用户口径

> 「把玩玩的关系第一轮相册里加一个上半身」

追问确认：
1. **多一张（共 4 张）** —— 不是「仍 3 张但保证有上半身」
2. **直接写死** —— 不做成背景可配字段

## 实测（改动前）

第 1 轮 3 张，上/下半身随机。`SHOT_SEED = 20261011` → scene_1 的相册是
**3 张全下半身**（`["下","下","下"]`），一张上半身都没有。

## 改动

### `scripts/RunData.gd`

```gdscript
const EXTRA_UPPER_BG := "scene_1"

func _photo_extra() -> int:
	return 1 if str(background().get("id", "")) == EXTRA_UPPER_BG else 0

func photos_expected_for_level(li: int) -> int:
	return ScenarioData.PHOTO_COUNT_START \
		+ ScenarioData.PHOTO_COUNT_PER_LEVEL * li + _photo_extra()
```

- `_roll_photos()`：`_append_photos(START + extra, extra)`
- `_append_photos(n, force_upper_tail := 0)`：批尾 `force_upper_tail` 张强制上半身
- `_make_photo(force_half := "")`：强制分支**跳过 `_rng.randi()`**
- `resume_run()`：`need = photos_expected_for_level(level_index)`

### ★★ 三个关键决定

1. **并进同一批，不另调一次 `_append_photos()`**
   —— 后者会因为「相册非空」把废片预算切到每批 1 张，开局上限从 2 变 3，
   破坏第 88 轮的口径。
2. **强制那张不吃随机数**
   —— 所以前 3 张与改动前**逐张一致**，只有末尾多一张。实测 20261011：
   `["下","下","下"]` → `["下","下","下","上"]`。
3. **期望张数收进一个门面** `photos_expected_for_level(li)`
   —— 它是整局固定偏移（+1），`resume_run()` 补照片与三处测试断言原来各算一遍公式，
   少一处就会「续玩回来少一张」。

### 测试（`tests/WardrobeTest.gd`）

- 开局张数断言改成走门面
- 新增 4 条：5 个种子「= 3 + 1 张」/ 多出来的是上半身 / 别的背景仍是 3 张 /
  强制只作用于末尾一张（`["下","下","下","上"]`，证明前 3 张没被推歪）
- 废片预算那段的「开局批」改成 `photos_expected_for_level(0)` —— 第 4 张也计入预算
- 逐轮追加那段的起点与终点都走门面
