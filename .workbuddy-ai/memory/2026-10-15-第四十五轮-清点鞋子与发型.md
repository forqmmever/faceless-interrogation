# 第四十五轮：清点 AU 的鞋子与发型（供挑选）

日期：2026-10-15

## 用户口径

> 「列出 au 中鞋子和发型，我要从中挑选」

**本轮不动游戏代码**，只清点 + 出图 + 出清单。

## 一、★ 三档分类（本轮最有价值的结论）

AU 图包里**混着一批 DoL 旧款**（名字与新款相同），所以每个款式都要验：

| 档 | 含义 | 能不能用 |
|---|---|---|
| **A** | 新几何 512×256 + 灰度蒙版（sat ≤ 0.05） | 推荐 |
| **B** | 新几何 512×256，但是**彩色** | **能用**，但需试色 |
| × | DoL 旧几何（256×128 / 256×256） | **不能用** —— 硬伤，位置会错位 |

### ★ B 档为什么能用（修正了原先的过度严格理解）

原项目约定记的是「几何必须是 512×256 **且** 饱和度必须是 0.00，两个条件缺一不可」。
本轮查清：`dol_prepare.tint()` 是

```python
lum = (r*299 + g*587 + b*114) / 1000.0 / 255.0
out = (target_r * lum, target_g * lum, target_b * lum, alpha)
```

—— **先把源像素转成灰度、再乘目标色**。所以彩色源**不会漏色**
（最终饱和度只由目标色决定），只是明暗关系来自原彩色的亮度分布。
项目现有的 `shoes_school_navy` 用的就是 B 档源图（`schoolshoes`）。

★ 对**头发**那个严格标准仍然是对的（明暗直接决定发丝质感），
  但对**鞋 / 衣服**，彩色源也能用 —— 实烘一次看效果即可。

## 三、出图口径

鞋和头发都是**灰度蒙版**（直接看是一团灰），所以：
- 鞋 → 叠在小人脚上、裁脚部放大
- 头发 → **tint 上发色 + 叠在头骨上**、裁头部放大

不这样做根本看不出形状。

## 四、★ 修了自家工具的两个 bug（都是「会让清单不可信」的）

1. **挑主体图没按 `resolve()` 的顺序**
   按字母序取到了 `acc.png`（附属装饰层）而不是 `full.png` ——
   导致 6 款鞋渲染成了错的图，`geta` 还被误判成 B 档。
   改成与 `dol_prepare.resolve()` **完全同一顺序**：
   滤 `-acc`/`_acc` → `full.png` → `full*` → `idle` → 数字名 → 其余。
   ★ 教训：**清点工具的取图顺序必须和烘焙一致**，否则「清单里看到的」≠「游戏里会用的」。

2. **文档分段失效**
   `dump_pick_list.py` 的输出在 Windows 上是 **CRLF**，
   用 `\n\n\n` 分段匹配不到（实际是 `\r\n\r\n\r\n`）→ 各段串行，
   出现「鞋子表 148 行」这种假数字（50 + 48 + 37 + 13 = 148，正是串在一起）。
   已先归一化换行再切。
   ★ 自检方式：**文档表格行数必须等于图里的款数**（50 / 48 / 37 / 13）——
     这个自检立刻暴露了串行问题。
