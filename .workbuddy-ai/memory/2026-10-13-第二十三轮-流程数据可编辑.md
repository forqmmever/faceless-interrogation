# 第二十三轮（3/3）：流程数据全部可编辑

用户口径（本轮原话，分两条消息）：

> 「编辑器还应该具备编辑一局游戏的轮数以及一轮游戏的问题数，每个问题的 qte 类型 出现时间」
> 「强制穿着的服装，可以是 固定几件衣服里选一件即可和固定一件的自由组合」
> 「缺陷遮掩这部分也要可编辑」

用户选定的两个设计分支（AskUserQuestion）：
- QTE 类型：**现有三种 QTE 全部可指定**（无 / 表情控制 / 递话打断 / 组合敲键）+ 自动
- 强制穿着：**一组规则自由组合**（不是二选一）

## ① 一局几关不再写死

`OutfitData.LEVELS` / `MAX_LEVELS` 从 **const 改成运行时表**：
- `DEFAULT_LEVELS`（出厂兜底）+ `var LEVELS` / `var MAX_LEVELS`，惰性读 `story.json.levels`
- `levels()` / `level_count()` / `level_at(li)`（越界夹回）/ `reload_levels()`
- **`level_unlocked()` / `open_level_count()` 从 static 改成实例方法**（static 读不到实例变量）
- `START_ACCEPTANCE` 留在代码里（它不是单关属性）
- 连带改：`RunData.levels()/level_count()`、`Main` 选关面板、
  `ProfileData.summary()`、`RunSave` 的越界判断

## ② 强制穿着：一组规则自由组合

每关一条：`{mode, rules[]}`，`mode` ∈ `none` / `random` / `fixed`。
- `random` 保留旧的「随机抽 0~2 件高暴露」→ **出厂后三关就是这个**，所以升级零回归
- `fixed` 下每条规则：`{"pick":"all", items:[...]}` 都要穿 / `{"pick":"any", items:[...]}` 任选一件

模型侧：
- `WardrobeModel.forced_groups` + `set_forced_groups()`
- `forced_allowed_ids(slot)` —— 三种粒度：all 锁死一件 / any 放开组内 / **没写规则表时退回逐件锁**
- `missing_forced()` / `missing_forced_text()`（一条规则一句人话）
- ★ **坑**：第一版 `forced_allowed_ids` 漏了「没有规则表但 forced_items 非空」那条路，
  → 求解器把锁死的槽位当自由的 → 一键达标断言连挂 3 条。
- `_group_options()` 改成按 `forced_allowed_ids` 收窄（原来是「强制槽位只有一件」）
- `RunData._apply_fixed_forced()`：all 组全进 forced_items；any 组**默认替你穿第一件穿得起的**
- `force` 空件（`bare`）不进随机池 —— 「强制你别穿」不是一条说得通的指令

## ③ 每题的 QTE 类型 + 出现时间

`story.json` 新增 `qte_plan`（按题号对齐）：
`{"qte": auto|none|expression|interference|combo, "delay": 秒}`

`Interrogation._apply_qte_plan(index, kind, opts)` 在 `_load_question` 里读计划：
- `auto`（出厂默认）→ 老规则：`needs_expression_for()` + 干扰计时器
- `expression` → 强制出，`qte_delay_left = delay`
- `interference` / `combo` → **准点排期**（`_intf_scheduled` + `_intf_delay_left`），
  来一次即止（`_intf_planned_used`），不走那个「每若干秒随机来」的循环
- `none` → 什么都不出
- `_cancel_qte()` 一并清掉排期（否则上一题排的那次会冒到新题上）

## ④ 缺陷遮挡可编辑

`DEFECTS` 从 const 改成运行时表（`DEFAULT_DEFECTS` 兜底 + `defects()`），
`WardrobeModel` 里 4 处 `data.DEFECTS` → `data.defects()`。

## ⑤ 编辑器：四页 + 两种新字段类型

新页面：🪜 关卡与轮数 / 👗 强制穿着 / ⏱ QTE 计划 / 🩹 身体缺陷
新字段类型（`renderField`）：
- `t:"objlist"` —— **嵌套清单**（规则表要套在每一关下面）
- `t:"multiselect"` —— **勾选组**（带筛选框；已经选中的永远显示，否则改不回来）

为了让编辑器能挑东西，`story.json` 多了一段**只读目录** `catalog`
（74 件衣物 + 4 个标签 + 18 个槽位；游戏不读它）。
`normalizeStory` 故意**不**自动建空数组（`levels: []` 会被当成「一关都没有」）。

校验新增：关卡越界 / 曲线倒退 / 反差要求超理论上界、强制规则引用不存在的衣服 /
「必须穿」组里同槽位两件、QTE 类型写错 / 延迟过大 / 计划比题目长、缺陷 id 重复 / 标签不存在。

★ **踩坑（重要）**：第一版把「反差要求 > 暴露值上限」当无解判据，
把出厂的**第 2 关**（要求 42、上限 32、实测最优 81）误报了。
根因：反差不是靠暴露值预算换的 —— 头饰 / 眼镜 / 妆容这些零暴露部件也贡献反差。
改成**宽松上界**：把各部位能穿到的最高反差加总（不扣预算），高过它才判必无解。
是编辑器冒烟测试把它抓出来的。
