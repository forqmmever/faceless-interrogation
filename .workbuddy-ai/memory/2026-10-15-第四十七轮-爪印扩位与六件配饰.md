## 二、第 47 轮：爪印扩到胸口与脸颊

### 「小腿」做不了 —— 两条实测证据

**① AU 的 `bodywriting` 没有小腿位置。** 全部 15 个位置：

```
breasts-0 .. breasts-6
forehead
left-cheek / right-cheek
left-shoulder / right-shoulder
left-thigh / right-thigh
pubic
```

**② 小腿那一段的皮肤本来就不够。** 逐行扫 `assets/dol_au/base/body.png`
（68×203）的身体掩膜，量出的逐行 x 区间：

```
y=103  27-41(15) | 43-57(15)     ← 两腿开始分开
y=106  27-57(31)                 ← 裆部连成一片
y=114  29-40(12) | 42-42(1) | 44-55(12)
y=120  30-40(11) | 44-54(11)     ← 大腿：每边 11 px
y=140  29-39(11) | 45-55(11)
y=153  30-37( 8) | 47-54( 8)     ← 小腿：每边只剩 8 px
y=161  30-37( 8) | 47-54( 8)     ← 鞋子从这一行起盖住
y=185  27-27(1) | 31-40(10) | 44-53(10) | 57-57(1)   ← 脚
```

身体总范围 x26..58 / y47..186；头部另有 `head.png`（x26..58 / y15..47，
最宽 33 px 在 y34-36）。躯干分段：y47-50 是脖子残端（7 px）、y57-67 最宽
（31~33 px，胸）、y75-81 收窄（19 px，腰）、y94 以后是胯（33 px）。

→ 结论：**小腿塞不下一枚看得清的爪印**，按用户许可只做胸口 + 脸颊。

### 关键事实：paw print 每个位置都是同一个 5×5 图案

逐像素比对 `left-thigh` / `breasts-0` / `right-cheek` 三张源图的**左列副本**
（x<130），5×5 的墨点分布完全一致：

```
row0: . X . X .
row1: X . . . .
row2: . . X X X
row3: X . X X X
row4: . . X X .
```

★ **陷阱**：这几个 PNG 是 512×256，里面**画了两份**（全身像列 x≈96-112、
胸像列 x≈353-369）。直接 `getbbox()` 会得到 `108,108-368,112`（宽 261）这种
横跨两张脸的假 bbox。必须先 `clip_to_body()`（`clip_view = (0,0,130,256)`）
才是真正要用的那一份。

所以 `src` 里的位置名**不影响结果**（`transform()` 会按 bbox 重新居中），
只有 `align` 决定落点。

### 落点公式（本轮再次验证）

```
align_x = (视口中心_x + 43) / 1.5
align_y = (视口中心_y + 15) / 1.5
```

反推依据：`transform()` 里 `tx = (align_x − 58)×1.5 + 106`，
而取景框是 `crop = (62, 0, 130, 203)` → 视口 = AU 画布 − (62, 0)。
两者合起来化简即得上面的式子（与既有 6 件纹身反算吻合，误差 ≤1 px）。

胸口那件 `gate: ["top","dress"]`（同 `tattoo_slave`），脸颊**不给 gate**。

### 脸颊这件返工过一次 —— 值得记的方法

第一版放在视口中心 (36, 40)，量出来 31 个墨点里 **9 个**落在
`sclera/iris/lashes/eyelids/brow` 上（**29%**），而既有星纹只有 6%（2 px）。

做法：把 **N=5/6/7/8 四档 × 全部视口位置**（vcx 31..46、vcy 24..47）全跑一遍，
对每个候选算「落皮肤比例」与「压眼像素数」，取**帕累托前沿**
（皮肤越高越好、压眼越少越好），再从中挑落点：

```
N=8  vcx=33 vcy=27  bbox x29-36 y23-30  落皮肤 100.0%  压眼 0   ← 额头，偏上
N=8  vcx=38 vcy=43  bbox x35-40 y40-45  落皮肤 100.0%  压眼 0   ← ★ 选这条
N=8  vcx=36 vcy=40  bbox x34-41 y39-46  落皮肤  96.8%  压眼 9   ← 第一版
```

最终 (38, 43) 的真实烘焙结果：**93.5% / 2 px**，与既有星纹同一水平；
而且落在**另一侧脸颊**（星纹 x45-52 右颊，它 x34-41 左颊）—— 两件能同时戴。

### 顺带修的数据同步坑

`data/story.json` 的 `item_desc` 是**整段替换**：

```gdscript
var idesc: Variant = d.get("item_desc", null)
if idesc is Dictionary and not (idesc as Dictionary).is_empty():
    _item_desc = idesc          # ← 整个换掉，不是 _merge_flat
```

所以只改 GDScript 的 `DEFAULT_ITEM_DESC` 会被 story.json 的旧值整段盖掉。
**正确同步办法**（本轮用的）：

1. 备份 story.json → 把 `item_desc` 置空 `{}` → 写回；
2. 跑 `DumpStory` → 得到全部默认值（**顺序也对**）；
3. Python 把备份里的旧值叠回去（`merged[k] = orig.get(k, default)`，
   备份独有的键追加在末尾）；
4. 再跑一次 `DumpStory` 规范化格式。

结果 `item_desc` **43 → 53 条**。

> ⚠ 同理要当心的还有 `backgrounds` / `traits` / `clue_frame` / `clue_sources` /
> `photo_notes` —— 这几段**都是整段替换**；只有 `rules` / `ui` / `phone` 走
> `_merge_flat` / `_merge_phone`（逐键覆盖）。

## 三、第 48 轮：六件配饰

### 六件都实测为 A 档

判据：新几何 512×256 + 纯灰度（最大饱和度 **0.000**）。直接取 `full.png` 即可，
不需要搬运、也没有试色风险。

| id | 中文名 | 源 | 暴露 / 门槛 / 反差 |
|---|---|---|---|
| `acc_legband_belted` | 搭扣腿环 | `legs/belted`（`full-long`） | 1 / 4 / 3 |
| `acc_legband_leather` | 皮质腿环 | `legs/leather` | 1 / 5 / 3 |
| `acc_choker_bunny` | 兔女郎项圈 | `neck/bunnycollar` | 1 / 6 / 4 |
| `acc_choker_whitney` | Whitney 的项圈 | `neck/Whitney's Collar` | 1 / 7 / 5 |
| `acc_choker_leash` | 带牵引绳项圈 | `neck/collarleash` + `acc` | 2 / 8 / 6 |
| `acc_choker_whitney_leash` | Whitney 的牵引项圈 | `neck/Whitney's collar with leash` + `acc` | 2 / 9 / 7 |

### `belted` / `leather` 的位置是推出来的

`belted` 在同一图包里出现在 **5 个部位**：

| 部位 | `belted` | `leather` |
|---|---|---|
| `hands/` | 有 | 无 |
| `legs/` | **有** | **有** ← 只有这里两件齐 |
| `lower/` | 有 | 无 |
| `upper/` | 有 | 无 |
| `feet/` | 有 | 无 |

用户给的名字是小写英文、不带部位 —— 但 `leather` 只在 `legs/` 里存在，
两件要成对就只能是 `legs/` 那一组（搭扣腿环 / 皮质腿环）。

### 牵引绳在 `acc.png` 那一层

- `neck/collarleash/acc.png` 左列 bbox `22,54-106,125` → 那条绳
- `neck/Whitney's collar with leash/acc.png` 左列 bbox `103,52-130,94` → 那条绳
- `neck/bunnycollar/acc.png` 只有 `100,53-109,61`（9×8 压在圈上）→ 不叠，免得杂点

所以带绳的两件写成**两层**（先 `full.png` 后 `acc.png`），
和 `acc_belt` 借 `lower/…/acc` 是同一个道理。

### 已知取舍：绳被取景框切掉

取景框只有 68 px 宽（AU 画布 x62..130）。实测烘后：

acc_choker_whitney_leash    bbox 38,48-67,93    贴到右边缘（x=67）
acc_legband_belted          bbox 29,114-55,185  未贴边
acc_legband_leather         bbox 28,121-55,186  未贴边
acc_choker_bunny            bbox 39,48-45,54    未贴边

两件的绳各被切约 40 px。与既有 `tool_tail`（被切 26 px）同级，
读起来像「绳子被画外的人牵着」，暂按现状保留，已在 README 记为已知取舍。
