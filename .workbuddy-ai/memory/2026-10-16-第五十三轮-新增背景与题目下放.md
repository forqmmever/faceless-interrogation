## 一、★ 整轮最关键的决定：新增了 `enabled`（草稿 / 启用）

用户选了「空白新建」，并接受「期间校验面板会一直报错」。但这个选择**不能直接照做**，
原因是我先把「一套背景能上场」的门槛量了出来 —— 全是从现存断言里读出来的硬要求：

| 项目 | 门槛 | 依据 |
|---|---|---|
| `cards` | **恰好 12 张**（B 5 + A 7） | `_check("[%s] 身份情报 12 条")` 写死 |
| `questions` | 每轮**恰好 1 道盲区题** + 总数 ≥ 每题抽题数 | 断言遍历每一轮 |
| `facts` | ≥ 每轮一条（2 轮 → 2 个） | 断言 |
| `sms` | 每条 `level` 依次 0/1，且**正好揭示 `facts[i]` 的官方口径** | 交叉断言 |
| `companion_sms` | ≥ 每轮一条 | 断言 |
| `interference_lines` | ≥ 4 条 | 断言 |
| 基础信息 | id/name/venue/intro/interrogator/cover_role/true_role/true_name 长度 ≥ 2 | `_bg_fields_ok()` |

**而开局是随机抽背景的** —— 抽到一套空背景会直接崩（归类环节没卡可归、
盲区题抽不出来、短信揭示不了事实）。所以：

> **空白新建 = 建一套「草稿」，草稿不参与抽取、不进测试的内容校验。**

| 草稿（`enabled: false`） | 已启用（**不写这个键**，或 `true`） |
|---|---|
| 不被游戏抽到 | 会被抽到 |
| 不进测试的内容校验 | 逐项校验 |
| 校验面板只给**一条**提醒 | 有问题逐条报 |
| 编辑器照常显示、照常编辑 | 同左 |

★ **缺省 = 启用** 是刻意选的：出厂那四套不用补字段，向后兼容。
判断式就一句 `b.get("enabled", true) != false`。

### 「新增内容型数据」这条经验的通用形式

以后再加任何**会被随机抽到 / 会被测试遍历**的内容类数据（背景、题目、
原貌预设、缺陷…），先问两个问题：

1. **半成品会不会被抽到？**（会 → 需要草稿 / 启用标志）
2. **测试会不会遍历它？**（会 → 要么过滤草稿，要么按门槛给最小可用骨架）

本轮两个都是「会」，所以草稿机制不是锦上添花，而是这个功能能不能做的前提。

## 三、★ 选关面板的「指定背景」必须保住随机流

`RunData.start_new_run(seed, level, bg_id)` 的关键不是「能用指定的背景」，
而是**指定之后会不会连带换掉人物**。

原貌 / 情报 / 性情 / 强制装备全部从**同一个 `_rng`** 出，所以：

```gdscript
	# ❌ 错的写法：指定时跳过 randi() → 后面所有随机整体错位
	if bg_id != "":
		background_id = bg_id
	else:
		background_id = str(ids[_rng.randi() % ids.size()])

	# ✅ 对的写法：无论指不指定都先抽一次（结果被覆盖掉）
	var rolled := str(ids[_rng.randi() % ids.size()])
	background_id = bg_id if (bg_id != "" and ids.has(bg_id)) else rolled
```

**「抽一次再丢弃」= 随机流恒定** → 同一个种子在指不指定背景时抽到的是**同一个人**。
不这么做的话，玩家一指定背景就等于换了个人，而且**可复现性一起没了**
（截图 / 测试靠固定种子）。

这条有断言守着（TestRunner：「指定背景不改变后续随机流」）——
**这种「不变式」类的东西一定要落成断言**，否则下次有人顺手把 `randi()` 挪走就没人发现。

## 四、★★ 修了两处「假绿」—— 越界会让断言静默消失

`WardrobeTest` 里这两行：

```gdscript
_check("第 4 轮解锁全部 4 条", int(seen[3]) == OutfitData.MAX_LEVELS)
_check("第 4 轮解锁全部 4 条", int(seen_n[3]) == OutfitData.MAX_LEVELS)
```

第 52 轮把一局压成 2 轮之后，`seen` 只有 `MAX_LEVELS`(2) 个元素 ——
访问 `seen[3]` **越界**，Godot 报 `SCRIPT ERROR: Out of bounds get index '3'`
并**跳过这一行**（`_check` 根本没执行）。

于是**这两条断言从第 52 轮起一直「没跑过」，而测试照旧显示 `Failures: 0`。**

### 教训（这条要长期记）

> **越界 / 运行时报错不会让测试失败，只会让那一行静默消失。**

所以：

1. **跑完测试要同时看三样**：`Failures: 0`、`SCRIPT ERROR`（有没有）、
   断言总数（有没有莫名减少）。本轮就是靠**断言总数从 585 → 587 却又不对**
   加上日志里那两行 `SCRIPT ERROR` 才发现的。
2. **改「一局几轮 / 槽位数」这类常量后，要 grep 所有带下标的断言**
   （`seen[3]` / `LEVELS[3]` / `rows[3]`）—— 第 52 轮那次就是漏了这两处。
3. 修的时候顺便把标题里的写死数字也改成动态的（`"末轮解锁全部 %d 条" % MAX_LEVELS`），
   免得下次再改常量时标题又对不上。

## 五、编辑器冒烟里的一个坑：模板字符串里不能有反引号

`editor_smoke.js` 第 74-94 行是一个**模板字符串**（反引号包围）里的对象字面量：

```js
const mainJs = `
  ...
  return { questionFields, ..., };
`;
```

我在那个区域里加注释时写了 `` `renderQuestions` ``（带反引号），
**直接提前终止了模板字符串** → `SyntaxError: Unexpected identifier`。

★ 在 `editor_smoke.js` 的这段区域里写注释：**不要用反引号**，
用普通文字引用函数名（`renderQuestions` 这样写）。

## 六、`get_background()` 故意不过滤草稿

`background_ids()` 只返回启用的（抽局用），但 `get_background(id)` **不**过滤 ——
因为**存档里可能记着一套后来被停用的背景**，玩家点「继续游戏」时仍要能取到它、
把这一局走完。

★ 这是「过滤放哪儿」的一个通用判断：**过滤只放在「产生新选择」的地方
（抽局 / 列按钮 / 校验），不要放在「按 id 取已有对象」的地方。**
