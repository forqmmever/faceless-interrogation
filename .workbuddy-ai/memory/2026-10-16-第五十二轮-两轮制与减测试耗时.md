# 第 52 轮：一局 4 轮 → 2 轮 · 曲线 125/150 · 删多余剧情 · 测试耗时砍 78%

用户口径两句：

1. 「现在的四个背景改成两轮适当调整反差曲线」
2. 「适当减少测试时间」

澄清（AskUserQuestion 两问）：

- 「四个背景改成两轮」→ **4 套背景不变，每局 4 轮 → 2 轮**
- 曲线 → 用户选了「压缩整条弧」，但**实测否掉了那个值**（见下）
- 轮次名 → **改成通用「第一轮 / 第二轮」**
- 用不到的剧情 → **删掉**

## 一、★ 用户的方案被实测否掉了 —— 这是本轮最重要的记录

用户选的是「曲线改成 125 / 160」。**不能照做。**

150 种子真实求解器（`auto_complete_outfit()`，DP + 缺陷掩码）量出的可达区间：

| 轮 | acc | cap | 可达区间 | 中位 | 建议 req（余 5） |
|---|---|---|---|---|---|
| 1 | 14 | 38 | 205 ~ 210 | 210 | 200 |
| 2 | 19 | 48 | **155** ~ 215 | 215 | 150 |

**第 2 轮写 160 = 最不利那批原貌无解、当场卡关。** 于是定了 **125 / 150**。

★ 值得记的是**为什么第 2 轮的地板只有 155**：最差那个原貌把 `stockings` 钉在
`stockings_sheerskin`（暴 9，这一栏最露的一件）—— 「脱到最露」的差反而是 0，
只能改穿保守袜（+9），这一栏就封顶了。

★ 另一个容易看错的点：**中位 215**。也就是说绝大多数种子余量有 +65，
只有最不利的那种原貌紧到 +5。**报「余量」时要用最差值，不能用中位** ——
本作的难度本来就是「由原貌决定」的。

## 三、★ 测试夹具越界 → 「还原现场」被跳过 → 一整片假红

`_test_true_presets` 里的清洗夹具 `by_level` 还是 **4 项**，而轮数已经变成 2：

```gdscript
var lv2: Array = ScenarioData.true_preset_by_level()
_check("…", ..., and (lv2[1] as Dictionary).is_empty()
                 and (lv2[2] as Dictionary).is_empty()   # ← 越界！lv2 只有 2 项
                 and (lv2[3] as Dictionary).is_empty())
```

越界 → **函数当场中断** → 末尾那句「把全局预设还回来」没执行 →
`ScenarioData._true_presets` 被夹具**永久污染**成
`[{第1轮, hair_short}, null, null, null]` → 后面所有读全局预设的用例全跟着错：

- 「两轮都配了原貌覆写」失败
- 「原貌暴露总和逐轮不降（[0]）」失败（`_bp[0]` 读到了夹具那套，总和 0）
- 「第 1 轮最优值只在钉死基准附近波动（实测 50）」失败
- 以及一批「每轮都可解」类的失败

**15 条失败里的大半都来自这一条越界**，而它们看起来像「曲线标定错了」。

### 教训

1. **测试夹具里凡是有「下标访问」，常量一改就会越界** —— 而越界会把
   **同一函数里后面的语句全部跳过**（包括「还原现场」）。所以「改常量」时
   必须**逐个 grep 夹具里的下标**（`lv2[2]` / `LEVELS[3]` / `rows[3]` 这类）。
2. **夹具的「还原」应该放在越界不可能发生的位置**，或者干脆用
   `push_error` + 提前 return 之前先还原。更好的做法：夹具改动包在
   一个「先存后还」的 try/finally 式结构里（GDScript 没有 finally，
   所以只能靠「不在中间 return」+ 断言不带下标）。
3. **看到「一大批断言同时红」先怀疑「共享状态被污染」，不要先怀疑产品逻辑。**
   本轮就是先按「曲线标定错了」查了一轮，才回过头发现是夹具。
   定位手法：在可疑断言前**插一行 `print` 把共享状态打出来**
   （本轮打印 `ScenarioData._true_presets` 一眼就看到了夹具值）。

## 四、★ 减少测试时间的做法（可复用）

### 第一步：先量。别凭感觉猜哪段慢

给 `WardrobeTest._ready()` 加**常驻**的分段计时（`Callable` 数组 + `call()`），
给 `TestRunner` 加「两段测试之间打点」（它有几个 `await` 协程，
**不能用动态 `call()` 包**——那会把执行顺序弄乱）。

实测一跑就清楚了（WardrobeTest 合计 147 秒）：

| 段 | 耗时 | 占比 |
|---|---|---|
| 强制装备可解性 | **117.7 秒** | **80.1%** |
| 一键达标 | 22.9 秒 | 15.6% |
| 其余 28 段合计 | ~6 秒 | 4.3% |

### 第二步：找出「白跑」的那部分（关键）

`_test_forced_solvability` 原本对**每一轮**都跑一次 DP。但打印出来的统计说：

```
（71 / 240 轮带强制装备）
```

**只有 30% 的轮次真的抽到了强制装备。** 剩下 70% 的轮次
根本没在验「强制装备会不会造成死局」（那一段的唯一目的），
而是在重复验「普通可解性」—— 已由 `PROBE_SEEDS` 那段与「一键达标」段覆盖。

**跳过它们 = 零覆盖损失地砍掉 70% 的 DP。**

```gdscript
if forced.is_empty():
    if li < OutfitData.MAX_LEVELS - 1:
        RunData.advance_level()
    continue
solved += 1
var ev := _solve_with_forced(...)
```

★ 但 `first_level_forced` / `levels_with_forced` 两个统计**照旧在跳过之前算** ——
它们是「强制规则确实按轮生效」的证据（比如「第 1 轮全都没有强制装备」），一条都不能省。

### 第三步：种子数一个没减

只做第二步 + `AUTO_SEEDS` 24 → 16 就够了：**147 → 31.7 秒**。
`FORCED_SEEDS` **仍是 120**、`PROBE_SEEDS` **仍是 40** ——
第二步是零损失的优化，没必要顺手砍覆盖。

★ 中途试过 `FORCED_SEEDS` 120 → 60（27.8 秒），**又还回去了** ——
为了 4 秒牺牲一半种子覆盖不划算。

### 结果

| 套件 | 改前 | 改后 |
|---|---|---|
| WardrobeTest | 147 秒 | **30 秒**（-78%） |
| TestRunner | ~197 秒 | ~168 秒（轮数减半的自然结果） |

## 五、其它

### 编辑器校验器：`空关卡表` 从「错误」降为「提醒」

`story_editor.html` 原来有一条 `if (!(bg.levels||[]).length) err(…"一道关卡都没有")`。
但**空 = 回落全局那份**是运行时明确支持的语义（`OutfitData.bg_levels()` 空 →
用 `DEFAULT_LEVELS`），而且本轮之后每套背景的 `levels` **本来就是空的** ——
不改判就一打开编辑器报 4 个错。改成 `warn` 并写明「出厂就是空的」。

### 截图：这一轮**全部 43 张都提交**

轮数变更影响**几乎所有**含进度文字的界面（选关面板 4 行 → 2 行、
顶栏「第 1 / 2 轮」、通关覆盖层「2/2 轮」、手机备注的轮回放）。

★ 这里有个判据上的新认识：**16×16 实心块判据对「少数字符变化」不敏感**。
`4/4 关` → `2/2 轮` 只改了几十个像素，实心块数 = 0，会被误判成「文字抗锯齿噪声」。
所以改用「**相对 HEAD 的差异量 vs 同代码两次跑的差异量**」比量级：
- 量级相当（3 倍以内）→ 噪声（SubViewport / 抖动）
- 明显更大（>3 倍）→ 真实变化

本轮 35 张判为真实变化、8 张判为噪声量级（其中 4 张是 SubViewport / 抖动，
4 张差异极小）—— 但因为轮数变更是全局的，**43 张全部提交**（新图是当前代码的真实渲染）。
